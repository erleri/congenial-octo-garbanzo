## 운영 코드·자료의 실제 반영 순서

1. 최신 main을 기준으로 이번 수정만 후보에 넣는다. 기존 작업 폴더의 다른 변경·비공개 자료는 포함하지 않는다. 기존 환율4파일·Actions·메일·migration·수신자는 변경하지 않는다.
2. PR의 Linux 검사에서 새 설치·타입·린트·전체 테스트·운영 빌드·추가 환율 검증과 격리 SQL 권한/계획환율 회귀를 확인한다. 과거 CI 성공을 이번 결과로 재사용하지 않는다.
3. 사용자가 승인한 뒤에만 main에 병합·Netlify 운영 배포한다. 검사용 PR 제목의 `[skip netlify]`는 운영 반영 전 제거하며, 실제 병합 커밋에도 배포 생략 문구를 넣지 않는다. 현재 검토 중에는 Netlify 미리보기도 생성하지 않는다.
4. 코드 배포 자체는 외부 API 수집·모델 생성·DB 변경·메일 발송을 실행하지 않는다. 정상 자료 갱신 때 새 생성 코드가 현재값 보관과 검증된 과거 복구를 함께 처리한다. 7일보다 오래된 복구도 별도 추가 동기화하므로 전면 재적재를 강제할 필요가 없다.
5. 기존 일일 작업의 DB 동기화·확인, 자료 커밋, Netlify의 해당 자료 배포가 끝난 뒤 DB/정적 자료의 동일 버전·가격·월평균을 읽기 전용으로 확인한다. 검토 목적으로 전체 일일 작업을 수동 실행하면 기존 메일도 나가므로 실행하지 않는다. 기존 예약 발송은 그대로다.
6. 공개6건·계획환율·인증·날짜·신규 표시를 확인한다. 이후 실제 runner의 무과금 리포트 준비 범위를 별도로 확인한다. 이번 CI 성공을 실제 자료 수집·예산 예약·원고 품질·자동 생성 성공이라고 표시하지 않는다.

## 유지하는 운영 설정

실제 조회 당시 DB는 `enabled=false`, `review_enabled=false`, writer `sol-us`, 월 상한$30·요청당$0.25다. 기존 반복 정책의 실행당$7·60회는 유지한다. 회사 지원$5로 조정하는 것은 추후 사항이다. 기존 Actions의 `currency/review/plan/hold=true`, 메일 `legacy/send approved=false/hold=false`를 바꾸지 않는다.

새 migration·Auth/RLS 변경·새 유료 모델 호출·새 메일 전환·운영 원고 수정은 없다. 정상 예약 작업 외의 유료/발송 실행은 이번 검토에 포함하지 않는다.

## 실패와 복구

- 검증한 이전 데이터·복구 기록이 손상되거나 이미 고정한 값과 충돌하면 새 자료 생성을 중단한다. 기록을 지우거나 검사를 끄지 않는다. 기존 DB·배포 자료를 유지한다. 해당 일일 작업이 실패하면 후속 발송도 보류될 수 있으며 이를 무조건 정상 발송으로 표시하지 않는다.
- 동기화 실패는 기존 `failed` 상태로 남기고 정적 대체 자료의 기준일을 유지한다. 복구 날짜·월평균 누락을 표본 검사만으로 통과시키지 않는다.
- 코드 오류는 원인이 확인된 수정/되돌림 커밋으로 정상 CI를 거쳐 해결한다. 기존 데이터4파일과 그 안의 보관·복구 이력은 과거로 되돌리지 않는다. 보관 기록을 모르는 이전 생성기를 그대로 재가동해 과거값 교체를 재발시키지 않는다.
- 원고·승인·비용·계획환율·메일 장부는 되돌림 대상이 아니다. DB 전체를 과거 백업으로 덮거나 권한을 넓혀 해결하지 않는다.

검사 결과와 PR·커밋은 비공개 `operating-rollout-20261108/`의 이번 검토 수령 기록에 보관한다. 이 문서의 준비 상태와 실제 CI/운영 반영 결과를 구분한다.
