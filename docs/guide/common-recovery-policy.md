# 공통 복구 정책

상태: **로컬 구현·검증 중, 운영 미반영·정책 기본 비활성**. 기준 운영 코드는 `0a033be`이며, 이번 변경은 네 번째 복구 실행 뒤 남은 진단·안전한 분리·단계 재개를 다룬다. 실제 운영 결과는 [운영 확인표](operational-status.md), 앞선 실패와 네 번째 실행은 [저장·재개 기록](runtime-storage-recovery.md)에 보존한다.

## 판정 기준

| 상태 | 처리 | 유료 작업 영향 |
| --- | --- | --- |
| DB가 미전송을 입증한 예약 | 기존 함수로 해제 | 원래 작업 재개 가능 |
| 정상 응답·비용 확정 | 완료 단계 재사용 | 중복 호출 금지 |
| 종료된 명확한 429, 본문·사용량 없음 | 전액 예약 유지·분리 | 해당 경로 대기 후 다음 실행에서 실패 단계만 추가 1회 |
| 부분 응답·연결 유실·처리 여부 불명 | 원래 비용 조회 | 공통 유료 처리 차단 |
| 비용 확정·응답 실패 | 비용과 응답 상태를 분리 | 429 이외의 자동 재시도 없음 |
| 출처·기간·원고 품질 미달 | 해당 자료·국가 보류 | 다른 적격 국가의 처리는 유지 |
| 인증·식별·무결성·예산 초과 | 공통 장애 | 관련 유료 작업 차단 |

HTTP 404나 빈 본문은 비용 0의 근거가 아니다. 비용 조회는 생성 때와 같은 운영 키로 수행하며, 요청 ID·종료 정보·유효한 비용이 모두 확인된 영수증만 원장에 연결한다. 로컬 키의 조회 결과를 운영 증거로 대신하지 않는다.

## 분리·예산·재시도

- `runtime-recovery/1`은 별도 서버 정책이다. 기존 `report-operating-policy/1`, 원래 동결 입력 `/1`·`/2`와 시험용 비용 분리 이력은 변경하지 않는다.
- 활성화는 생성·검토가 보류되고 진행 중 호출이 없는 상태에서 판본과 승인 근거를 확인하는 서버 함수로 수행한다. 관리자 브라우저에는 실행 권한을 주지 않는다.
- 명확한 거절을 분리해도 원래 비용은 `unknown`으로 남고 예약 전액이 예산에 포함된다. 월 경계에도 미확정 예약을 이월한다. 새 시도도 별도 비용·호출 수로 계산한다.
- 추가 1회는 원래 요청 계보 전체의 한도다. 요청·배치·정책 ID 변경으로 횟수를 초기화하지 않는다. 과거에 비용을 지불하고 성공한 시험의 두 번째 추가 시도는 재사용할 수 있지만 새로 만들지는 않는다.
- 같은 입력·모델·경로·요청 해시를 복원한 경우에만 재시도한다. 최신 출처 자격·가격·기간 검사는 그대로 적용한다. 변경·철회된 입력을 강제로 재개하지 않는다.
- 429 발생 후 최소 15분, 유효한 `Retry-After`가 더 길면 그 시각까지 같은 경로의 새 요청을 막는다. 다음 실행에서 재시도 대상을 우선하며 경로 확인 요청은 한 건만 예약할 수 있다. 확인된 정상 응답 뒤에 나머지를 처리한다.
- 추가 시도도 429면 해당 입력의 자동 시도는 소진되고 경로는 24시간 대기한다. 이후 적격한 다른 작업도 같은 경로의 단일 확인 규칙을 적용한다. 다른 모델·경로로 자동 전환하지 않는다.
- 개별 HTTP 요청의 자동 재전송은 계속 0회다. 별도 worker 실행에서 이루어지는 단계 재시도와 구분한다. 월 $30·실행 $7·요청 $0.25 및 기존 호출 수 한도를 늘리지 않는다.

## 비용 조회와 실행 인터페이스

`report:operate -- --action reconcile`은 기존 비용 조회·복구 판정·감사 기록만 수행한다. 환율·기사·공식 통계 수집, 모델 호출, 신규 예산 예약, 원고 공개, 독자 메일 발송은 하지 않는다. 리포트 전용 워크플로에서도 같은 동작을 선택할 수 있다. 기본 동작은 `plan`이며 새 스케줄은 추가하지 않는다.

조회 결과는 확정·기록 없음·인증/권한 오류·조회 제한·공급자 오류·연결/시간 초과·형식 오류·식별 불일치·종료/비용 정보 부족으로 구분한다. 키·전체 응답·원문은 진단에 넣지 않는다.

첫 조회 뒤 간격은 5분 → 30분 → 6시간 → 24시간, 이후 하루다. 다음 실행에서만 확인하며 대기 때문에 worker를 장시간 유지하지 않는다. 한 실행에서 최대 20건의 비용 기록을 오래 확인하지 않은 순서로 조회하고, 요청당 일시적 네트워크/5xx 조회 실패만 한 번 추가 조회한다. 미조회 항목도 전체 차단 판정에는 포함한다. 100건 단위 페이지를 끝까지 확인하며, 분리한 미확정 비용도 계속 조회한다.

비용이 나중에 확정돼도 실패 응답을 정상 원고로 바꾸지 않는다. 정상 응답은 재사용하고, 재시도할 수 있는 거절은 해당 단계로, 그 밖의 실패 응답은 자료·원고 보류로 연결한다. 검토 모델의 거절은 원고 품질 검토 완료로 마감하지 않는다.

## 관리자·알림·감사

관리자 연결·수집 상태에 공통 복구 정책 활성 여부, 국가·기준일, 공통/개별 영향, 미확정 예약, 비용 조회 사유, 추가 시도 횟수와 다음 조회·경로 대기 시각을 표시한다. 원본 요청·공급자 본문은 공개하지 않는다.

분리 후 운영이 재개돼도 미확정 비용 경고는 유지한다. 같은 원인의 확인 시각만 달라졌다면 알림 판본을 바꾸지 않는다. 원인·영향·회계 상태 변경은 기존 관리자 검토 알림으로 연결한다. 복구 판정은 현재 상태와 별도의 추가형 감사 이력으로 보관한다.

## 검증·운영 적용

비용 API 오류, 명확한/불명확한 거절, 같은 실행 재시도 금지, 계보별 한도, 완료 단계 재사용, 월 경계, 동시 경로 확인, 지연 영수증·중복 정산, 100건 초과 조회, 권한과 알림 중복을 검사한다. 실제 저장 입력 복원과 합성 장애·모의 생성은 별도로 기록한다.

운영 반영은 검증 후 구체적 범위를 확인한다. 생성 일시 보류·진행 호출 확인·백업 → 추가형 DB 변경 → 호환 코드 → 비용 전용 확인 → 승인된 정책 활성화·기존 생성 설정 복원 순서다. 현재 남은 다섯 번째 실제 execute는 최신 입력·비용·대기 조건 확인 후 별도로 사용한다. 로컬 검증 성공을 운영 비용 확정이나 실제 AI 생성 성공으로 보고하지 않는다.
