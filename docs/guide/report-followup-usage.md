# 자동 리포트 후속 처리와 익명 이용 집계

상태: **로컬 구현·검증, 운영 미적용**. 기준 실행은 2026-11-10 정기 작업 [#212](https://github.com/erleri/congenial-octo-garbanzo/actions/runs/42774743767)이며, 기존 배포 `681de0c`와 이번 수정은 구분한다.

## 확인한 원인과 한계

#212는 입력 저장을 통과했다. 6통화 모두 원문 처리의 제공 경로 사전 검사에서 보류됐고 모델 호출은 0회다. 환율·독자 메일과 관리자 알림 작업은 각각 성공했다. 기존 저장 용량 장애와 다른 단계의 문제다.

당시 코드는 여러 사전 검사 오류를 `source_endpoint_preflight_hold`로 합쳤고 제공 정보 원본의 해시·검사 시점을 남기지 않았다. 따라서 당시의 세부 원인은 확정할 수 없다. 원문 경로 `sol/azure`와 집필 `sol-us/azure/us`의 차이만으로 원인을 단정하지 않는다.

오늘 저장된 운영 입력을 비공개 로컬로 읽고 원본 해시를 확인한 뒤 현재 공개 제공 정보로 재생했다. 2026-11-10 20:13 KST에 원문 계획 20건은 모두 통과했다. 무료 GET 2회, 모델 호출·신규 예약·운영 쓰기 0회다. 과거 실패가 없었다는 뜻이 아니며, 당시 정보와 현재 정보를 혼동하지 않는다.

## 공통 처리 경로

- 오류를 제공 정보 조회 / 경로 불가 / 지원 기능 / 처리 조건 / 가격·입력 한도 / 요청 구성으로 구분한다. 단계·모델·경로·시각·제공 정보 해시만 기록하고 본문·인증값·예외 원문은 기록하지 않는다.
- 제공 정보 조회를 실행 안에서 공유하고 모델·경로별 5분간 재사용한다. 일시적인 무료 GET 실패만 1회 재시도한다. 유료 요청 재시도 규칙은 그대로다.
- 새 반복 운영 설정은 승인한 모델 경로를 원문 추출·대조·집필·원고 검토에 전달한다. 단계별 출력·가격·예산 계산은 유지한다.
- 기존 동결 입력은 기존 정책·요청 해시로 재개한다. 완료·비용 확정 단계는 제공 정보 장애가 있더라도 재사용하며, 아직 보내지 않은 단계에만 제공 정보 검사를 한다. 미확정 비용은 기존 차단·예약 기준을 유지한다.
- 기존 정책이 남은 실행의 경로는 바꾸지 않는다. 운영 적용 시 기존 보류 실행을 먼저 같은 정책으로 정리한다. 경로 통일 정책으로 전환하려면 남은 실행·예약을 확인하고 새 정책 판본과 새 상한을 명시한다. 과거 요청을 새 설정으로 덮어쓰는 기능은 없다.
- 준비 점검도 실제 원문 요청과 대조 단계의 입력 상한을 검사한다. 집필은 카드가 확보된 뒤 실제 요청으로 기존 검사를 수행한다. 준비 통과만으로 원고 생성 성공을 주장하지 않는다.
- 기술 보류는 관리자 운영 확인 항목으로 남기며 후속 정상 검사 때 해제한다. 장애 기록 저장 자체가 실패하면 기술 장애로 중단한다.

## 리포트 전용 실행

[report-followup.yml](../../.github/workflows/report-followup.yml)은 main에서만 실행한다. 기본 `plan`은 무료 점검이며 `execute`는 기존 변수·서버 활성화·정책·예산을 모두 통과해야 한다. 기존 일일 작업과 같은 `daily-dashboard-email` 잠금을 사용한다. 환율 갱신과 독자 메일 전송은 포함하지 않는다. 실행 뒤 필요한 관리자 알림만 기존 중복 방지 경로로 연결한다. 새 원고는 검토 대기이며 자동 공개하지 않는다.

## 익명 이용 집계 v2

`record_app_usage_v2`는 익명 카운터만 기록한다. `admin_app_usage_v2`는 활성 관리자에게 기간 전체 합계와 원고별 20행 페이지를 제공한다. 기존 v1 테이블·API·UTC 기록은 보존하고 v2 한국시간 기록과 합산하지 않는다.

| 행동 | 의미 |
| --- | --- |
| 화면 조회 | 대시보드·추이·리포트로 실제 이동한 횟수 |
| 추이 구분 | 일별·월별·상세 비교와 선택 통화별 조회 |
| 메일 유입 | `entry=email` 링크로 앱을 실제 연 횟수; 전달된 메일도 포함 |
| 리포트 열기 | 공개 원고 본문을 표시한 횟수 |
| 30초 표시 | 같은 원고가 전면 탭에 연속 30초 표시된 횟수 |
| 근거 펼침 | 해당 화면 방문에서 출처를 처음 펼친 횟수 |
| 대시보드 연결 | 대시보드에서 리포트 링크를 선택한 횟수 |

사용자 ID·이메일·IP·전체 URL·유입 주소·기기 지문은 저장하지 않는다. 고유 독자 수·정독률·메일 오픈율이 아니다. 로그인·관리자·로컬·미리보기·프레임·DNT/GPC는 일반 독자 집계에서 제외한다. 공개되지 않은 원고와 시험 원고도 제외한다. 링크 미리보기만으로 기록하지 않는다.

반복 렌더링·자동 상태 갱신은 새 조회로 세지 않는다. DB 수락 후에만 중복 방지 상태를 확정하며 실패나 로그인 제외 뒤의 정상 재조회는 다시 시도할 수 있다. 별도의 식별 쿠키나 방문자 ID를 만들지 않으므로 새로고침은 새 앱 진입으로 센다. 메일 유입 구분은 현재 페이지의 메모리에만 유지한다.

관리자 화면은 기본 30일이며 7일을 선택할 수 있다. 꺼짐·활성화 후 빈 상태·정상·조회 장애를 분리한다. 요약·일별 그래프/수치·메뉴/통화별 조회·원고별 상세를 제공한다. 1,000행 절단 합산은 없으며 원고별 목록만 페이지로 나눈다. 공개 종료된 원고는 과거 횟수를 보존하되 비공개 제목이나 본문은 노출하지 않는다.

## 검증과 미확인

- 실제 운영 동결 입력 20개 원문 계획: 현재 제공 정보 사전 검사 통과, 외부 모델 전송 없음.
- 로컬 전체 회귀: 1,425건 통과. 이는 코드 검사 수이며 원고 품질 표본이 아니다.
- 격리 DB: v2 권한·집계 23항목 통과. 1,202개 원고 집계 묶음, 7일/30일, 시험 기록 제외, 권한 해제, 장애 알림 중복을 확인했다.
- 합성 UI: 390·1440px, 기간·페이지·꺼짐·빈 상태·오류 화면 확인. 실제 이용률이나 실제 iPhone 검증이 아니다.
- 실제 관리자 브라우저 로그인 검사는 시험 계정 로그인 메일 발송이 자동 승인 검토에서 차단되어 미확인이다. 로그인 우회는 하지 않았고 DB 권한 검사와 합성 UI를 구분했다.
- 타입·린트·운영/리포트/로컬 앱 빌드·공개 번들 검사를 수행한다. 최종 CI와 운영 확인은 아래 반영 단계에서 별도 기록한다.

## 반영·복구 순서

1. CI 통과 후 이 migration 1건과 코드 배포·집계 활성화의 구체적 범위를 승인받는다. `20261110110228_usage_v2_report_followup.sql`은 추가형이며 운영 기본 집계는 꺼진 채 생성한다.
2. 리포트 진행 중 호출·미확정 비용을 확인하고 리포트 생성만 일시 보류한다. 기존 환율·독자 메일·공개 원고는 유지한다. 운영 백업 후 migration → 코드 순서로 적용한다.
3. Netlify `VITE_USAGE_ENABLED` 하나만 확인한다. 전체 환경변수를 조회하지 않는다. 승인 후 웹 값과 DB `enabled/v2_enabled/scope=production`을 맞추고 활성화 시각을 확인한다.
4. 운영 검증용 카운터는 `verification`으로 구분하고 독자 요약에 넣지 않는다. 실제 공개 본문 조회·관리자 요약을 별도로 확인한다. 관리자 로그인 상태의 방문이 기록되지 않는 것은 정상이다.
5. 리포트 전용 `plan`에서 최신 입력·이전 실행 재개·비용을 확인한다. 월 $30 / 실행 $7 / 요청 $0.25 안의 승인된 처리만 실행한다. 독자 메일 전체 작업을 재실행하지 않는다.
6. 원문 처리·집필·검토·검토함·관리자 알림의 실제 결과와 비용을 남긴다. 자료 부족·대상 없음만으로 생성 검증 완료라고 하지 않는다.
7. 문제 시 리포트 실행을 보류하고 집계 v2를 비활성화한다. v1/v2 데이터·동결 입력·비용은 보존하며 migration 삭제나 과거 입력 재작성은 하지 않는다.

현재 운영 집계는 기존 `enabled=false`, 기록 0건이다. 배포된 공개 JavaScript에서는 운영 조회를 제외하는 집계 분기를 확인했다. Netlify 설정 원본의 값 자체는 조회하지 않았으며, 적용 전 해당 키 하나만 확인한다. 이번 수정의 운영 배포·새 유료 생성·메일 발송·실제 이용 집계 활성화는 아직 하지 않았다. 이전 확정 실비 $0.6350093와 미확정 예약 $0.34849는 그대로다.
