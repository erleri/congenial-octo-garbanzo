# 관리자 검토 항목·승인 오류 보강

상태: **로컬 구현·검증, 운영 미반영**. 기존 원고·환율·비용·생성 설정을 수정하거나 추가 모델 호출·메일 발송·공개 승인을 하지 않았다.

## 발견한 원인

| 항목 | 확인한 사실 | 처리 |
| --- | --- | --- |
| COP 11월11일 | 평균 4점·근거 5점이지만 원인 설명 3점, 필수 4점 미달 | 승인 차단 유지. 단순 ‘내용 검토 미완료’ 대신 미달 점수 표시 |
| CLP 11월11일 | 내용 검토 통과·봉인 해시 일치. 저장 series 5,633개 중 숫자 4,388개·명시적 null 1,245개 | 생성 표시 계층과 DB 공개 필드 검사의 불일치. 공개 projection에서만 명시적 결측을 제외 |
| 비용 확인 3건 | 11월2일 MXN 2건 각각 $0.174245, 11월10일 ARS 1건 $0.0949025. 공급자 429 이후 비용 영수증 미확인 | 합계 $0.4433925 전액 예약과 자동 조회 유지. 원고 승인 대상과 구분 |

CLP 원고 내용·기존 series·packet·validation·봉인 영수증을 고쳐 성공 처리하지 않는다. 0 또는 직전 값으로 결측을 채우지 않는다. 공통 공개 변환에서 명시적 null 관측만 제외하고 숫자·순서는 보존한다. 숫자 문자열, 값 키 누락, 잘못된 날짜 타입과 필수 사실의 null은 계속 거부한다. 기존 그래프도 유효 숫자만 그리므로 공개 API의 숫자 타입을 유지한다.

비용 3건은 이번 35회 실행의 확정 비용 $0.74860575와 별개다. `recovery_retry_completed`, `recovery_retry_wait`, `recovery_retry_exhausted`는 각각 재시도 경과이며 원요청의 정산 완료가 아니다. 개별 분리된 예약은 다른 적격 작업을 막지 않으며, 운영자가 ‘승인’해 금액을 0으로 만들 수 없다. 수동 완료 처리나 원장 삭제를 도입하지 않았다.

## 공통 경로 변경

- [DB 공개 필드 검사](../../supabase/migrations/20261111135925_report_approval_missing_series.sql)는 공개 사본에만 적용한다. 기존 저장 확인·권한·원고 품질·공개 승인 조건은 유지한다.
- [공통 JS 공개 변환](../../scripts/currency-report/storage.js)도 같은 결측 규칙을 사용해 다음 생성부터 저장될 공개용 후보의 타입을 맞춘다. 원본 입력과 모델 요청을 절단하거나 수정하지 않는다.
- [승인 요청](../../src/lib/reports/review-action.ts)은 15초 안에 결과를 확인하지 못하면 결과 미확인으로 표시하고 읽기만 다시 수행한다. 자동 승인 재전송은 없다.
- 승인 중 자동 목록 갱신을 멈추고 이전 조회 결과를 무효화해, 늦은 응답이 조용히 사라지는 경우를 방지한다. 권한 해제·탭 이탈 시 비공개 자료를 숨기는 동작은 유지한다.
- 오류·진행·완료 안내를 해당 원고의 버튼 옆에도 표시한다. 서버가 거부한 원고를 UI만 통과시키지 않는다.
- 검토함은 ‘검토·운영 상태’로 표시하고 비용·복구 상태와 원고 승인 행동을 구분한다. 과거 시도 수를 현재 추가 허용 횟수와 나눠 `2/1`처럼 표시하지 않는다.

## 검증과 반영 경계

운영에서 필드 타입·개수, 저장 영수증의 candidate/packet/validation 해시 일치와 미확정 예약 상태를 읽기 전용으로 확인했다. 전체 입력 패킷 조회는 비공개 원문을 포함할 수 있다는 자동 승인 검토의 제한에 따라 진행하지 않았다. 원문 없이 확인한 결측 구조를 합성 자료로 재현했다.

[DB 검사](../../supabase/tests/report_approval_missing_series.sql)는 실제 관리자 승인 함수, 익명·일반 로그인 권한, 봉인 보존, 큰 결측 배열과 잘못된 필드 차단을 확인한다. [UI 동작 검사](../../src/lib/reports/review-action.test.ts)는 지연 응답·중복 클릭·응답 유실에 따른 자동 재전송 방지를 확인한다. 합성 승인 결과는 실제 CLP 운영 승인 성공으로 보고하지 않는다.

운영 코드 `3268a6c`에서 이번 수정만 분리한 로컬 브랜치는 타입·린트, 코드 208파일·1,479항목, 격리 DB 31파일·609항목과 운영/리포트/로컬 앱 빌드·공개 번들 검사를 통과했다. [정제 근거](evidence/review-approval-fix-20261111.json)는 운영 읽기 전용 관측과 합성 로컬 검증을 구분한다. 실제 아이폰과 운영 CLP 승인 성공은 아직 미확인이다.

운영에는 백업 후 DB 함수 변경 1건과 코드 배포가 필요하다. 기존 CLP 원고는 그대로 둔 채 승인 동작을 다시 확인하고, COP 기준·비용 원장·생성 예산·메일 설정은 유지한다. 새 경로 전환 준비안과 이 수정 묶음을 섞어 배포하지 않는다.
