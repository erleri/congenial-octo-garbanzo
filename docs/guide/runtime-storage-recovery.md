자동 복구 대상은 두 가지다. 첫째, `source_endpoint_preflight_hold`가 남아 있고 실제 요청 기록이 0건인 케이스다. 둘째, 집필 준비의 과거 크기 오류이며 해당 케이스의 기존 요청이 모두 비용 확인된 원문 처리인 경우다. 이미 집필한 케이스·미확정 비용·진행 중 요청·공개 원고는 이 복구로 초기화하지 않는다. 복구는 무료 plan에서 수행하지 않으며, 실제 execute의 기존 활성화·정책·예약·동시 실행 잠금 안에서 수행한다.

## 저장 구조와 권한

`runtime-document/2`는 원본 JSON을 Node gzip으로 압축해 기존 서버 전용 객체·조각 저장소에 보관한다. `runtime_documents`는 작은 조회·회계용 명세서와 객체 참조를 보관한다. 기존 SQL 원고 마감 함수에 필요한 packet은 같은 등록 기록에 native JSONB로 두며 문자열 사본을 더하지 않는다. 이 packet은 서버 전용이고 공개 원고의 승인·복사 조건을 바꾸지 않는다.

원본 상한 128MiB·압축 상한 32MiB·조각 512KiB·명세서 256KiB를 검사한다. 작은 기존 입력은 종전 inline 형식을 유지하며 큰 입력만 새 형식으로 보관한다. 기존 task·context 행 크기 제한은 유지한다. 객체 준비 → 조각 저장 → 완전성 확인 → 읽기 복원 → 명세 등록 → 실행 연결의 순서를 따른다. 누락·변조·불일치는 최신 자료로 대체하지 않는다.

새 테이블·등록·복구 함수는 service_role 전용이다. 익명·일반 로그인·관리자 브라우저에 원본 읽기 권한을 추가하지 않는다. 기존 작업의 회계·중복 방지·최종 마감 조건은 유지한다. 기존 공개 이력을 worker가 읽을 때 새 문맥도 복원하며, SQL 메일 조회에 필요한 통화·발행 사유는 작은 명세에 유지한다. 보관 객체의 자동 삭제는 도입하지 않는다.

## 운영 검증과 중단 기준

### 첫 실제 실행에서 확인한 결과

2026-11-10 22:43 KST에 저장·재개 코드 배포를 확인하고 생성 활성값을 복원했다. 무과금 [준비 점검 #3](https://github.com/erleri/congenial-octo-garbanzo/actions/runs/42827286279)은 원래 저장 입력으로 최대 $6.996155001·52회, 모델 호출 0회를 확인했다. 압축 전 50,770,620B·압축 후 8,976,778B·명세 1,254B이며 이미 보관된 객체를 재사용했다.

[실제 후속 실행 #4](https://github.com/erleri/congenial-octo-garbanzo/actions/runs/42828070743)는 최대 5회 중 첫 회다. worker가 과거 기술 보류 6건을 자동 재개했고 실제 모델 요청 11회·확정 비용 $0.2478475·새 미확정 비용 없음으로 종료했다. CLP는 11월 10일 원고를 집필·독립 검토해 `pending_review`로 저장했다. 이 원고의 집필·검토 비용은 $0.1389872이며 원문 처리 비용과 구분한다. 비공개 task 1개·context 2개가 새 보관 구조로 등록되어 실제 마감까지 연결됐다. 관리자 알림 작업도 성공했다. 기존 공개 원고 6건은 변경하지 않았다.

이 실행을 전체 정상 완료로 판정하지 않았다. COP에서는 처음부터 탈락한 후보 1건을 근거의 사후 철회처럼 취급해 다른 유효 근거 2건까지 막는 공통 경로 오류가 확인됐다. 또한 `partial_pending_review`와 적합 기사 없음의 정상 탐색 결과가 프로그램 수리 필요로 분류됐다. MXN의 기간·귀속 검토 탈락 및 BRL·PEN·ARS의 실제 자료 판본 변경은 이 오류들과 구분한다.

### 후속 수정의 범위와 검증

공통 후보 선택에서 **처음 탈락한 미사용 후보**와 **이미 채택한 근거의 철회·충돌·무효화**를 구분한다. 아직 task를 만들지 않았다면 탈락 후보는 일반 선택 단계에서 제외하고 다른 검증 자료를 평가한다. 이미 사용한 근거·과거 승인 근거·철회·충돌·재검토 필요 차단은 유지한다. 정상 탐색 상태는 진단에 남기되 기술 장애 알림으로 올리지 않고, 알 수 없는 오류는 계속 기술 장애로 다룬다.

`runtime-source-candidate/1` 복구는 해당 과거 사전 차단을 원래 입력으로 다시 검사하도록 worker에 한 번만 돌려준다. 이력·비용·응답을 보존하고, 집필 완료·진행 중/미확정 비용·철회·충돌은 복구 대상에서 제외한다. 재개 자체는 근거 승인이나 집필 자격이 아니다. 무료 plan은 조회만 하며 실제 execute에서만 복구한다.

저장된 실제 COP 입력 무료 재생에서 기존 차단 `original_pipeline_failed`가 없어졌고 승인 자료 2건·탈락 후보 1건 및 전체 입력 해시가 유지됐다. 새 모델 호출·운영 상태 수동 수정은 0건이다. PR #29 최종 CI는 코드 204파일·1,438항목, DB 29파일·547항목과 타입·린트·빌드·자료/기간·복구 검사를 통과했다.

후속 통합 검사는 6통화 각각에 미사용 탈락 후보를 넣고 task 저장 전에 합성 장애를 발생시켰다. 공통 조정 경로가 같은 입력을 복구한 뒤 유효한 근거로 집필·독립 검토를 진행했고, 재개 시 원문 처리의 추가 요청 없이 집필·검토 2회만 요청했다. 탈락 기록은 유지되고 사용 근거에는 포함되지 않았으며, 완료 후 다시 실행해도 요청이 늘지 않았다. 이는 합성 모델 응답을 사용한 로컬 연결 검사이며 실제 6통화 생성 성공이 아니다.

PR #29는 사용자 승인 후 운영 migration `20261110142727` 적용 및 23:28 KST 배포를 확인했다. 생성 설정은 전환 중에만 보류했다가 같은 Sol·예산 조건으로 복원했다(제어 판본 11). 적용 전 암호화 백업은 89개 테이블 내용 해시·정책 16개·소유자·권한·핵심 역할 속성의 로컬 복원 대조를 통과했다. 신규 복구 함수는 서버 전용이며 익명·관리자 브라우저 실행 권한이 없다.

두 번째 [실제 execute #6](https://github.com/erleri/congenial-octo-garbanzo/actions/runs/42835434602)은 worker가 COP 과거 사전 차단을 자동 재개하고 `frozen_country_material_superseded`로 전환했다. 현재 수집 판본이 달라진 것을 확인했으므로 오래된 입력을 강제로 집필하지 않았다. 모델 호출 0회·신규 비용 $0·새 미확정 비용 없음이며 전체 상태는 정상 검토 대기(`review_wait`, 종료 코드 0)다. 첫 실행의 CLP 검토 대기는 유지됐다. 관리자 알림은 `already_recorded`·전송 0회로 중복을 막았다. 이 결과는 실제 자동 복구·정상 상태 분류의 운영 증거이며, COP 새 원고 생성 성공으로 계산하지 않는다. 다음 공통 사이클의 최신 입력 준비·처리는 별도로 확인한다.
