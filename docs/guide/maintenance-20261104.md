## 청소와 복원

- 기존 변경과 비공개 자료의 기준 목록 30,777파일을 기록하고 압축 내용의 SHA-256을 확인했습니다. 비밀 환경파일은 값 복사 없이 해시로 보존 여부만 검사했습니다.
- 작업 폴더에서 **432.43MiB** 제거: 보관한 원본 **232.79MiB**, 재설치 가능한 옛 의존성 **199.64MiB**.
- 삭제 대상: `scratch.ts`, `scratch_test.js`, `inspect_excel.js`, 옛 `clean-verify-359521bf`, 옛 `release-off-build-20261016`, 중복 `schema-proposals/ui2_usage.sql`.
- 원고·근거·비용·승인·발송·복구 자료와 실제 migration은 유지했습니다. 원문/비용을 포함한 6통화 시험 폴더는 용량이 커도 삭제하지 않았습니다.
- 현재 서버가 쓰는 `dist-ui2-preview`, UI 비교 자료·메일 시안은 유지했습니다. 다른 작업 폴더·공유 Git 이력·복구 키는 손대지 않았습니다.

비공개 복구 위치는 작업 저장소 옆 `latamfx-maintenance-private/20261104`입니다. `baseline.json`, `cleanup-plan.json`, `disposition.json`, `baseline.zip`, `restore-cleanup.py`가 원래 경로·해시·처리·복원을 연결합니다. `restore-cleanup.py --output <새 폴더>`는 새 위치에만 복원하며 현재 작업을 덮어쓰지 않습니다. 원본 코드와 큰 데이터 파일2개를 실제 별도 폴더에 복원해 해시 일치를 확인했습니다. 전체 보관 대상도 ZIP에서 읽어 해시를 확인했습니다. 재설치 의존성은 보존한 과거 lockfile로 `npm ci`하여 재생성합니다.

**저장소 밖에 만든 안전 백업 722.43MiB는 별도입니다.** 작업 폴더 감소를 PC 전체 디스크 절감으로 주장하지 않습니다. 현재는 되돌림 안전성을 위해 백업을 유지하므로 전체 디스크는 증가했습니다. 보관소 만료·자동 삭제는 설정하지 않았습니다.
