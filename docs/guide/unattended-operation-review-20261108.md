## 활성화 전 수정 대상

### A1. 수집 실패 때 저장 기사 재사용도 막힘

- 위치: `scripts/currency-report/retained-research.js:10–11`.
- 원인: 재사용 가능한 기간을 **이번에 수집에 성공해 만든 검토 카드**에서만 구한다. 검토 대기열이 비면 즉시 반환한다. 조사하려던 기간과 수집 성공 여부가 묶여 있다.
- 재현: 같은 기간의 등록된 저장 후보 1건이 있어도 새 검토 대기열이 0건이면 재사용 0건. 기간을 가진 카드가 있을 때는 1건을 재사용했다. 기존 테스트는 원문이 없는 상태에서도 새 카드가 남아 있는 부분 실패만 다뤘다.
- 영향: 일시적인 전면 수집 실패 때 저장된 유효 자료를 평가할 기회까지 사라진다. 공식 지표 캐시와 달리 뉴스 재사용의 완전 실패 경로가 취약하다.
- 최소 수정: 이미 계산한 조사 기간을 재사용 함수에 명시적으로 전달한다. 현재 출처 등록·기간·규칙·철회·수정 충돌 검사를 그대로 유지한다. 저장 자료의 수집일을 오늘로 바꾸지 않고, 오래된 자료만으로 새 환율 원인을 승인하지 않는다.
- 완료 조건: 전체 조회 실패/정상 회복/기간 경과/출처 제외/새 수정본 충돌 각각에서 허용된 자료만 보존 또는 제외. 유료 검토 재사용과 집필 자격은 별도 검사.

### A2. 한 국가의 이력·정정 확인 실패가 전체 생성 중단으로 확대됨

- 위치: `scripts/currency-report/operating-cycle.js:51–52`; 국가별 진단 저장도 같은 함수 63행에서 예외를 격리하지 않는다.
- 원인: 국가별 정정 확인 실패를 전역 `correction_recording_required`로 합친다. 단순 기사 부족은 분리되지만 이력 조회 실패는 분리되지 않는다.
- 재현: PEN 이력 조회에만 합성 실패를 주자 나머지 5개국은 `planned`인데 전체는 `configuration_or_input_hold`, 모의 모델 호출 0회가 됐다.
- 영향: 일시적인 한 국가의 저장 상태 문제를 해결하기 전까지 정상 국가도 진행하지 못한다.
- 최소 수정: 국가별 이력·정정·상태 저장 오류는 해당 국가의 유료 작업 전에 보류하고 다음 국가로 진행한다. 실패한 국가는 다음 실행에서 다시 확인한다. **공유 자격 오류, 전체 DB 장애, 비용 미확정, 승인/예산 불일치, 공통 무결성 문제는 전역 중단을 유지**한다. 오류를 숨기거나 기록 실패 상태로 해당 국가를 게시하지 않는다.
- 완료 조건: 한 국가만 실패 → 다른 5개 진행, 다음 실행에서 실패 국가만 복구, 기존 승인 대기 원고·호출 중복 0. 전역 보안·회계 실패는 여전히 전체 유료 중단. 상태 저장 예외도 같은 범위 계약으로 검증.

### A3. 후보량이 많으면 예산 내 작업도 시작하지 못함

- 위치: `scripts/currency-report/operating-batch-plan.js:116–125`.
- 원인: 발견한 후보 전체의 최대 비용·호출 수를 한 번의 묶음에 합산한다. 한도를 넘으면 전역 보류한다. 발행할 필요가 없는 국가에도 보수적인 집필·검토 슬롯을 더하는 계산이 있다.
- 재현: 한 국가 25건, 나머지 국가 각 1건인 합성 입력에서 72회/$8.34603 상한이 계산되어 전체 보류, 모의 호출 0회였다. 6개국 모두 준비 상태인데 승인된 한도 내 일부 처리도 못 했다. 이 금액은 합성 입력 계산이며 실제 비용이 아니다.
- 영향: 뉴스가 많은 날마다 한도 확대나 후보 수동 제거를 요구하는 운영이 될 수 있다. 초과 지출 차단은 옳지만, 자동 대기·이어서 처리하는 준비 단계가 부족하다.
- 최소 수정: 월/회차/요청 한도는 유지하고, 통화별 공정한 순서로 한도에 들어가는 독립적인 검토 단위를 고른다. 나머지는 이유·우선순위·정확한 입력을 보존해 다음 회차로 이월한다. 새 실행 ID로 예산을 초기화하거나 본문을 잘라 넣지 않는다. 같은 근거 재검토·같은 원고 집필을 중복하지 않는다. 실제 작성 대상만 집필·검토 비용을 예약하되 이미 승인된 총한도는 늘리지 않는다.
- 완료 조건: 상한 미만·정확히 상한·초과·월 예산 소진·재시작·동시 실행·근거 변경에서 누락/중복/초과 과금 0. 앞 순서 국가만 계속 처리되는 편향도 확인.

## 이미 작동하는 부분

같은 오프라인 실행에서 PEN의 뉴스만 HTTP 503 상태로 만들었을 때, 나머지 5개국은 모의 생성·검토를 거쳐 승인 대기 초안으로 이어졌다. 동일 실행을 다시 수행해도 추가 모의 호출은 0회였다. 따라서 '모든 국가가 항상 함께 멈춘다'는 진단은 틀리다. **기사 부족은 격리되지만 이력/정정 실패와 전체 사전 비용 계산에는 전역 중단이 남는다.**

기존 코드의 다음 경계도 유지해야 한다: 대시보드 휴일 이월과 뉴스 날짜 분리, 무료 수집을 발행 필요와 독립 실행, 원문/기간/출처 검사, 자동 게시 금지, 비용 미확정 시 후속 유료 요청 중단, 동일 원문 검토 캐시와 국가별 실행 소유권. 이들은 이번 발견을 고치려고 완화할 규칙이 아니다.

## 운영 표시·진단 보완

- **공식 발표 일정:** MXN의 현재/전월 PDF를 조회하는 코드는 공식 발표 달력과 연결되어 있지 않다. 직전 '발표 전이므로 정상' 판단은 원문 달력 대조 결과다. 자동 수집은 여전히 `not_found`로 기록한다. 발표 예정/발표 후 미확보/접근 장애를 별도 표시하고, 달력을 확인하지 못하면 `발표 여부 미확인`으로 남겨야 한다. 미발표인 소비 지표만으로 FX 원인 검토 전체를 막지 않는다. 일회성 날짜 하드코딩은 금지한다.
- **전체 상태:** 합성 실행은 5개국 성공·1개국 부족인데 현재 실행 대표 결과는 `failure`다. 상세 행에는 구분되지만 Actions 요약은 짧고 일상 리포트 job에는 기존 메일을 보호하려는 `continue-on-error`가 있다. 메일 보호는 유지하되 정상 대기/국가별 장애/공통 중단과 다음 행동을 관리자 결과에서 분명히 보여야 한다. 실제 관리자 화면이나 알림 전달까지 이번에 확인했다고 주장하지 않는다.
- 외부 사이트의 개편·유료화·인증 만료를 영구적으로 없앨 수는 없다. 중요한 것은 정상 대기는 자동으로 넘어가고, 일시 장애는 다음 일정에 복구하며, 수동 판단은 권한·비용·출처 변경처럼 필요한 경우에만 요청하는 것이다.
