# 환율 중심 생성·검토 기준 — 2026-11-02

이번 변경은 로컬 공통 생성 경로의 교정이다. 기존 원고·환율·비용·승인을 수정하지 않았으며 유료 호출, 운영 DB 변경, 배포, 게시를 하지 않았다.

## 고정된 우선순위

1. 무엇이 달라졌나: 대시보드와 같은 저장 기준환율과 코드의 변동 계산을 사용한다.
2. 왜 움직였나: 확인한 시장 사건 → 출처가 설명하는 반응 경로 → 해당 통화의 연결이 핵심이다.
3. 앞으로 확인할 변수: 앞선 설명과 연결되는 근거가 있을 때만 제시한다.
4. 사업 참고: 환율 이해에 직접 도움이 되는 경우에만 짧게 추가한다. 소비통계가 있다는 이유로 넣지 않는다.

최초·누적 변화·정기 점검·새 자료 업데이트 모두 같은 기준을 적용한다. 정기 점검이 새 원인을 요구하는 것은 아니다. 현재 자료가 기존 환율 설명을 재확인하거나 보완할 수 있어야 한다. 이전 원고 자체는 현재 근거가 아니다. 환율 해설이 부족하면 조사·근거 대기로 남기고 이전 공개 보고서를 유지한다. 소비·정책 소개로 대신 집필하지 않는다.

누적 2%, 2주 미발행 후 정기 점검, 기존 휴일의 직전 값 선택과 대시보드 환율 공급 경로는 변경하지 않았다. 이는 조사 시점을 정하는 규칙이고 집필 자격을 면제하지 않는다. 주말 뉴스도 독립 자료 시점으로 처리하되 과거 기준환율의 원인으로 소급하지 않는다.

기사 자체의 해설은 `publication_view`, 기관의 견해는 `institutional_view`, 이름 있는 전문가 발언은 `attributed_view`다. 최종 카드에서는 귀속 견해로 연결하되 귀속 유형을 유지한다. 매체 해설에 가상의 전문가 이름을 붙이지 않는다. 매체 도메인·기관·인명·원문 위치를 검사하고 별도 대조가 모든 하위 주장과 조건을 확인해야 한다.

날짜가 누락된 과거 응답을 고쳐 재사용하지 않는다. 새 실행의 `eventDateEvidence`에는 명시/상대/미상, 원문 구절·블록 위치, 같은 날/전날 관계를 요구한다. `hoy`, `hoje`, `ayer`, `ontem`, `este viernes` 등은 현지 발표일과 실제 달력 관계가 맞아야 한다. 사건 구절인지 다른 사건·회고·예정 표현인지는 별도 검토한다. 정확한 장중 관측시각이나 종가 여부는 이 계산으로 만들지 않는다.

## 실제 저장 결과 재생

대상: 2026-11-01 실제 실행의 원문 추출 24건과 원고 6건. 이전 비용 $0.8520151 및 원응답을 보존했다. 기존 29개 파일의 재생 전후 해시가 같으며, 새로운 평가 파일만 별도 저장했다.

| 통화 | 새 기준 결과 | 기술 검토 입력 |
|---|---|---|
| BRL | 환율 설명 없음 → 보류 | 준비 가능, 호출하지 않음 |
| MXN | 환율 설명 없음·보조 문단 과다 → 보류 | 기존 입력도 요청당 기존 $0.25 상한 안에서 준비 가능 |
| COP | 환율 설명 없음 → 보류. 기존 ‘명목 매출 증가’ 범위 오류 기록 보존 | 준비 가능, 호출하지 않음 |
| PEN | 환율 설명 없음 → 보류 | 준비 가능, 호출하지 않음 |
| CLP | 환율 설명 없음 → 보류 | 준비 가능, 호출하지 않음 |
| ARS | 환율 설명 없음 → 보류 | 준비 가능, 호출하지 않음 |

24건의 과거 추출 출력은 그대로 검사했다. 사건일 미상 16, 요청 기간 불일치 2, 환율 해석을 사실로만 반환한 출력 1, 추출 정보 부족 2, 무관 1, 별도 비교 후보 2다. 마지막 두 후보 역시 과거 대조에서 기간·가격 기준 문제로 보류됐으므로 이번에 채택 기사로 승격하지 않았다. **새 규칙이 과거 기사 24건을 자동으로 구제했다는 뜻이 아니다.**

멕시코의 검토 요청은 새 계산에서 보수적 입력 예약량 54,963, 비용 상한 $0.2193275다. 이는 실제 사용량·청구액이 아니며 호출 승인도 아니다. 동일 입력을 손실 없이 복원하는 검사를 통과했다. 모델 문맥 한도와 실제 제공 가격·지원 기능은 실제 호출 전에 다시 검사한다.

검토 사전 점검은 집필 전에 이미 명백히 큰 **고정 근거 입력**을 막는다. 아직 생성되지 않은 원고의 최종 길이까지 보장하는 검사는 아니다. 원고 생성 뒤 실제 검토 요청을 다시 계산하며, 넘치면 근거를 자르거나 자동 재시도하지 않고 원고를 보존하고 보류한다.
