# 정기 점검 집필 기준 보강 — 결론형 제목과 경고 배치

2026-10-27 · `periodic-writing/2` · 저장 원고 검증 · 신규 유료 호출·운영 적용 없음

## 문제와 변경 범위

Sol의 실제 정상 점검본은 제목을 “전회 설명은 이번에도 분석가의 견해를 통해 점검할 수 있다”로 작성했다. 요약과 구리 문단에는 전체 기간 원인 지속·기여 크기를 확인하지 않았다는 안내가 반복됐다. 이전 자동 편집 검사는 경고를 남기지 못했고 별도 독자 검토에서 문제를 지적했다.

이전 집필 지침은 정상·보완·미확인 상태가 무엇을 뜻하지 않는지 반복해서 설명했다. 실제 출력에도 그 제한이 본문으로 옮겨졌다. 이것이 모델 응답의 유일한 원인이라고 검증한 것은 아니지만, 입력 설계에서 개선할 부분으로 판단했다.

이번에는 **다음 생성에 사용하는 공통 지침·스키마 설명·문장 검토·편집 신호**를 보강했다. 기존 AI 원고·수동 샘플·비용·점수·A안 파일은 바꾸지 않았다. 정상 점검 외 설명 보완·일부 근거 부족에도 같은 집필 버전을 전달한다. 특정 통화나 모델 전용 예외는 만들지 않았다.

## 새 작성 기준

| 영역 | 집필 기준 | 유지하는 경계 |
| --- | --- | --- |
| 제목 | 확인한 대상과 해석상 결론을 함께 전달 | 점검 가능·자료 존재에 머물지 않음. 실제 원인 지속·우열을 추가하지 않음 |
| 요약 | 이번에 확인한 경로와 전회 설명을 읽는 데 필요한 결론 | 제목 반복·검토 요지 소개·공통 경고로 분량을 채우지 않음 |
| 설명 | 출처에 귀속한 이번 근거와 의미 | 첫 문장으로 충분하면 종료. 추가 문장은 새 경로·변화·중요 조건이 있을 때만 |
| 범용 한계 | 코드가 접힌 공통 한계 영역에 한 번 표시 | 요약·매 문단의 일반 면책으로 반복하지 않음 |
| 중요한 조건 | 해당 설명 곁에 유지 | 실제 반대 근거·조건·가격 기준 차이를 줄이는 작업은 하지 않음 |
| 관찰 항목 | 의미 있는 다음 확인 질문만 선택 | 근거 없는 일정과 발표일을 만들거나 항목 수를 채우지 않음 |

정상 점검의 결론은 이번 근거가 지지하는 기존 설명의 경로다. 설명 보완은 새로 확인한 경로나 조건을, 일부 근거 부족은 확인된 부분의 결론을 전달한다. 전회 설명을 현재 원인의 증거로 쓰거나 미확인을 영향 소멸로 바꾸는 것은 계속 금지한다.

상태의 제한은 구조화된 `scopeGuardrails`로 전달한다. 지면에 붙일 문구가 아니라 주장 선별 규칙이다. `readerTask`는 상태별 독자 질문을 알려 준다. 일반 원인 보고서용 문체 예시는 정기 점검 입력에서 제외했다. 제목·요약·본문의 스키마 설명과 집필 지침은 같은 정의를 참조한다.

## 코드와 검토 연결

- `periodic-editing.js`: 공통 집필·검토 기준, 스키마 설명, 알려진 문체 신호, 공통 한계 조립.
- `periodic-check.js`: 세 상태의 독자 질문·구조화된 경계·집필 버전을 공통 입력에 연결.
- `openrouter.js`: 전송 지침·스키마·별도 한계 영역에 적용. 한계 문구 용량 부족은 외부 요청 전에 중단.
- `editorial.js`·`rules.js`: 과정 중심 제목·과정 문장·범용 한계·여러 위치의 반복을 검토 신호로 기록.
- `claim-review.js`: 새 집필 버전과 검토 결합을 확인. 이전 지침에 대한 검토를 그대로 재사용하지 않음.

숫자가 들어 있는 기존 가격 한계 문구는 정확히 보존한다. 공통 한계를 추가하면서 기존 조건을 잘라 내지 않는다. 네 개 한계 슬롯이 부족하면 숫자 없는 안내끼리 묶고, 보존할 수 없으면 조용히 누락하는 대신 입력 준비를 중단한다.

검사 신호는 문체 검토 후보이며 원고를 자동 수정·삭제하지 않는다. 과정 문장은 R05, 제목은 R10, 범용 한계 반복은 R07의 미검증 신호로 연결한다. 같은 단어가 있다는 이유로 사실 오류·게시 불가를 확정하지 않는다. 의미상 인과·귀속·범위 확대는 기존 문장별 근거 대조를 계속 거친다.

데이터·유형 선택 계약은 `periodic-check/1`을 유지하고 집필·검토 정책을 `periodic-writing/2`로 구분했다. 원인 보고서·경제 업데이트의 기본 프롬프트는 변경하지 않았다. 기존 응답과 점수는 당시 기록으로 보존한다.
