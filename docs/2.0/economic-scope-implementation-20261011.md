# 공통 근거 범위의 생성과 검토 연결

근거 카드의 대상·단위·기간·비교 범위를 실제 생성 입력과 문장 검토에 연결했다. 칠레 저장 원고 두 건에서는 제목의 선도 표현과 가계 부담 확대가 교정 대상으로, 전체 순위는 확인 대기로 남았다. 같은 물가지수 안에서 음의 기여가 상승을 일부 상쇄한다는 설명은 유지됐다.

## 적용한 계약

새 생성 입력은 `currency-input/5`, 경제 업데이트는 `economic-update/3`, 문장 검토는 `claim-review/4`다. 공통 카드 `evidence-scope/1`은 [범위 검토 기준](economic-scope-review-20261011.md)을 사용한다. 과거 요청·원고·점수·비용·검토는 당시 버전으로 보존했다.

`evidence-scope.js`는 검토자가 명시적으로 작성한 카드를 출처의 URL·발표일·대상 기간·전체 본문 해시·전달 구절 해시에 묶는다. 카드 내용이 바뀌어도 새 검토 결합이 필요하다. 출처·기간·구절·범위가 변경된 옛 카드는 생성 전에 거절한다. 해시는 무결성 확인이며 사람 인증이나 내용의 진실 판정이 아니다.

모델에는 지표 대상·단위·비교 기준, 채택 가능한 주장, 제외할 확대, 미포함·미확인 정보, 교차 문장에 필요한 출처를 전달한다. 검토자 신원·내부 승인·보관 원문 영수증은 전달하지 않는다. 경제 업데이트의 신규 요청에는 카드가 필수이며, 기존 환율 설명 경로에도 동일한 카드 계약과 작성 기준을 적용할 수 있다. 카드가 없는 기존 환율 자료에 근거를 자동 생성하지 않는다.

경제 업데이트는 지표 구성과 소비 맥락을 설명한다. 환율 원인 설명은 시장 반응과 해당 통화의 연결을 설명한다. 공통 검토자는 두 목적을 구분하고 제목·요약부터 비교 집합, 지수와 가계, 기간, 자료 부재, 문장 전체의 지지를 확인한다. 조건부 원리는 기존 승인된 적용 계약을 따른다.

## 문장 출처의 누락 처리

생성자가 제출한 문장 대응표를 검토 입력에도 전달한다. 제목·요약은 실제 문장에 붙인 출처를 사용하고, 대응표를 제공하지 않는 이전 검토 경로는 기존 원문 대조 방식을 유지한다. 출처를 붙인 것 자체를 의미적 지지로 평가하지 않는다.

한 문장이 두 출처를 참조했는데 해당 단락에는 하나만 연결되어 있으면 `block_source_missing`을 기록한다. 검토자가 모든 문장을 `supported`로 평가해도 이 오류는 남으며, 교정이나 검토 통과로 우회할 수 없다. 출처를 보완하면 새 검토 결합이 필요하다. 표현을 바꾸거나 누락 출처를 자동 추가하지 않는다.

공개 저장 투영에서는 범위 카드와 문장 대응표를 제외한다. 원문 구절과 검토 정보의 기존 비공개 경계도 유지한다. 실제 모델 시험 명령은 카드 검토 결합과 전송 입력의 일치를 호출 전에 확인한다. 경제 카드의 첫 새 정보도 검토 결합된 채택 주장으로 조립해, 옛 카드의 별도 요약이 다시 유입되지 않도록 했다.

## 저장 자료 평가 결과

| 대상 | 자동 검사와 참조 | 에이전트 원문 대조 |
| --- | --- | --- |
| 칠레 /1 원본 | 기존 괄호 위치 문법 때문에 현행 스키마 불합격. 자동 변환하지 않음 | 실제 수요 자료 부재를 단정한 문장은 교정 대상 |
| 칠레 /2 원본 | 임금 단락에 물가 출처 누락. 검토 결과와 별도로 차단 | ‘주도’ 소제목과 실제 생활 부담 비교는 교정. ‘가장 컸다’는 순위 확인 대기 |
| /2 출처만 보완한 예시 | 참조 오류 해소, 자동 검사 통과 | 기존 제목·본문의 범위 문제와 순위 확인 대기는 유지 |
| /2 범위를 좁힌 편집 대조 | 자동 검사·출처 연결 통과 | 지수 가격 상승·양의 기여로 한정한 세 문장은 지지됨. 기존 음의 기여 상쇄 설명도 유지 |

편집 대조는 에이전트 작성 예시이며 새 AI 원고나 공개 보고서로 저장하지 않았다. 의미적 대조는 작성자의 자기 점수나 정규식 판정이 아니라 보존된 원문 구절을 읽은 에이전트 판단이다. 사람 독자 평가·실제 모델 품질·게시 승인은 남는다.

물가 원문의 강조 표현은 전체 순위를 증명하지 않지만 반대 순위도 증명하지 않는다. 이에 따라 순위 확인 대기와 확인된 범위 초과를 구분했다. 입력 카드의 부재 단정은 새 입력에서 ‘이번 입력에 판매 자료 미포함’으로 바로잡았다.

## 재현과 검증

저장소에서 portable Node를 사용해 다음 명령을 실행한다.

```powershell
node scripts/currency-report/replay-economic-scopes-local.js
```

이 명령은 키·네트워크·DB를 사용하지 않는다. 고정된 두 원고, 실제 입력, 기존 평가와 공식 원문을 읽고 새 private 폴더에 요청 준비·재평가·대조 예시를 저장한다. 과거 10개 파일의 전후 해시를 확인한다. 승인 기록을 새 입력에 복사하지 않으며 공개 보고서 파일을 쓰지 않는다.

이번 결과는 `.local-reports/private/economic-scope-replays/run-z7XXpT`다. 신규 API 호출·비용은 0이고 기존 실제 지출 $0.061774를 보존했다. 준비된 요청의 계산상 상한은 $0.144936이며 **승인되거나 실행된 예산이 아니다**. 기존 두 번의 개별 승인은 소진됐고 새 요청의 `paidCallAuthorized`는 false다.

공통 범위 카드의 투영·변경 무효화·미확인 정보 상태·참조 누락을 담당하는 테스트 4개를 추가했다. 기존 경제 생성 연결과 공개 투영 테스트는 새 계약을 확인하도록 보완했다. 전체 67파일·373개 선언·467개 실행 사례 통과, 매개변수 확장 94개다. 중복 이름·동일 본문·자기 비교 감사에서 발견된 항목은 없다. 이 감사는 의미적 중복의 부재나 실제 원고 품질을 증명하지 않는다.

타입 검사·린트·운영 빌드·리포트 빌드·번들 경계가 통과했다. Windows 샌드박스의 임시 파일 rename 권한 때문에 최초 테스트는 시작하지 못했고, 정상 실행 환경에서 관련 40개와 전체 회귀를 확인했다. 기존 운영 진입 번들 804,454바이트 경고는 유지한다. 로컬 기존 A안 원고 응답은 HTTP 200, private 재평가 파일은 HTTP 403이었으며 새 카드·대응표·검토 필드가 공개 응답이나 두 브라우저 번들에 없음을 확인했다. DB 변경이 없어 pgTAP은 재실행하지 않았다. A안 코드·원고를 변경하지 않아 새 시각 비교도 수행하지 않았다.

## 남은 실제 품질 시험

위 코드 연결 당시 새 입력의 실제 모델 품질은 미검증이었다. 후속 별도 승인으로 [같은 근거의 세 번째 실제 생성](economic-scoped-trial-20261011.md)을 확인했다. 자동 검사와 이전 범위 오류는 개선됐지만 반복 경고·관찰 항목과 비교 제한 범위가 남아 미채택이다. 기존 원고·평가·비용을 수정본으로 대체하지 않았다. 권장 작업 모델은 실제 원문·내용 평가 Astra High, 추가 구현 Sol High다.
