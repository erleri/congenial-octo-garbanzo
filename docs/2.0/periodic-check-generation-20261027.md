# 정기 점검본의 공통 생성·검토 연결

2026-10-27 · `periodic-check/1` · 로컬 구현 · 유료 호출·운영 적용 없음

후속 현재 집필 기준: [정기 점검 제목·반복 경고 보강](periodic-writing-rules-20261027.md)의 `periodic-writing/2`. 아래는 최초 연결 기록이며 실제 모델 시험·이후 편집 보강과 구분한다.

## 독자에게 전달할 결과

정기 점검본은 전회 이후 가격과 기존 설명을 짧게 다시 확인한다. 새 사건이나 당일 원인을 의무적으로 만들어 쓰지 않는다. [세 가지 편집 샘플](periodic-report-samples-20261027.md)의 구분을 공통 입력·출력·문장 검토 경로에 연결했다.

| 확인 결과 | 선택 조건 | 집필 범위 |
| --- | --- | --- |
| `normal_check` 정상 점검 | 전회 항목 모두에 이번 검토 근거가 있고 추가·조건 보완이 없음 | 기존 설명을 이번 자료와 대조. 시장 무변화나 전체 기간 원인 지속을 뜻하지 않음 |
| `explanation_update` 설명 보완 | 기존 항목을 재확인했고 새 항목 또는 명시적으로 검토한 조건 보완이 있음 | 추가·보완을 설명. 실제 원인 교체·기여도 순위로 확대하지 않음 |
| `partial_evidence` 일부 근거 부족 | 확인 가능한 항목이 있지만 전회 항목 또는 현재 검토 후보 일부가 미확인 | 확인한 설명만 작성. 미확인은 공통 확인 범위에 한 번 표시 |
| `hold` 보류 | 확인된 설명이 전혀 없거나 전회·가격 비교가 성립하지 않음 | 집필 입력을 만들지 않고 사유 반환 |

자료 부족과 설명 보완이 동시에 있으면 일부 근거 부족 상태를 우선 표시한다. 개별 항목에는 추가·재확인·조건 보완 상태가 남는다. 설명 두 개는 상한이며 전회 항목 우선·새 항목 입력 순으로 선택한다. 중요도 순위로 표시하지 않고 생략한 항목 ID를 기록한다.

## 입력부터 검토까지

1. **전회 기준 확인:** 공개본 ID·통화·발행일·관측일·가격·가격 기준·설명 항목을 받는다. 대기·반려 원고를 전회 공개본으로 쓰지 않는다.
2. **가격 대조:** 공급자·시리즈·가격 종류·거래일 기준·시간대를 비교하고 저장 시계열의 전회·현재 값을 확인한다. 코드가 누적 변화율과 방향을 계산한다. 현재 기준일과 관측일이 다르거나 동일 날짜 가격이 중복되면 보류한다.
3. **근거 연결:** 기존 검토 카드의 출처 ID·구절 ID·해시와 이번 설명의 적합성 검토를 받는다. 통화·당일 기간·원본 결합이 맞지 않거나 검토가 없으면 해당 항목을 미확인으로 남긴다. 소비 통계를 당일 환율 원인 대신 넣지 않는다.
4. **상태 선택:** 전회 설명 항목과 이번 확인 항목을 비교해 위 상태를 결정한다. 기사 수·키워드만으로 의미 변화를 추정하지 않는다.
5. **집필 입력 구성:** 선택한 항목의 구절만 모델에 전달한다. 같은 DF 카드 안에서도 선택하지 않은 다른 요지까지 포함하지 않는다. 전체 기사나 이전 수동 원고를 정답으로 전송하지 않는다.
6. **코드 조립·자동 검사:** 전회 대비 수치·방향·미확인 항목을 코드가 조립한다. 모델은 제목·요약·선택한 설명·선택적 다음 질문과 위치별 출처 ID를 제출한다. 잘못된 개수·출처·문장 구조·수치·업무 지시는 기존 검사 경로에서 차단한다.
7. **내용 검토:** 문장의 모든 주장과 선택 구절을 대조하고, 정기 점검 전용 네 판단을 별도로 남긴다. 자동 검사 통과는 내용 통과·게시 승인이 아니다.

현재 공식 일정 입력은 추가하지 않았다. 일정 근거가 없으면 발표일을 만들지 않으며, 다음 확인 질문은 편집상 질문으로 구분한다. 영업 문단은 강제로 추가하지 않는다. 본문 300~600자는 가독성 참고이며 최소 길이 검사는 없다. 짧은 설명을 한 문장이라는 이유만으로 보강 요구하지 않는다.

## 검토자가 반드시 남길 네 판단

| 항목 | 확인하는 것 |
| --- | --- |
| `comparison` | 전회·현재 가격과 설명의 비교 기준 |
| `stateMeaning` | 정상→무변화, 보완→원인 교체, 미확인→영향 소멸의 확대 여부 |
| `evidenceScope` | 문장별 귀속·기간·통화 연결을 실제 구절이 지지하는지 |
| `readerValue` | 반복 경고·분량 채우기 없이 점검 결과를 전달하는지 |

각 항목은 `pass / hold / unverified`와 구체적 이유를 요구한다. 문장 검토가 있어도 이 판단이 누락되면 내용 검토를 완료로 처리하지 않는다. 시점·귀속·범위 오류는 필수 교정, 제목·반복·표현은 문체 개선으로 구분한다. 기존 안전한 조건부 설명을 경고 부족만으로 반려하지 않는다.

품질 평가는 변화 전달·점검 유용성·가독성·근거 충실도의 네 항목이다. 평균 4/5 이상·근거 4/5 이상·중대 오류 0건과 필수 검토 통과를 함께 요구한다. 이 기준을 코드에 연결한 것이며 실제 원고가 해당 점수를 달성했다는 결과는 아니다.

## 구현 위치와 재사용

- `scripts/currency-report/periodic-check.js`: 준비·근거 상태·유형 선택·비교 수치·집필 범위.
- `openrouter.js`: 기존 생성 입력·스키마·조립 경로에서 선택적으로 `periodic_check` 처리. 일반 원인 보고서 지침과 충돌하지 않도록 목적별 집필 지침을 선택한다.
- `claim-review.js`: 기존 문장·세부 주장 검토에 점검 목적과 네 판단 연결. 선택 구절만 검토 입력에 제공한다.
- `rules.js`·`editorial.js`·`owned-content.js`: 목적별 평가, 짧은 설명 허용, 불필요한 환산 문단 자동 삽입 방지.
- `prepare-periodic-check-local.mjs`: 공개 자료 입력 JSON으로 준비만 수행. 모델·네트워크 호출 없음.
- `replay-periodic-check-local.mjs`: 저장 칠레 자료와 가정한 전회 기록으로 세 경우 재현. 결과 원고·비용·승인 기록 등록 없음.

입력은 `{ packet, previous, topics, mode }`다. `previous.origin=published_record`와 `status=published`는 호출자가 실제 공개 저장소에서 확인해 제공해야 한다. 해시는 변조·오래된 결합을 검사하며 관리자 인증을 대신하지 않는다. 현재 운영 공개본 조회·전회 항목 자동 추출·스케줄러 연결은 구현 범위 밖이다.

`topics`는 ID·이름·`supports / qualifies`·검토 구절 연결·적합성 검토 기록을 담는다. 의미적 지지·보완 관계는 기존 근거 검토가 제공해야 하며 코드가 스스로 승인하지 않는다. 따라서 지금 자동화된 부분은 **검토된 근거에서 상태·범위·입력·검사를 일관되게 선택하는 과정**이다. 근거의 의미 판단과 원고 내용 승인은 별도다.

```text
npm run report:periodic:prepare -- <공개 자료와 검토 기록을 담은 입력.json>
npm run report:periodic:replay
```

두 명령은 `.env`를 읽지 않고 `.local-reports/private/`의 새 폴더에만 결과를 쓴다. 재생용 가상 전회 기록은 `saved_replay`에서만 허용한다. 재생 패킷으로 실제 생성 함수를 호출하면 전송 전에 중단하며, 기존 유료 사건 시험 도구로 잘못 연결하는 경로도 차단했다. 모델 기본값·운영 스케줄·발행 규칙은 변경하지 않았다. Sol의 기존 슬롯 출력 형식과 호환성을 오프라인에서 확인했다.

출력 조립 검증에는 기존 수동 샘플을 계약에 맞춘 **명시적 시험 응답**을 사용했다. 숫자·자료 부족 문장은 코드 영역으로 옮기고 원본 파일은 보존했다. 새 AI 작성·실제 모델 품질·독립 내용 검토로 집계하지 않는다.

최종 검증 결과와 보존 기록은 후속 실행 상태에 연결한다. 세 경우의 입력·출력·검토 준비 파일은 Git 제외 경로에 보관한다. 운영 DB·메일·배포·원격 push는 실행하지 않았다.
