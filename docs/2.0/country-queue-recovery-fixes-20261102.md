# 조회 상태·통화별 대기열 공통 보완 — 2026-11-02

## 반영 결과

[독립 점검 S1~S3](input-edition-independent-audit-20261102.md)를 공통 실행 경로에서 수정했다. 국가별 승인 예외나 특정 기사의 통과 규칙은 추가하지 않았다.

| 문제 | 공통 처리 | 검증 결과 |
|---|---|---|
| S1: 조회 실패를 원문 변경으로 오인 | 새로 관측한 기사 판본·공식 수치·재검토 필요 기록과, 조회 결과에서 자료가 빠진 상태를 구분 | 6통화×반환형 실패 3종의 18조합에서 기존 작업을 대기시켰다. 복구 후 검토만 1회, 작성 재호출 0 |
| S2: 한 국가 장애가 다른 국가의 새 입력을 막음 | 원래 배치·국가 사건·장부를 유지하며 대기열의 각 작업을 확인한다. 긍정적으로 확인된 새 입력은 반복 운영 정책 범위에서 별도 진행 | PEN 장애 중 COP 새 입력 작성·검토 완료. 이후 PEN 복구 시 원래 검토만 재개. 두 배치 동시 대기에서도 뒤쪽 COP 검토 재개 |
| S3: 실행 요약에서 현재 수집 장애 누락 | 현재 수집 진단을 반환과 최종 저장에 포함하고, 여러 배치의 기술 오류도 결과 분류에 연결 | 전체 조회 실패는 실패/종료코드1, 사용 가능한 자료가 남은 부분 실패는 부분 장애 표시. 기술·비용 오류는 주의/종료코드2 유지 |

완료된 후속 배치의 캐시를 다시 읽을 때도 COP의 완료 상태와 PEN의 현재 대기를 함께 유지한다. 다른 배치의 건너뜀/옛 준비 상태로 현재 대기 상태를 덮어쓰지 않는다.

추가로 현재 기준환율 응답이 불완전한 경우에도 새 가격 판본으로 처리하지 않는다. `frozen_reference_refresh_wait`로 기다렸다가 원래 입력으로 재개한다. 기존 대시보드의 휴일·직전 정상값 처리와 원고에 고정한 기준일을 유지한다.

## 수집 상태와 자료 판본

- 예외가 발생한 수집 실패와 `access_failed`, `extraction_failed`, `discovery_incomplete`를 반환한 실패가 같은 재개 원칙을 따른다.
- 정상 응답의 빈 색인도 기존 기사가 수정·철회됐다는 증거로 보지 않는다.
- 새 기사/실제로 달라진 원문, 채택된 공식 수치·정의·발표 판본, 새 충돌 검토 기록은 새 입력 후보가 될 수 있다. 이것이 내용 품질이나 발행 승인까지 뜻하지는 않는다.
- 같은 자료가 현재 확인돼 있고 일부 다른 조회만 실패했다면, 그 실패를 표시하면서 기존 검토를 진행할 수 있다.
- 이번 변경 전 잘못 종료된 실제 `frozen_country_material_superseded` 사건이 격리 DB에 남아 있는지 확인했고 **0건**이었다. 과거 행을 고치거나 옛 내용 반려를 강제로 재개하지 않았다.

## 대기열과 비용

`operating-cycle.js`는 무료 수집을 한 번 수행한 뒤 원래 대기 배치들을 순서대로 처리한다. 각 통화는 미완료 작업이 속한 원래 배치에 남는다. 다른 국가의 긍정적으로 확인된 새 판본은 기존 반복 운영 승인의 범위에서 진행할 수 있다.

한 실행의 호출 수·확정 비용을 공통으로 누적하므로 배치를 옮겨 상한을 초기화할 수 없다. DB의 월 예산·배치 예산·호출 수·단계별 예약·lease·미확인 비용 차단도 유지된다. 비용이나 전송/저장 결과가 미확인인 경우 다른 배치의 신규 호출도 멈춘다. 자동 재시도·백업·게시를 추가하지 않았다.

일회 시험 정책은 두 번째 배치를 자동으로 만들지 않는다. 새로운 입력에 대한 추가 승인 없이 일회 시험을 반복 운영으로 바꾸지 않는다.

DB의 대기 배치 조회는 한 건에서 최대16건 처리로 확장했다. 17번째 행을 읽으면 초과를 감지해 `operating_queue_capacity_hold`로 알린다. 자료를 조용히 버리지 않는다. 해당 조회용 부분 인덱스를 추가했다. 동일한 service-only 함수·인수·권한을 유지하며 익명/일반 로그인 권한을 열지 않았다.

## 검증

### 자동 검사

- 최종 **167파일 1,229사례 통과**. 새 논리 사례 9개에는 18개 국가/실패 조합, 빈 색인, 불완전한 가격, 부분 장애, 장기 장애, 여러 대기 배치, 미확인 비용, 일회 승인 제한, 현재/과거 오류 구분을 포함한다.
- 테스트 목록 검사: 중복 이름·동일 본문·자명한 단언 탐지 결과 없음. 의미적 중복이 전혀 없거나 실제 원고 품질 표본 1,229건이라는 뜻은 아니다.
- 타입·전체 린트·운영 빌드·앱 리포트 빌드·리포트 전용 빌드·브라우저 번들 경계 검사 통과.
- 첫 전체 실행의 9건은 샌드박스가 장부 시험의 로컬 하드링크를 막아 실패했다. 무결성 처리를 바꾸지 않고 정상 파일 권한으로 다시 실행해 전부 통과했다.
- 리포트 전용 빌드의 기존 `dbClient.ts` 정적/동적 import 혼용 경고는 남아 있다.

### 실제 격리 DB와 저장 어댑터

1. 권한·대기열·동시 lease·미확인 비용·장부 보존 및 기존 재개 **SQL50검사 통과**. 시험 행과 임시 제어 변경은 전부 롤백했다.
2. 통과한 대기열 함수/인덱스 정의만 `supabase_db_latamfx-2x-isolated:56322`에 반영했다. migration 이력 삽입이나 운영 DB 반영은 없다. 기존 행·제어 해시가 같고, 종료 후 `enabled=false`, `review_enabled=false`, 예산0이다.
3. 실제 `createRuntimeStore` 직렬화/복원과 설치된 DB 함수를 연결해 세 가지 통합 시험을 수행했다. 모델과 자료 조회 응답만 합성이다.

| 통합 조합 | 합성 초안 | 모의 모델 단계 합계 | 확인 |
|---|---:|---:|---|
| 반환형 조회 실패 → 복구 | 6 | 24 | 같은 작성 응답 재사용, 남은 검토만 수행 |
| PEN 지속 장애 + COP 새 가격 → PEN 복구 | 6 | 25 | COP 먼저 완료, PEN 원래 검토만 재개 |
| 위 조합에서 COP 새 검토도 대기 → 두 배치 재개 | 6 | 25 | 오래된 PEN 뒤의 COP도 재개 |

통합 시험의 모든 행/제어 쓰기는 롤백했고 전후 해시가 같다. 실제 외부 모델 요청/새 비용/새 뉴스 수집은 **0**이다. SQL 클라이언트를 주입한 시험이며 Supabase HTTP 요청까지 시험한 것으로 표시하지 않는다. UI와 실제 새 원고 내용 품질은 이번 변경의 시험 대상이 아니다.

### 기존 실제 자료

과거 원문 처리 요청21건을 같은 해시로 재현하고 원본 입력4파일 해시 일치를 확인했다. 알려진 MXN 옛 잘못된 성공 결과의 현재 재사용 보류도 유지했다. 기존 원고를 수정하거나 새 모델 품질 합격으로 바꾸지 않았다.
