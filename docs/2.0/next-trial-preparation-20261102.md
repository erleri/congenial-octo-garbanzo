> **우선순위 정정:** BRL·CLP만 유료 집필하는 다음 단계 제안은 철회한다. 아래 준비안은 보존하되 실행하지 않는다. 목표는 6통화 공통 자동화의 중단 지점을 해결하는 것이다. 현재 후보 목록 내 대체 자료 처리는 있지만, 검토 후 확인된 공백을 다음 탐색으로 전달하는 연결, 추출/대조 단계별 재개, 보류 종류별 재개 조건이 충분하지 않다. 먼저 이 흐름을 저장 자료·모의 실행으로 검증하고, 이후 6통화 동일 진입점으로 실제 시험한다. 모든 통화에 원고를 강제로 만드는 것을 합격 조건으로 삼지 않는다. 근거가 없는 경우에도 프로그램이 대체 탐색과 종료·재개 조건을 결정하고 사람의 임시 처방 없이 다음 실행으로 이어져야 한다.

## 이번 작업의 결론

BRL·CLP의 검증된 카드로 집필 입력과 비용 예약안을 준비했다. COP·ARS의 등록된 무료 탐색도 수행했으며, ARS의 새 기사 두 건을 막던 공통 수집기 오류를 고쳤다. **새 원고를 만들거나 6통화의 집필 자격을 모두 승인하지 않았다.**

유료 호출 0, 신규 비용 $0, DB 쓰기·게시·메일·배포 0. 기존 대시보드와 원고, 실제 실행·비용 기록을 유지했다. 새 탐색은 무료 GET 16회이며 이후 수집기 검증은 저장 응답만 사용했다.

## 공통 수집기 수정

JSON-LD의 `articleBody`가 한 줄로 제공되면 기존 수집기는 문단당 8,000자 제한 때문에 본문 전체를 거절했다. 실제 새 두 건은 각각 9,076자·9,792자의 단일 본문이었다. 접근 실패나 원인 기사 부재와 다른 **수집 구현 오류**였다.

- `article-body-limits.js`에 수집·검토 준비의 공통 한도를 두었다: 최대 4,096블록, 직렬화한 블록 전체 UTF-8 200,000바이트.
- JSON-LD 수집의 임의 문단 길이 제한을 없애고 기존 검토 준비의 전체 용량 기준과 일치시켰다. 본문 자르기·요약·임의 분할 없이 기존 블록을 그대로 보존한다.
- 안전 검사는 기존 공통 `unsafeSourceText`를 재사용한다. 접근 차단·메타데이터·출처 처리·내용 대조·요청별 비용 제한도 유지한다.
- 크기가 큰 본문은 수집 가능해도 유료 요청 상한을 넘으면 전송 전에 보류한다. 한도는 무제한 수집이나 출처의 이용 허가를 의미하지 않는다.
- 이번 수정 대상은 공통 JSON-LD 경로다. 예전 선택 구절용 `source-context` 등의 별도 계약을 일괄 완화하지 않았다.

저장 캡처만 재생한 결과 COP 3건은 동일, ARS는 3건에서 5건으로 늘었다. 복구한 본문 전체가 공통 원문 검토 입력 준비까지 통과했다. 그 입력의 상태는 `prepared_not_called`이며 유료 호출·내용 승인·집필 승인은 모두 아니다. 초기 추출 실패 기록과 캡처를 그대로 남겼다.
