# 통화별 대기열 보완 후 최종 독립 점검 — 2026-11-02

## 판정

**유료 6통화 전체 재시험으로 넘어가기 전 두 가지 공통 결함을 보완해야 한다.**

이전 S1~S3의 고정 회귀를 포함한 관련 검사 56건은 통과했다. 그러나 근거 검토의 철회와 준비 조건만의 복구를 결합한 새로운 재현에서 각각 결함을 확인했다. 이번 점검은 현재 에이전트가 기존 합격 결과를 전제하지 않고 수행한 코드·행동 감사이며, 별도 모델이나 외부 검토자의 평가를 뜻하지 않는다.

실제 원고·환율·제품 코드·DB 정의는 수정하지 않았다. 실제 외부 호출과 신규 비용은 0이다.

## F1 — 근거 검토가 철회돼도 대기 중인 원고 검토가 계속된다 (높음)

### 재현

1. 한 통화에서 기사 추출·대조와 집필을 완료하고 원고 검토 직전의 제공 경로 장애를 모의한다.
2. 해당 기사에 대한 기존 검토 기록을 보존하면서, 그 기록을 대체하는 명시적 `withdrawn` 판정을 추가한다.
3. 같은 기사·환율로 재개한다.

새 수집 입력의 캐시는 `source_review_withdrawn`을 정확히 반환한다. 그런데 대기 중 배치는 검토 모델을 1회 모의 호출하고 `pending_admin_review` 초안을 만든다. **실제 자동 게시가 발생한 것은 아니지만, 철회된 근거에 기대는 원고가 정상 승인 대기 경로로 들어간다.**

BRL·MXN·COP·PEN·CLP·ARS 모두 같은 결과였다. COP 사례는 실제 저장 어댑터와 설치된 격리 SQL에서도 재현했다.

### 원인

- `operating-source-cache.js:93`: 철회 상태는 새 `savedSourceReviews`에만 전달된다.
- `operating-refresh.js:20`: 갱신 비교는 기사·환율·공식 수치·일부 재검토 기록을 보지만 현재 근거 검토의 철회 상태를 비교하지 않는다.
- `operating-cycle.js:148`: 재개 시 고정된 옛 `prepared`를 사용한다.
- `runtime-batch.js:74`: 그 옛 입력과 저장 응답을 사용해 검토를 이어간다.

기사 본문이 같다는 사실과 해당 근거가 현재도 사용 가능하다는 판단을 같은 것으로 취급하는 경계다.

### 수정 계약

- 과거 입력·응답·비용은 불변으로 유지한다.
- 재개 전 현재 유효한 근거 검토 상태를 별도로 확인한다. 알려진 철회·충돌·재검토 필요는 옛 성공 캐시로 우회하지 못하게 한다.
- 명시적 철회를 단순 조회 장애와 구별한다. 조회 실패는 원래 작업을 보존하는 대기이며, 철회는 해당 근거를 쓸 수 없다는 명시적 제약이다.
- 철회 후 대체 자료가 준비되면 새 입력 판본으로 평가한다. 기존 원고를 자동 수정하거나 과거 검토 성공으로 복원하지 않는다.
- 근거가 여전히 유효한 정상 재개에서는 작성 재호출 없이 남은 단계만 수행한다.

## F2 — 새 자료 없이 준비 조건만 복구된 국가는 다른 국가의 대기에 계속 묶인다 (높음)

### 재현

1. COP는 수집 완료시각 검증 실패로 준비 보류한다. 기사 본문·환율은 이미 반환된 상태다.
2. PEN은 집필 뒤 원고 검토 대기 상태로 만든다. 나머지 네 통화는 초안 생성한다.
3. COP의 시각 오류를 정상화하고 PEN의 자료 조회 장애는 유지한다.
4. 같은 실행을 세 차례 반복한다.

COP는 현재 준비가 가능해도 옛 `country_preparation_hold`를 계속 반환한다. 새 호출은 0이며 초안은 네 통화에서 더 늘어나지 않는다. 기사나 환율을 바꾸거나 PEN의 대기를 해소하기 전까지 COP가 진행하지 못한다.

복구 대상 통화를 6개 모두로 교체해 재현했다. COP 복구/PEN 장애 조합은 실제 저장 어댑터와 격리 SQL에서도 세 차례 반복 확인했다.

### 원인

- `runtime-batch.js:58`: 고정된 옛 준비 보류가 실행을 계속 차단한다. 옛 입력을 바꾸지 않는 것은 정상이다.
- `operating-cycle.js:106`: 다른 대기가 있는 동안 새 실행을 여는 후보는 `_superseded`만으로 수집한다.
- `operating-cycle.js:112`: 자료 판본이 같고 준비 조건만 복구되면 새로 실행 가능한 국가에 포함되지 않는다.

`freshKey`에는 준비 판정 변화가 포함돼 있지만, 그 입력을 선택하는 분기가 빠져 있다. 기존 준비 복구 검사는 다른 국가가 대기하지 않는 경우만 다뤘다.

### 수정 계약

- 새 작업 선택은 현재 국가별 작성 자격, 미완료 작업의 소유 배치, 기존 처리 기록을 함께 기준으로 삼는다.
- 원래 작업이 있으면 같은 장부에서 재개한다. 유료 작업을 시작하지 못했던 준비 보류가 해소됐다면 새 자료가 없더라도 현재 입력으로 진행할 수 있어야 한다.
- 한 국가의 대기가 다른 국가의 복구를 막지 않게 한다. 반대로 이미 처리한 사건을 준비 복구로 오인해 중복 집필하지 않는다.
- 반복 운영 정책과 일회 시험 승인을 구분한다. 일회 승인을 새 배치 허가로 확장하지 않는다.
- 공통 호출·비용 상한, 미확인 비용 차단, lease와 국가별 중복 방지는 유지한다.
