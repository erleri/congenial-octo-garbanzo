# 공통 입력 판본·국가별 재개 보완 — 2026-11-02

## 반영 결과

[독립 재점검 R1~R3](automation-independent-reaudit-20261102.md)를 로컬 공통 경로에 반영했다. BRL·MXN·COP·PEN·CLP·ARS가 같은 식별·종료·재개 규칙을 사용한다. 특정 국가·가격·기사를 승인하는 예외는 추가하지 않았다.

| 문제 | 변경한 처리 | 확인한 동작 |
|---|---|---|
| R1: 새 기준환율 입력이 옛 집필 작업과 충돌 | 사건과 입력 판본을 구분. 기준환율의 실제 값/정의/공급자 정보와 근거 판본으로 `inputEdition`을 만들고 단계 요청 키에 연결 | 6통화 각각 자기 가격 변경 시 옛 작업만 사유와 함께 종료. 다음 실행에서 새 판본 집필·검토. 재실행 추가 호출 0 |
| R2: 다른 통화 갱신이 대기 작업을 고립 | 전체 배치의 일괄 종료를 공통 실행 경로에서 제거. 원래 배치와 장부를 먼저 재개하고, 해당 통화의 입력이 바뀐 경우에만 그 사건을 종료 | 6통화 각각 다른 통화의 가격 변경에도 원래 검토만 1회. COP·PEN 동시 대기 중 COP 가격/자료 변경 시 PEN은 계속 진행 |
| R3: 저장 완료 후 외부 목록 장애로 마무리 불가 | 현재 권한·요청·확정 비용·모델을 검사한 뒤 동일 저장 응답을 먼저 재사용. 새 전송이 필요할 때 외부 제공 경로 검사 | 실제 저장 완료 뒤 확인 응답 유실+모델 목록 장애 조합에서 같은 run ID/원고/영수증 유지, 추가 모델 전송 0 |
| 추가 발견: 재개 시 동일 집필 입력 재등록 | 실제 DB의 `payload_hash` 유일 제약과 모의 저장소의 차이를 확인. 같은 스냅샷/바인딩의 기존 입력은 검증 후 재사용 | 같은 입력의 등록 RPC는 한 번만 실행. 모의 저장소도 중복 삽입을 거부하도록 개선 |

수집시각만 갱신된 것을 새 기준환율 판본으로 계산하지 않는다. 새 입력이라고 기존 비용·응답·요청을 덮어쓰지 않는다. 집필 모델·프롬프트·날짜를 바꾸는 것만으로 같은 사건을 무제한 재호출할 수 있게 하지 않았다.

## 실행 순서

1. 현재 무료 수집과 제어/예산 확인은 유지한다.
2. 같은 정책의 미완료 배치가 있으면 원래 입력·기준시각·장부를 불러온다.
3. 통화별 입력을 대조한다. 다른 통화만 바뀌었으면 영향을 주지 않는다. 해당 통화의 가격 또는 근거 판본이 바뀌었으면 원래 사건을 `frozen_country_reference_superseded` 또는 `frozen_country_material_superseded`로 마친다.
4. 영향을 받지 않은 대기 작업은 같은 배치에서 완료한다. 변경된 통화의 새 입력은 다음 예정 실행의 대상이며, 그 자리에서 재귀적으로 추가 유료 실행하지 않는다.
5. 새 입력도 기존 정책·발행 자격·미확인 비용·동시 실행·검토 대기 원고·회차/월 예산을 통과해야 한다. 일회 시험의 단일 배치 제한은 유지된다. 종료가 새 시험 예산을 승인하지 않는다.
6. 새 수집이 실패한 통화는 기존 자료가 수정됐다고 추정하지 않는다. `frozen_source_refresh_wait`로 원래 사건을 대기시키고 복구 후 재개한다.

보고서에 고정한 기준일·가격을 새 실행 시각으로 바꾸지 않는다. 이미 저장된 초안을 승인하는 것은 기존 active admin 경로의 별도 행동이다.

## 이전 버전 호환

- 새 식별은 `runtime-input-edition/1`과 `runtime-request-identity/2`다. 공개 `CurrencyReport`와 URL은 바꾸지 않았다.
- 이전 `currency-report-runtime/1`의 저장 입력은 유지한다. 새 식별로 준비한 입력도 같은 런타임 버전/저장 인터페이스를 사용한다.
- 이전 키로 결제된 **정확히 같은 입력**이 있으면 요청 해시와 저장 컨텍스트를 대조해 재사용한다. 이전 응답의 모델·확정 비용·예약 범위·유효 상태를 다시 검사한다.
- 이전 키로 저장된 원고의 식별은 해당 작성 작업의 원래 키를 사용해 유지한다. 저장 확인 응답이 유실돼도 업그레이드 때문에 새 원고로 바뀌지 않는다.
- 다른 가격 판본은 옛 응답을 재사용하지 않는다. 근거 부족/내용 반려/비용 미확인에 대한 기존 보류를 약화하지 않았다.

## 검증

### 공통 경로와 장애 조합

`continuation-recovery.test.ts`의 논리 사례를 확장했다. 국가별 자기 가격/다른 가격의 12조합, 두 통화 동시 대기, 근거 추가, 수집 실패, 저장 확인 응답 유실, 이전 키 응답 재사용을 확인했다. `runtime-supply.test.ts`에는 동일 입력 등록 재사용 검사를 추가했다.

최종 전체 자동 검사 **166파일 1,220사례 통과**. 기존 테스트 목록 검사에서 같은 이름·동일 본문·자명한 단언의 탐지 결과는 없다. 이는 의미적 중복이 전혀 없거나 실제 AI 품질 표본 1,220개라는 뜻이 아니다. 타입·전체 린트·운영 빌드·앱 리포트 빌드·리포트 전용 빌드·브라우저 번들 경계 검사도 통과했다. 기존 `dbClient.ts`의 정적/동적 import 혼용 경고는 남아 있다.

### 실제 격리 DB와 저장 어댑터

- 기존 권한·lease·비용 미확인·장부 보존·최종 저장 검사와 국가별 종료/재개 검사를 합친 **30개 SQL 검사 통과**. 전부 롤백했다.
- 별도 통합 시험에서 `createRuntimeStore`의 실제 JSON 직렬화/복원과 **설치된 DB 함수**를 연결했다. HTTP 서버 대신 트랜잭션 내부 SQL 클라이언트를 주입해 모든 쓰기를 롤백 가능하게 했다. 이 시험을 Supabase HTTP API 시험으로 표시하지 않는다.
- 다른 국가 가격 변경: 첫 실행의 미완료 원고는 검토만 이어서 실행했다. 합성 원고 6개, 전체 입력 등록 RPC 6회, 모의 모델 단계 총24회로 완료했다.
- 두 국가 대기+한 국가 가격 변경: 영향을 받지 않은 검토는 원래 배치에서 마치고 변경된 입력은 다음 배치에서 작성했다. 합성 원고 6개, 입력 판본 7개, 모의 모델 단계 총25회였다.
- 저장 완료 응답 유실+외부 목록 장애: 같은 저장 결과로 마무리했고 총 모의 단계24회에서 늘지 않았다. 입력 등록 RPC도6회였다.
- 실제 외부 모델 호출/비용은 모든 시험에서 **0**. 제어·원고·환율·장부·근거 기록을 포함한 비교 대상 행의 전후 해시가 같았다. 새 DB 함수/마이그레이션 설치와 운영 활성화는 하지 않았다.

통합 시험 도구를 작성하는 동안 UTF-8 청크 처리와 완료 결과의 캐시 형태를 시험 검증부에서 바로잡았다. 해당 중간 시험도 롤백했으며, 최종 통과 결과만 제품 검증 근거로 채택했다.

### 저장 실제 자료

실제 과거 `/3` 요청21건의 재구성과 원본 입력 파일4개의 해시 일치를 다시 확인했다. 알려진 MXN 옛 성공 응답의 현재 자동 재사용 보류도 유지된다. 새 모델이 그 모순을 잡았다는 뜻은 아니다.
