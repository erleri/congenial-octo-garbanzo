# 6통화 공통 자동 처리·재개 보강 — 2026-11-02

## 목표와 완료 범위

BRL·MXN·COP·PEN·CLP·ARS 모두 같은 진입점에서 실패 이유를 판정하고, 다음 탐색 또는 중단 단계 재개로 이어지도록 기존 운영 코드를 보강했다. 두 통화만 유료 집필하는 우회 계획은 실행하지 않았다.

이번 완료 범위는 **공통 실행 코드, 실제 저장 응답 재검증, 합성 6통화 흐름 검증, 격리 DB의 실제 저장 함수 검증**이다. 새 외부 모델 호출·뉴스 조회·실제 원고·운영 배포는 0이다. 실제 모델이 새 지침에 맞게 정확한 설명을 작성하는지까지 합격한 결과는 아니다.

## 연결한 처리

| 상황 | 프로그램의 다음 처리 | 같은 자료의 반복 비용 방지 |
|---|---|---|
| 원인 설명 부족·가격만 있음·기간/귀속 불일치·대조 반려 | 저장된 검토 결과를 다음 탐색에 전달. 이미 부족했던 기사의 우선순위를 낮추고 다른 등록 후보와 공식 등록 색인을 확인 | 동일 원문·동일 기준의 반려는 재사용. 새 자료/수정본/검토 규칙 변화가 있어야 새 판단 가능 |
| 본문 형식·추출 실패 | 접근 실패와 구분해 다른 등록 경로를 진행. 본문 수집 시 형식/크기 오류를 유지해 기록 | 수집 실패를 모델에게 원인 추정 요청으로 바꾸지 않음 |
| 접근/이용 제한 | 기존 허용된 다른 출처로 진행 | paywall·robots·제외된 매체를 우회하지 않음 |
| 제공 경로 사전 검사·실행 시간·승인 예산의 일시 대기 | 사건과 배치를 `paused`로 보존. 다음 실행에서 고정된 입력과 완료된 요청을 조회하여 미완료 단계부터 진행 | 저장된 추출은 실제 요청·모델·응답·비용이 일치해야 재사용. 재사용 자체는 새 호출 수/비용을 소비하지 않음 |
| 비용 미확인·진행 중 요청 | 기존 회계 복구 경로로 전달하고 새 유료 처리를 중단 | 새 사건 ID를 만들어 비용 제한을 우회하지 않음 |
| 원인 미상의 프로그램 오류 | `await_pipeline_repair`와 운영 확인 필요 상태로 보고 | 기사 부족으로 오인해 반복 과금하지 않음 |
| 새 자료/조건 변화 없음 | 현재 결과 유지, 다음 무료 확인을 기다림 | 동일 완료 배치와 사건은 재생성하지 않음 |

수집·내용 검토·집필 자격·게시 승인은 계속 별도 상태다. ‘프로그램이 다음 행동을 결정했다’는 사실이 원문 지지나 집필 합격을 뜻하지 않는다.

## 탐색과 재개의 실제 경계

1. 기존 일정 실행이 시작되면 현재 허용된 출처와 저장 검토 기록을 읽는다.
2. 반려/설명 부족 기록에서 공통 탐색 요구를 만든다. 이미 검토한 URL은 **후순위**로 두되 수정 기사일 가능성을 확인할 수 있도록 완전히 금지하지 않는다.
3. 등록 목록·색인에서 다른 후보를 우선 확보한다. 기존 국가별 요청 수, robots, 출처 등록, 자료 기간 검사를 유지한다. 제목·URL 날짜는 근거 승인으로 쓰지 않는다.
4. 사용 가능성과 비용을 점검한 실제 요청 목록을 고정한다. 그 목록과 예산 안에서만 원문 추출·독립 대조·집필·문장 검토를 실행한다.
5. 검토 후 새로 발견한 공백은 기록해 **다음 예정 실행의 탐색**에 반영한다. 고정된 유료 배치 도중 승인 목록 밖의 기사를 무제한으로 추가 전송하지 않는다.
6. 일시 장애면 원래 고정 배치를 재개한다. 원문·입력·규칙이 달라졌다면 예전 응답을 새 요청의 결과로 바꾸지 않는다.

이번에 연결한 것은 다음 일정 실행까지 이어지는 자동 흐름이다. 한 실행 안에서 모델이 무제한 검색·교정·재시도를 반복하는 기능은 아니다. 새 모델·예산·운영 활성화의 승인 경계도 유지했다.

## 코드 변경

- `research-continuation.js`: 모든 통화가 사용하는 실패 분류, 다음 행동, 재개 조건, 탐색 피드백.
- `operating-cycle.js`·`runtime-supply.js`·`automatic-supply-plan.js`: 저장된 출처 검토를 수집 전에 읽어 탐색에 전달. 일시 대기는 고정 배치/사건을 재개 가능한 상태로 저장.
- `selected-source-collection.js`·`registered-material-adapters.js`: 검토 피드백에 따른 후보 순서와 등록 대체 색인 조회. 기존 수집 예산과 출처 경계 유지.
- `runtime-source-review.js`·`runtime-batch.js`: 실제 결과와 후속 행동을 연결. 모순 근거 반려는 유지하고 다른 후보·다른 통화 처리를 계속함.
- `runtime-source-transport.js`: 완료된 동일 요청 단계는 신규 호출 한도를 사용하지 않고 재사용. 새 전송에만 현재 예산·호출 제한을 적용.
- `operating-source-cache.js`: 일시 장애를 영구 반려로 저장하지 않음. 새 판단은 고유한 불변 기록으로 추가해 과거 반려와 공존. 정상 판단을 우선 재사용. 과거 저장 형식도 읽음.
- `operating-result.js`: 분류되지 않은 프로그램 오류를 운영 확인 필요 상태로 보고.

특정 국가나 기사에 대한 승인 예외는 추가하지 않았다. 국가별 기존 출처·현지 시간대·가격 정의는 그대로 사용한다. 대표 숫자는 기존 대시보드 기준환율이며 휴일 이월 로직도 변경하지 않았다.

## 실제로 검증한 것

### 공통 실행 경로의 합성 검증

- 여섯 통화의 최초 근거를 가격 기준 충돌로 반려 → 새 원고 0.
- 같은 자료로 다시 실행 → 신규 모의 모델 전송 0.
- 다음 수집에서 여섯 통화 모두 반려 기록의 URL을 탐색 피드백으로 받음.
- 다른 근거가 별도 검토를 통과 → 같은 공통 경로로 여섯 검토 대기 초안 생성. 실제 API 호출/비용/게시 0.
- 한 통화의 추출 완료 후 대조 제공 경로 사전 검사 실패 → 해당 사건만 일시 대기, 다른 다섯 통화 계속 처리.
- 같은 배치 재개 → 완료된 추출 재호출 0, 대조·집필·문장 검토만 진행.
- 새 판단 후에도 과거 반려 기록의 해시 유지, 불변 기록 키 중복 0.
- 실제 수집기 모의 HTTP에서 이미 날짜가 맞는 기사라도 검토 피드백이 있으면 등록 대체 색인을 조회하고 다른 기사를 우선 수집. 고정 GET 예산 유지.

이는 프로세스 검증용 합성 사례다. 실제 보고서 품질 표본으로 합산하지 않는다. 기존 비용 미확인·권한/예산/중복 회귀 검사도 유지했다.

### 저장된 실제 기사·응답

실제 기사 21건과 모델 응답 28건을 원래 요청 버전으로 다시 대조했다. 과거 작업/고정 입력/실제 결과/종료 비용 기록 4개의 SHA-256이 같았다. 새로운 지침으로 생성한 결과라고 재표시하지 않았다.

BRL·CLP는 이전의 검증 카드 연결 상태를 유지했다. MXN은 기술적 입력 준비와 기사 내부 가격 모순의 내용상 보류를 구별해야 한다. COP·PEN·ARS의 날짜·독립 대조·원인 설명 공백을 삭제하거나 통계로 대신하지 않았다. 후속 행동을 결정할 수 있게 됐다는 사실만으로 이 통화들을 집필 합격으로 바꾸지 않았다.

이 재생은 외부 호출 없이 실제 저장 결과에서 다음 행동이 산출되는지 확인한 것이다. 공통 지침이 실제 새 모델 응답의 가격 모순을 잡았다는 증명은 아니다.

### 실제 격리 DB

`supabase_db_latamfx-2x-isolated:56322`에만 연결했다. 기존 저장 함수에 6통화의 반려/정상 합성 기록 12개를 같은 트랜잭션에서 저장했다.

- 두 판단이 함께 저장됨.
- 동일 기록 재저장 시 중복 없음.
- 직렬화한 원래 기록의 순서/해시 보존.
- 실제 읽어온 기록으로 정상 판단을 우선 재사용.
- 시험 쓰기 전부 롤백. 기존 원고·리뷰·공개본·출처 기록·실행 제어의 해시 동일.
- 새 DB 객체·권한·migration·실행 활성화 없음.

재현: `node scripts/currency-report/verify-continuation-db-local.mjs`. 고정 컨테이너와 포트를 확인하며 키를 읽거나 모델을 호출하지 않는다.
