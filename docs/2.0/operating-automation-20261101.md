# 반복 승인을 없애기 위한 운영 자동화 보완 / 2026-11-01

## 구분해야 할 두 가지 승인

사용자는 여섯 통화 전체 실행에 총 최대 $7·최대 60회를 승인했다. 그 뒤 OpenRouter 기사 본문 전송 확인에 대해 ‘그냥 승인하는 것이 아니라 자동으로 돌아가도록 조치하는 것이 중요하다’고 지시했다. 이를 지속 운영의 월 예산 승인이나 현재 도구 차단 해제로 해석하지 않았다.

직전 자동 승인 검토는 원문 payload와 OpenRouter라는 구체적 외부 목적지에 대한 명시적 승인 부족을 이유로 실행 코드 추가를 거절했다. 이 대화의 도구 승인 검토는 서비스 코드로 해제할 수 없으며, 다른 경로나 설정값으로 우회하지 않는다. 이번 작업에서는 모델 전송·유료 호출·운영 활성화를 하지 않았다.

실제 서비스는 매 기사마다 대화 승인을 요청하는 방식으로 만들지 않는다. 소유자가 서버의 처리 범위와 운영 예산을 확정한 뒤, 그 범위 안의 새 기사는 동일한 수집·내용 검토·비용·중복 기준으로 처리해야 한다. 기사나 AI 응답이 승인 상태를 바꿀 수 없어야 한다. 게시의 관리자 승인은 생성 실행 권한과 별도로 유지한다.

## 실제 발견한 연결 공백

1. 기존 묶음 실행기는 이미 만들어 둔 수집 자료와 기사별 계획/예산 승인 객체를 받았다. 이를 운영 전체 자동 수집이라고 부를 수 없었다.
2. 현재 GitHub Actions의 새 리포트 작업은 이미 등록된 집필 입력을 읽는다. 자동 수집·원문 검토 공급기를 자체 연결하는 실행 진입점은 아직 없다.
3. 칠레의 기존 출판사 어댑터는 saved 모드를 즉시 건너뛰었다. 저장된 기사 네 건이 있어도 자동 경로에서는 0건이 됐다.
4. 같은 어댑터의 검색 날짜는 보고서 날짜에 묶여 현지 조사 목표 날짜와 다를 수 있었다.
5. 활성 출처 조사 문서의 ‘원문 전체 자동 전송 금지’가 별도로 보강된 원문 검토 계약과 혼동될 수 있었다. 집필에는 카드만, 원문 전송은 별도 승인된 비공개 원문 검토 범위만이라는 역할을 명확히 했다. 출처 등록 자체를 외부 전송 승인으로 만들지 않았다.

`authorizationCandidate.authorized`는 항상 false다. 자동 계획은 외부 전송 승인·지속 예산 승인·서버 실행 권한을 만들어 내지 않는다. 승인된 설정을 실제 실행 권한으로 검증해 전달하는 서버 연결은 다음 구현 범위다. 이 대화의 차단된 호출에 이 후보를 사용하지 않는다.

등록된 매체 안의 새 기사 URL은 코드가 자동으로 처리한다. 새 매체·제외된 매체·다른 모델/제공 경로·처리 범위 변경을 기존 설정으로 자동 허용하지 않는다. 원문 검토 준비, 원문 지지 검토, 집필 자격, 문장 검토, 관리자 게시는 계속 다른 상태다.

## 저장 자료 재생 결과

2026-10-31 대시보드 스냅샷과 실제 수집된 10월30일 조사 자료를, 수동 기사 입력 묶음을 직접 집필에 주입하지 않고 기존 수집 어댑터부터 재생했다. 운영 DB가 아닌 격리 로컬 DB의 발행 이력과 비활성 상태만 읽었다.

| 통화 | 보완 전 자동 수집 | 보완 후 자동 수집 | 원문 검토 요청 준비 |

| BRL | 2 | 2 | 2 |
| MXN | 8 | 8 | 8 |

전체 24건·계산상 최대 $6.988945·최대 60회다. 이는 새 과금이 아니다. 실제 모델 호출 0·지출 $0·새 외부 기사 요청 0·운영/DB 설정 변경 0이다. 기존 원문과 원고를 편집하지 않았다. 여섯 통화의 첫 점검 준비이지 실제 원고 품질 합격이 아니다.

검증은 새로운 등록 URL의 자동 계획, 등록 범위 밖 URL 차단, 미확인 발행 이력, 설정 변경, 초과 호출 보류, 수집 실패 격리, 칠레 저장 어댑터의 실제 재생·판본 충돌·가격 거래일 보존을 확인했다. 전체 타입·lint·154파일 1,126사례·운영 빌드·번들 경계 검사를 통과했다. 이 숫자를 원고 품질 표본 수로 사용하지 않는다.
