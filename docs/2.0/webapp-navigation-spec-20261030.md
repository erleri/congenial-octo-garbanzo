## 후속 사용자 검토 — 대시보드 정보 보존 우선

A/B 대시보드 시안은 기존 실행 버전보다 정보/편의성이 떨어진다는 사용자 평가로 보류했다. 독자 3메뉴·관리자 별도 진입의 구조와 구분한다. **기존 대시보드의 당월 누적 평균·MoM·기준일 값·52주 위치·주목 포인트·출처/자료 상태와 단기/월간 차트·평균선을 유지한다.** 기존 계획 편차도 독립 메뉴 제거를 이유로 삭제하지 않는다. 시안에서 지표의 중심을 일간 값으로 바꾸거나 차트를 전환식으로 숨기는 것을 UI 단순화로 취급하지 않는다. 다음 화면 비교는 기존 대시보드 컴포넌트 사본에서 메뉴/연결/배치의 작은 변화를 보여주는 방식으로 진행한다. 아래 A/B는 제안 이력이며 선택된 기본 배치가 아니다. 상세 검토는 [시안 평가 정정](dashboard-layout-comparison-20261030.md)을 따른다.

## 읽는 순서와 결정 상태

일반 독자는 **대시보드 → 환율 추이 → 환율 리포트**의 세 메뉴를 사용한다. 관리자는 별도 **관리자** 버튼으로 작업 공간에 들어간다. 색상·폰트·대시보드 최종 배치는 이번에 확정하지 않는다.

- 사용자 합의: 일별/월별 통합, 리포트 독립 메뉴 잠정 채택, 관리자 별도 진입, 이용 현황 필요.
- 이번 설계 기본안: 계획 대비 독립 메뉴 제거, 기능은 아래 목적별 위치로 이전. 사용자에게 상세 선택을 반복 요청하지 않고 다음 샘플의 기준으로 사용한다.
- 아직 미결정: 대시보드 A/B 구성과 계획 편차 노출 정도, 리포트 상세 탐색 배치, 분석 도구·보존 기간·실제 비용/이용 조건. 합의한 것처럼 처리하지 않는다.
- 기존 앱·그림을 바꾼 결과가 아니라 구현에 사용할 기준안이다. 기존 FigJam C1~C5/F는 현재 구조의 기록이며 다음 시안에서 이 문서와 대응한다.

## 1. 전체 구조

```text
LATAM FX
├─ 대시보드: 지금의 숫자와 여러 통화의 흐름
│  ├─ 추이 보기 → 선택 통화의 환율 추이
│  └─ 해석 읽기 → 해당 통화의 최신 유효 공개 리포트
├─ 환율 추이: 통화·기간 선택 → 일별/월별 → 차트/표
│  └─ 상세 비교: 기존 이동·선행 평균과 계획 대비 조회
├─ 환율 리포트: 6통화 목록 → 상세 → 근거·과거 이력
└─ 관리자 버튼 → 로그인·권한 확인 → 관리 작업 공간
   ├─ 관리 홈: 검토 대기·연결 오류·미확인 비용 등 필요한 일
   ├─ 리포트 관리: 검토·승인·반려·정정·철회·이력
   ├─ 데이터·API: 공급자·용도·자료 기준일·마지막 성공/실패
   ├─ 계획환율: 수정·저장·변경 이력
   ├─ 이용 현황: 화면·통화·리포트 이용 집계
   └─ 운영 기록·고급: 실행·비용·기존 메일 설정·비상 Excel·복구
```

이 구조는 기능의 소속이며 관리자 상위 탭을 모두 가로로 늘어놓으라는 뜻이 아니다. 관리자 화면은 내부 목록 탐색으로 구성한다. 일반 화면은 로그인 없이 읽고, 관리자 버튼을 누르면 비로그인 상태에서는 로그인만 보여준다. 로그인했더라도 active admin이 아니면 비공개 자료를 조회하지 않는다. 버튼 숨김을 권한 검사로 대신하지 않는다.

## 2. 기존 기능의 목적지

| 현재 항목 | UI2.0 위치 | 보존/정리 기준 |
|---|---|---|
| 대시보드 USD/KRW·6통화 기준환율 | 대시보드 | 단위·가격 정의·기준일 유지 |
| MoM·52주 위치·30일/월간 차트 | 대시보드 샘플 + 환율 추이 | 기능 삭제 없이 대시보드 노출 깊이 비교 |
| 월별 이력, Local per USD·KRW 환산표 | 환율 추이의 월별/표 | 기존 조회 통화·기간·단위·자료 범위를 축소하지 않음 |
| 일별 차트·표·보간/결측 안내 | 환율 추이의 일별 | 결측을 0이나 변화 없음으로 표시하지 않음 |
| 계획 대비의 이동·선행 평균·실제·계획 편차 | 환율 추이의 접힌 상세 비교 | 독립 상위 메뉴만 제거. 산식·기간·조회 권한 보존 |
| 계획환율 수정·변경 이력 | 관리자 > 계획환율 | 동일 편집 기능 한 벌만 유지 |
| 기존/로컬 리포트 목록·A안 | 환율 리포트 | 통화·날짜·실행별 기존 URL과 과거 판본 보존 |
| 기존 Admin과 로컬 API/원고 검토 분기 | 관리자 작업 공간 | 어느 한쪽만 남겨 기존 기능을 잃지 않도록 통합 |
| 메일링·원본 자료·비상 Excel | 관리자 > 운영 기록·고급 | 기존 기능/권한 유지. 메일 내용 변경·Excel 시험은 이번 범위 아님 |
| 이용 현황 | 관리자 > 이용 현황 | 새 설계. 아직 수집기/DB/외부 도구 미연결 |

리포트 범위 BRL·MXN·CLP·COP·PEN·ARS와 기존 환율표가 지원하는 더 넓은 통화 범위를 혼동하지 않는다. 계획 편차는 대시보드에 반드시 크게 표시하지 않는다. 샘플에서 최소 표시/펼침을 비교한다.

## 3. 독자 동선과 이동 규칙

| 시작 | 행동 | 도착·유지할 맥락 |
|---|---|---|
| 대시보드 통화 카드 | 추이 보기 | 선택 통화의 추이, 기본 기간 명시 |
| 대시보드 통화 카드 | 해석 읽기 | 최신 유효 공개본, 현재 숫자와 다른 리포트 기준일 표시 |
| 환율 추이 | 일별/월별·차트/표 전환 | 통화·단위·선택 기간 유지. 범위 지원이 다르면 조정 사실 안내 |
| 환율 추이 | 관련 리포트 | 해당 통화 목록/기간에 맞는 공개본. 기간 내 보고서 없음을 다른 날짜로 숨기지 않음 |
| 리포트 목록 | 통화/날짜 선택 | 선택한 고정 판본. 내용·수치·차트를 최신값으로 덮어쓰지 않음 |
| 리포트 상세 | 이전/다음·이력·다른 통화 | 이전/다음은 같은 통화의 공개 발행일. 다른 통화는 최신본으로 이동하고 날짜 명시 |
| 리포트 상세 | 현재 환율 보기 | 해당 통화의 현재 추이. 과거 리포트의 숫자는 유지 |
| 리포트 상세 | 근거·공유·인쇄 | 출처 펼침, 해당 판본의 안전한 공개 URL, 인쇄 |
| 어느 화면 | 뒤로가기·새로고침·직접 링크 | 실제 선택 화면 재현. 이동 때마다 통화를 재선택하지 않음 |

직접 URL에 원문·인증 토큰·관리자 정보·비공개 실행 ID를 새로 넣지 않는다. 현재 run 매개변수는 호환성을 보존하되 승인된 공개 판본만 해석하고, 공유 링크의 공개 식별자는 상세 설계에서 확정한다. 오래된 리포트에 도착하면 원래 날짜와 최신 공개본으로 가는 길을 제공한다.

기존 월별/일별 화면은 React 상태 기반이므로 이미 영구 URL이 있는 것처럼 간주하지 않는다. 새 환율 추이 URL 계약과 브라우저 이동을 구현할 때 정한다. 기존 #report·통화/날짜 URL·#mailing 접근은 깨뜨리지 않는다. 비관리자 메일 구독 동선이 있다면 관리 내부로 숨기지 않고 기존 접근 권한대로 보존한다.

## 4. 리포트 상태와 관리자 접근

세부 판정은 [S01~S16 공통 상태표](report-state-actions-20261030.md)를 그대로 사용한다.

| 상황 | 독자에게 보일 것 | 관리자 행동 |
|---|---|---|
| 아직 공개본 없음 | 미발행 안내 + 환율 추이 이동 | 조사/검토 상태 확인 |
| 새 근거 부족·검토 대기 | 기존 유효 공개본과 원래 날짜, 공개 가능한 확인 상태 | 부족 이유/초안은 관리에서만 조회 |
| 최신 내용 변화 없음 | 기존 공개본 유지, 실제 점검을 한 경우에만 점검일 | 발행 후보와 게시를 구분 |
| 철회·잘못된 날짜/주소 | 서로 다른 안내. 철회 원문 숨김, 안전한 정정/목록 링크 | 사유·감사 기록 보존 |
| 조회 실패 + 캐시 | 마지막 공개본·캐시·게시 상태 마지막 확인 시각 | 초안을 대체 공개하지 않음 |
| 조회 실패 + 캐시 없음 | 조회 실패·재시도 | 미발행으로 잘못 표시하지 않음 |
| 로그아웃·권한 해제 | 공개 페이지는 계속 이용 가능 | 비공개 초안/원문/검토 상태 제거 |

U01 미발행/철회/없는 주소 구분, U02 복구 후 오래된 연결 오류 제거, U03 조사 상태, U04 정정·이력, U05 관리/운영 연결, U06 상단 줄바꿈을 UI 구현 필수 목록에 포함한다. 상태 전달 경로가 아직 없으면 화면 문구만으로 구현 완료라고 하지 않는다.

## 5. 이용 현황: 적게 모으고 필요한 질문에 답하기

### 초기 범위

관리자는 기간별 페이지 조회, 통화별 조회, 리포트별 열람·읽기 지표, 진입 경로를 본다. 개인을 추적하거나 회사/방문자의 신원을 추정하지 않는다. 만족도·매출 효과를 조회 수로 단정하지 않는다.

| 이벤트 | 전송할 최소 항목 | 집계 목적 |
|---|---|---|
| page_view | 정해진 화면 이름, 선택 통화(있을 때), 공개/빈 화면/오류 상태 | 화면 이용. 리포트 정상 열람과 오류 진입 분리 |
| currency_select | 화면, 통화 | 관심 통화; 단순 선택을 보고서 열람으로 세지 않음 |
| report_open | 공개 보고서 ID·버전·통화·기준일, 허용된 진입 경로 | 실제 공개 본문 표시 성공 뒤만 열람 기록 |
| report_engagement | 공개 보고서 ID, 활성 체류 구간, 본문 도달 구간 | 화면이 보이고 활성화된 동안만 측정. 읽기 확정/내용 이해 점수 아님 |
| evidence_expand / history_open | 공개 보고서 ID, 행동 종류 | 근거/과거 보고서 이용 |
| share / print | 공개 보고서 ID, 버튼 동작 | 공유 버튼 클릭/인쇄 요청일 뿐 전달·인쇄 완료로 표시하지 않음 |

이벤트는 허용 목록으로 생성한다. 전체 URL·query/hash·외부 referrer·기사 제목/본문·검색어·토큰·이메일·관리자 계정·초안 ID·비용/사유는 보내지 않는다. 진입 경로는 dashboard/trends/report_list/history/direct_or_unknown 같은 열거형을 사용한다. 향후 이메일은 별도 캠페인 표식으로만 추가 검토하며 수신자별 식별자는 넣지 않는다.

- SPA 화면 전환을 직접 기록하고 React 재렌더, 상태 polling, 탭 새로 노출만으로 page_view/report_open을 중복 발생시키지 않는다. 의도한 새 방문은 별도 조회이며 방문자 수와 다르다.
- 같은 화면 인스턴스의 반복 전송은 이벤트 ID로 멱등 처리한다. 브라우저 탭 내 임시 메모리 상태로 중복을 줄이고 전역 사용자 ID는 만들지 않는다.
- 초기에는 정확한 순 방문자·재방문자·기기 간 사용자 추적을 제공하지 않는다. 활성 시간 구간 경계는 측정 계약 단계에서 정하고 지금 임의 수치를 합격 기준으로 삼지 않는다.
- 로컬/프리뷰/합성 원고/관리자 시험을 독자 집계에서 제외. 관리자 로그인 기간은 공용 통계 수집을 중지하고 로그인 전 행동까지 완벽히 구분했다고 주장하지 않는다.
- 측정 실패/차단은 앱·환율·리포트 조회를 막지 않는다. 자동 수집 유실이 있으므로 전체 독자의 완전한 전수 통계로 표시하지 않는다.
- 대시보드의 리포트 노출 수를 기록하지 않는 초기 범위에서는 클릭률을 만들지 않는다. 진입 경로별 열람 수만 표시한다. 전환율/클릭률은 분모 이벤트와 중복 기준을 정한 뒤 추가한다.
- 제3자 도구가 IP/브라우저 정보를 수신할 수 있으므로 ‘이름을 안 받으면 개인정보가 전혀 없다’고 단정하지 않는다. 도구·보존·지역·동의/고지 필요성·비용을 다음 연결 설계에서 확인한다. 아직 외부 분석 서비스·스크립트·쿠키를 추가하지 않는다.
- 리포트 제작/원문/비용 장부와 이용 이벤트의 저장을 분리한다. 원시 이벤트를 무기한 적재하지 않으며 집계·삭제·월 한도는 기존 데이터 수명 정책과 맞춘 뒤 적용한다. 이번 문서는 보존 기간이나 외부 서비스 구매 승인이 아니다.

### 이용 현황 화면 초안

첫 화면은 기간 선택 + 많이 본 화면/통화 + 최근 공개 리포트별 열람/읽기 지표 + 경로별 열람으로 제한한다. 상세 이벤트 로그는 기본 화면에 넣지 않는다. 데이터 없음을 0명 이용으로 단정하지 않고 수집 미연결/수집 장애/실제 0건을 구분한다.

## 6. 대시보드와 모바일: 다음 샘플에 넘길 조건

- 샘플 A: 6통화 카드에 숫자·작은 추이·리포트 연결. 샘플 B: 6통화 요약 + 선택 통화 큰 추이.
- 두 샘플은 같은 저장 자료/동일 기간/같은 리포트로 비교한다. 숫자만 남기고 흐름을 없애지 않는다.
- USD/KRW·단위·변화 기간·강약 방향·자료 기준일을 유지한다. MoM과 전일 변화를 이름 없이 혼용하지 않는다.
- 계획 편차는 작게/펼침으로 비교하고 필수 큰 카드로 확정하지 않는다.
- 모바일 390px에서 읽기/선택/뒤로가기 가능, 가로 스크롤 강요와 가려진 버튼 방지. 하단 3메뉴는 시안 기본안이며 최종 배치는 샘플에서 확인한다.
- 관리자 버튼은 독자 탐색과 분리. 로그인/로그아웃 및 권한 상태가 명확해야 한다.
- 색·고급스러운 톤은 구조 선택 뒤 별도 검토. 기존 A안 리포트를 디자인 실험 때문에 새 원고로 만들지 않는다.

## 7. 이후 순서와 완료 조건

1. 이번 메뉴·기능·이용 현황 문서를 설계 기준으로 저장 — 완료.
2. 동일 자료의 PC/모바일 대시보드 A/B 샘플과 통합 메뉴 동선 제시 — 다음 작업. 설계 판단 Astra High, 클릭 시안 구현 Sol High.
3. 선택 후 환율 추이/리포트 이력/관리 상세와 측정 계약·도구를 묶어 설계. 색·글꼴 검토를 이어간다.
4. 선택된 UI를 로컬 구현하고 상태·권한·회귀·이벤트 중복/누락·수집 실패 격리를 확인한다.
5. 이메일 제공 방식은 웹 구조 뒤 별도 검토. 출시/파일럿/운영 승인 조건은 기존 계획 유지.

이번 완료는 문서화다. 제품 코드/환율/원고/DB/워크플로/메일/외부 분석 수집/유료 모델 호출은 변경하지 않는다. FigJam 기존 지도를 개정했다고 보고하지 않는다.
