# 3번 — 자동 자료 공급 연결과 실제 6통화 점검

> 후속 상태: [공통 자료 처리 기준](material-processing-20261101.md)을 구현했다. 아래24건 전부의 매체 정책 미등록/미확정은 당시 상태다. 같은 저장 자료의 최신 결과는 검토 요청 준비3·문맥17·게시정보2·이용범위2이며, 실제 AI 검토/집필 통과는 아직 아니다. 원문 전체 경로와 제한 문맥/자체 카드 경로를 구분한다.

사용자 요청: 3번을 마감하고 실제 자동 리포트 생성·로컬 승인·공개 조회 후 이메일로 진행한다. **실제 생성/승인까지는 아직 도달하지 않았다.** 이번 작업에서 발견한 미완료 조건을 아래처럼 구분한다. 새 리포트를 생성했다고 표시하거나 과거 원고로 대신 승인하지 않았다.

## 실제 확인한 상태

- 운영 대시보드의 공개 `https://latamforex.netlify.app/data.json`을 읽기 전용으로 확보했다. 기준일은 **2026-10-31**이다. 기존 로컬 `data/fx-full-history.json`의 2026-09-12 값과 섞지 않고 별도 비공개 사본으로 보존했다. 운영 자료는 쓰지 않았다.
- 등록된 국가별 무료 출처 전체를 기존 질문 계획·수집기로 처리했다. 59회 제한된 HTTP 조회에서 기사 후보 24건을 확보했다. BRL2·MXN8·CLP4·COP3·PEN3·ARS4건이다. 실제 시장 설명에 채택된 수가 아니라 수집된 원문 후보 수다.
- 조사 목표는 10월30일이다. 이는 기준일 직전 평일의 **검색 목표**이며 휴일·거래일이나 기사의 사건일을 확정한 값이 아니다. 기사별 실제 날짜·가격 종류는 별도 검토 대상이다.
- 확보한 원문으로 외부 요청 없는 저장 재생도 수행했다. 6통화 모두 새 시장 설명 입력을 준비하지 못한 상태가 재현됐다.
- 가장 앞선 공백은 원문 외부 처리 정책의 미등록/미확정이다. 24건을 사용 금지라고 법적으로 판정했다는 의미가 아니다. 기존 ‘자체 작성 사실·견해 카드’의 사용 판단을 ‘새 기사 원문 전체 전송’에 자동 상속하지 않았다. 일부 후보는 발표 메타데이터도 부족하다.
- 실제 유료 호출0·신규 지출$0·새 실제 원고0·실제 승인0·메일 변경/발송0. 기존 원고·환율·공개 이력을 보존했다.

## 구현한 공통 연결

`runtime-supply.js`가 같은 기준환율과 기존 발행 판정을 먼저 확인한다. 조사할 조건이면 국가별 전체 활성 출처를 기존 수집기로 연결한다. 출처를 임의로 한 신문에 고정하지 않는다. 배제된 출처는 이유를 유지한다.

원문 수집 → 별도 추출/대조 → 독립 작성 노트 → 노트 사용 정책 → 실제 기간·역할 연결 → 공통 집필 입력 → 비공개 저장을 연결했다. 수동 검토 결과를 매번 사람이 만들어 넣는 것을 운영 절차로 채택하지 않는다.

- `runtime-source-review.js`: 기존 원문 대조 계약을 호출한다. 없는 자동 검토/정책을 사람의 수동 작업으로 대체하지 않고 대기 상태로 돌려준다. 저장 판단은 같은 원문·카드에만 재사용한다.
- `runtime-note-material.js`: 원문 검토가 끝난 요지를 명시적 노트 사용 정책과 연결한다. 원문 이용 범위와 노트의 외부/공개 범위를 구분한다. 전문가 귀속·일반 달러 맥락·현지 통화 연결을 분리한다. 원리나 출처 허가를 모델이 스스로 승인하지 않는다.
- `runtime-source-transport.js`: 원문 추출과 대조 비용도 기존 비공개 DB 예약·월 한도·응답 저장에 연결한다. 기존 writer/reviewer 두 저장 단계를 사용하되 context의 purpose=original_source_review로 원고 집필과 구분한다. 원문 요청 본문은 DB에 복제하지 않는다. 실제 응답·비용은 비공개로 보존한다. 새 승인 범위·출처 정책이 없으면 전송하지 않는다.
- `runtime-supply-local.js`: 6통화를 순서대로 처리하고 각 결과를 저장한다. 저장/실제 수집을 구분하며 이 명령의 기본 연결은 유료 전송을 제공하지 않는다. 실험용 입력의 수동 등록 명령을 완전 자동 서비스라고 부르지 않는다.
- `runtime-worker.js`: 입력 공급 콜백을 연결할 수 있게 하고 새 한국 날짜에는 오래된 입력을 다시 확인한다. 메모리 결과를 곧바로 믿지 않고 영속 저장소에서 다시 읽는다. **현재 workflow CLI에 국가별 실시간 공급·유료 원문 검토를 기본 활성화한 것은 아니다.**

새 원문을 자동으로 검토하는 두 단계와 그 결과가 실제 집필 요청으로 이어지는 것은 합성 대역으로 통과했다. 이는 실제 원문 사용 조건이나 실제 모델 품질의 합격이 아니다.

## 날짜·보관 보완

주말·휴일에 별도로 확인된 예상 기준일을 공통 가격 검사와 집필기가 다르게 처리하던 문제를 보완했다. 확인된 달력이 해당 저장 기준일을 예상하는 경우에만 단순 경과일 보류를 해제한다. 중복·결측·보간·공급자 오류는 해제하지 않는다. 달력이 없으면 계속 보류한다.

수집 시작 뒤에 가져온 자료가 모두 ‘미래 자료’가 되지 않도록 분석 마감시각만 수집 완료시각으로 이동한다. 기사 게시·수정·사건·환율 관측시각을 완료시각으로 채우지 않는다.

이전 거래일의 시장 설명은 새 날짜로 바꾸지 않는다. 이전 묶음은 보존하고 현재 입력에서는 보관 참조로만 남겨, 오래된 자료가 현재 8개 출처 한도를 계속 차지하지 않게 했다. 월간 소비 배경은 실제 대상 기간을 유지한다.

## 공개 승인 경계

공통 집필 입력이 공개 사용 판단을 잃어버리는 공백도 발견했다. 새 실행은 sourceUseReview의 외부 모델/공개 상태를 별도로 저장한다. 내용 점수가 통과해도 공개 사용이 미확정이면 UI에서 승인 보류 사유를 표시한다.

공식 CLI로 만든 `20261031154346_currency_runtime_public_use_guard.sql`을 **격리 로컬 DB에만** 적용했다. 새 runtime 원고의 공개 복사 시 sourceUseReview.publicDisplay=pass를 요구한다. 과거 승인 기록을 재평가하거나 철회하지 않는다. 운영 DB/migration 이력은 변경하지 않았다.

## 남은 순서 — 같은 3번 안에서 마감할 항목

1. 새 기사에 대한 자동 카드화의 처리 범위를 실제 사용 형태에 맞춰 확정한다. **원문 전체 전송·제한된 원문 맥락 분석·자체 사실/견해 노트는 서로 다르다.** 현재의 pending이 법적 금지인지, 정책 미등록인지, 지나치게 넓은 전송 설계 때문인지 구분한다. robots/무료 접근만으로 허가를 만들거나, 정책이 없다는 이유만으로 모든 분석이 금지라고 단정하지 않는다.
   정기 점검도 기존 별도 비교/노트 사용 입력을 새 공급 경로에 연결해야 한다. 새 공통 경로의 정기 입력은 현재 외부 사용 미검증으로 보류하며, 검증되지 않은 상태를 pass로 만들거나 누적 변동 보고서로 대체하지 않는다.
2. 그 범위가 준비된 출처·입력 한 건을 대상으로 추출/대조·집필·최종 검토의 전체 비용 상한을 계산한다. 같은 카드 집필을 반복한 것을 새 원문 자동 검토로 보고하지 않는다. 예산은 기존 합의대로 신규 범위를 확인한 뒤 승인받는다.
3. 실제 자동 생성 → 근거/품질 확인 → 격리 로컬 승인·익명 조회를 수행한다. 실패 원고는 보존하며 승인하지 않는다.
4. 이 검증 후 이메일의 새 리포트 있는 날/없는 날 구성을 진행한다. 현재 이메일 단계로 넘어갔다고 처리하지 않는다.

현재 사용자에게 새 토큰 발급이나 유료 뉴스 구독을 요구할 단계는 아니다. 남은 것은 위 처리 범위와 실전 자동 입력 검증이며, 프로그램 연결 통과와 구분해 마감해야 한다.
