수동 교정·재시도·백업·새 승인 없이 추가 호출을 하지 않았다. 기존 원고·원응답·비용 장부·운영을 보존했다. 격리 DB는 종료 후 `enabled=false`, `review_enabled=false`, `monthly_limit_nano=0`이며 기존 공개 원고 해시도 같다.

## 차단 이유: 자료 부족과 처리 계약을 구분

### 1. BRL: 날짜 표현과 파서의 충돌

Agência Brasil 기사에서 모델은 `eventDate=2026-10-30`, `basis=explicit`, 인용 `Nesta sexta-feira (30)`를 반환했다. `news-event-date.js`의 explicit 검사는 ISO/일·월·연도 또는 일·월 형식을 요구하므로 `explicit_event_date_not_supported`를 반환했다. 같은 구절에는 상대 요일 표현과 일 숫자가 함께 있다.

따라서 이것을 “기사에 날짜도 원인 설명도 없다”로 설명하면 틀리다. **실제 기사 표현·모델의 날짜 분류·파서 계약이 맞지 않은 사례**다. 원문에 명시된 표현과 발행 현지 날짜/요일의 일치 여부를 검증하는 공통 호환 규칙이 필요한지 저장 응답으로 평가해야 한다. 파서 실패를 피하려고 모델 원응답의 basis/date를 손으로 바꾸지 않았다.

### 2. CLP: 내용 지지와 참조 번호의 계약 차이

Emol 기사에서 추출한 시장 설명을 대조 모델은 모두 supported로 반환했다. 그러나 추출 n2/n3는 귀속 문맥까지 `[2,3]`을 참조했고, 대조는 `[3]`만 반환했다. `original-news-pipeline.js`는 후보가 사용한 문단을 대조 결과에서도 모두 참조하도록 요구하므로 `comparison_dropped_candidate_context`로 차단했다.

**이 사례 역시 원인 기사가 없어서 막힌 것이 아니다.** 실제 해석 내용의 지지 여부와 문맥 참조의 보존 방식을 함께 검토해야 한다. 발언자 소개·조건 문단을 보존하는 안전 요구는 유지하면서, 필요한 문맥을 잃지 않은 정상 축약까지 과도하게 막는지 저장 원문/응답으로 판단해야 한다. 이번에는 문단 번호나 원고를 수정하지 않았다.

### 3. MXN·COP·PEN·ARS: 내용·탐색·출력 형식이 혼재

- **MXN:** 11월 1일 아시아시장 개장 가격 자료는 `price_only`로 대조 통과했다. 다른 후보에는 10월 21/27일 등 조사 구간 밖 자료, 사건일 미확인, 무관 기사, 보류 판정인데 주장을 함께 반환한 출력(`held_extraction_has_claims`)이 있었다. 모든 반려를 실제 뉴스 부재로 합치지 않는다.
- **COP:** 기존 두 기사에 대한 `invalid_original_comparison` 보류는 재호출하지 않고 보존했다. 신규 처리 한 건은 `event_date_unverified`였다. 이번에 유효한 세션 원인 설명을 확보하지 못했다.
- **PEN:** RPP의 10월 29/30일 가격 관측은 각각 대조를 통과했지만 `price_only`였다. El Comercio 후보는 정보 부족이었다. 가격 숫자만으로 환율이 움직인 이유를 만들지 않은 보류는 유지해야 한다.
- **ARS:** 5개 전송 후보에는 실질환율/월간 성과의 배경, FX 사건일 미확인, 정보 부족, 무관 스포츠 기사도 있었다. 긴 기사 1건의 요청 한도 초과도 별도로 기록했다. 무관 범주·확인 가능한 오래된 발행 자료는 가능한 한 무료 탐색 단계에서 선별해야 한다. 새 날짜의 일별 FX 원인을 억지로 채우지 않는다.

종료 후 유효 판정 이력을 읽었을 때 CLP/COP/PEN 일부 같은 원문 판본에 다중 판정 충돌도 확인됐다. 이는 이번 국가별 결과의 직접 차단 이유와 구분해 `source-states.json`에 남겼다. 최신 판정을 임의로 우선시키거나 과거 기록을 삭제하지 않았다.

## 종료 저장 오류

최종 상태는 `operating_execution_hold`, 이유는 `runtime_store_checkpoint_currency_report_operating_batch_failed`였다. 설치된 DB 함수는 체크포인트 JSONB의 문자열 크기를 **64,000바이트**로 제한한다.

국가별 결과는 이미 `currency_report_operating_cases.result`에 저장돼 있다. 이 6개 원기록과 당시 수집 진단, 공통 실행 결과 형식으로 종료 입력을 별도 재구성해 읽기 전용 SQL로 측정하면 **97,942바이트**다. 수집 진단만 JavaScript 직렬화 기준 56,400바이트이며, 국가별 결과까지 합쳐 한도를 초과한다. 원본 함수의 해당 입력 크기 거절 조건을 확인했다.

이 재구성 자료는 원래 실패 결과를 덮어쓴 것이 아니다. 원래 최종 파일은 오류와 null 호출/비용을 그대로 보존했다. **실제 호출 24회·비용 $0.2511376·미확인 0은 별도의 원장과 국가별 원기록으로 확정**했다. null을 미확인 과금으로 잘못 설명하지 않는다.

보완 방향은 진단을 지우거나 DB 한도를 무작정 높이는 것이 아니다. 원문/세부 진단의 기존 비공개 저장을 보존하면서, 배치 종료 기록에는 제한된 요약과 국가별 기록 참조를 저장해야 한다. 실제 다수 출처·중복 상태를 포함한 자료 크기로 검증해야 한다.

## 이번 결과가 뜻하는 것과 다음 작업

앞선 1,240검사는 재개·중복·예산·유효성 경계를 확인했지만, 이번 실제 원문 표현과 다수 진단을 합친 종료 기록의 크기까지 충분히 검증한 것은 아니었다. **집필 호출 자체가 0이므로 이번 결과만으로 GPT Sol의 집필 실력이 부족하다고 결론 내릴 수 없다.**

다음에는 추가 유료 호출부터 반복하지 않는다. 이번에 저장된 실제 원문·24응답으로 다음 한 묶음을 검증한다.

1. 종료 기록을 bounded summary/원기록 참조로 연결하고 실제 결과 64KB 경계를 검증한다.
2. 날짜 분류·인용 문맥·대조 참조 보존의 공통 계약에서 정상 자료의 과잉 차단과 실제 근거 부족을 구분한다.
3. 기간 밖·비경제 분야 자료의 무료 단계 선별과 보류 사유 전달을 확인한다.

BRL/CLP 원고를 사람이 고쳐 채우거나, 새 원고 6건을 확보한 것처럼 표시하지 않는다. 저장 응답으로 수정 타당성을 확인한 뒤 실제 모델 시험 여부/범위를 다시 결정한다.
