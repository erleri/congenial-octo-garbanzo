## 대시보드에서 보존한 정보

`Dashboard.tsx` 자체는 변경하지 않았다. 기존 카드의 당월 누적 평균·MoM·기준일 값·52주 범위, Anchor·Focus, 30일/24개월 두 차트 묶음을 유지했다. 기존 통화 순서 BRL/MXN/CLP/COP/ARS/PEN도 같다.

브라우저에서 새 이동 링크를 제외한 **6카드 본문, Anchor, Focus, 두 차트 제목이 기준 화면과 정확히 같음**을 확인했다. 같은 원본/산식과 기존 컴포넌트를 사용한다. 캡처에서 PC6열을 유지하고 상단 메뉴/갱신 버튼의 과도한 줄바꿈을 정리했다.

## 이동과 필터

- 카드의 `CLP 추이 보기`는 CLP 일별로 이동한다. 환율 추이 내부에서 일별·월별·상세 비교를 선택한다.
- 개별 통화 변경은 두 조회에 공유하고, 월별 ALL은 별도 기억한다. ALL에서 일별로 갈 때 마지막 개별 CLP 복원, 다시 월별로 가면 ALL 복원을 실제 확인했다.
- 월 범위와 연도 범위는 독립적으로 유지한다. 월별은 연도 단위라는 안내를 표시한다. 주소가 자료 범위를 벗어나면 가능한 범위로 정규화하며 조정 안내를 제공한다.
- 주소 예: `#trends?view=daily&currency=CLP&monthly=CLP&from=2026-08&to=2026-09&yearFrom=2025&yearTo=2026`. `#report`·통화/날짜/공개 run·`#mailing`은 보존한다.
- 리포트 왕복은 검증된 내부 추이 주소만 브라우저 이력 상태로 기억한다. 리포트 새로고침 후에도 CLP/월 범위로 복귀했다. 공유 주소에 계정·토큰·초안·원문을 추가하지 않는다.
- ALL 조회는 전체 리포트 목록으로 안내하고, 특정 통화의 보고서를 전체 통화 설명처럼 붙이지 않는다.

## 공개 시각과 새 배지

공개 목록에 기존 공개 테이블의 `published_at`만 추가 조회했다. DB 구조·게시 시각·원고·승인 기록을 바꾸지 않았다. 같은 제한된 공개 필드 투영에 과거 검토 표시와 명시적 정정 분류(있을 때만)를 추가했다.

- 당일 여부는 실제 공개 timestamp를 한국 날짜로 변환해 계산한다. 보고서 기준일, 기사 발표일, 원고 생성일로 대체하지 않는다.
- 승인 공개본·최신 확인 상태만 새 배지 대상이다. 날짜 미제공/날짜만 있음/미래 공개시각·초안·반려·합성·과거 검토본·편집 사본은 새 배지에서 제외한다.
- 명시적 공개 `revisionKind=correction`이 있을 때 ‘정정’으로 구분한다. 현재 정정 메타데이터를 승인 RPC에 새로 저장하는 경로는 이번에 만들지 않았다. 공개 정정/철회 전체 설계 U04를 완료했다고 보지 않는다.
- 새 공개 확인은 기존 상태 확인 간격(15분 로컬 값)과 창 복귀를 사용한다. 필터 변경마다 조회하지 않고, 화면 전환/창 복귀/주기 확인으로 갱신한다. 한국 자정의 표시 변경은 로컬 타이머로 처리하며 AI를 호출하지 않는다.
- 실제 기존 원고의 날짜를 바꾸지 않았으므로 현재 화면에는 ‘새 리포트’가 없다. 당일/전일/자정/타임존·시각 누락/정정의 검증은 합성 입력을 사용한 단위 검사이며 실제 새 발행 사례가 아니다.

공개 테이블의 2개 요약에 timestamp가 정상 조회되고 private raw/packet/validation/comparison 전체가 반환되지 않음을 별도 익명 쿼리로 확인했다. 같은 익명 클라이언트의 초안 테이블 조회는 거절됐다. 쿼리 방식은 [Supabase select 공식 문서](https://supabase.com/docs/reference/javascript/select)의 컬럼 선택·JSON 필드/별칭을 확인했다. changelog.md 읽기는 도구의 markdown 지원 제한으로 실패했으며 버전/새 기능을 도입하지 않았다.

## 계획 비교와 관리

기존 `buildMovingComparisonRows`·포맷·열 순서를 공유 컴포넌트로 추출했다. 추이의 상세 비교에는 공개 조회표만 표시하고 관리자 저장자/이력/입력 컨트롤은 섞지 않는다. 관리자→계획환율에서는 기존 편집/로그인/변경 이력을 보존했다.

로컬 계획 저장소는 미연결이므로 자동 평균/참고값 안내와 읽기 전용을 유지한다. 모달의 22개 숫자 필드가 비활성임을 확인했으며 **실제 저장·로그인 메일 발송은 실행하지 않았다.** 전체 관리자 화면 통합·실제 운영 저장 검증은 후속 범위다. 로컬/운영의 기존 관리 분기도 유지한다.

## 검사

- 전체 회귀: **138파일·1,045실행 사례 통과**, 새 단위 검사는 이동/배지 계약 각3개. 사례 수를 원고 품질 표본으로 계산하지 않는다.
- 처음 격리 환경의 하드링크 EPERM으로9실패가 발생했다. 코드를 우회 수정하지 않고 호스트에서 같은 전체 검사를 재실행해 통과했다. 실패/재실행 JSON을 모두 보존했다.
- 테스트 중복 감사: 동일 이름·동일 본문·동일값 비교 오류 0. 의미적 중복 전체를 자동 입증한 것은 아니다.
- 타입 검사·전체 린트 통과. 후속 소규모 보완은 관련 검사/린트로 다시 확인한다.
- 운영 빌드·기존 앱 로컬 빌드·리포트 빌드 통과. 번들 경계: 운영 진입815,792bytes/초기 JS816,858bytes, xlsx 지연 로딩. 로컬 DB/초안 endpoint는 운영 JS에서 제외했다. 기존 큰 청크 경고의 크기 기준을 올리거나 숨기는 설정 변경은 하지 않았다.
- 브라우저: 월별 두 표, ALL 유지, 리포트 조회·새로고침·복귀, 뒤로가기, 비교/편집 경로 확인.
- 실제390px iframe viewport에서 기존 앱을 검증했다. 스크롤바 제외 본문375px와 scrollWidth375px가 같고, 월별 표만 내부 가로 스크롤이다. PC1265px에서는 본문 가로 넘침 없이6카드를 유지한다. 실제 iPhone Safari 기기 검증은 별도다.
- 대시보드/일별/월별 컴포넌트 원본3개, 환율·설정·산식 파일 등 **12개 보존 해시 일치**. 원고·DB/승인·workflow·메일·의존성/lockfile 변경 없음.

비공개 증거: `.local-reports/private/ui2-integration-20261030/`의 기준 화면/코드사본, browser-checks.json, unit-tests*.json, test-inventory.json, preservation-public-check.json. 비용·자격증명·기사 원문을 화면이나 이 문서에 복사하지 않았다.

## 남은 제한과 다음 순서

- 직접 주소의 미발행/잘못된 날짜/잘못된 run 안내는 구분했다. 철회·미존재를 정확히 구분하는 공용 상태 응답은 아직 없으므로 철회 전용 안내 U01 전체 완료는 아니다.
- U02의 복구 후 관리자 연결 실패 문구를 성공 조회 시 제거하도록 보완했다. 이번에 다시 컨테이너 장애를 만들거나 실제 관리자 계정의 권한을 변경하지 않았다. 기존 DB/권한 검증 기록과 이번 익명 조회 확인을 구분한다.
- 공개 조사 상태·정정 연결·운영 provider/새 workflow·전체 관리 로그인 정리, 이용 통계 수집, 실제6통화 원고/파일럿/배포 승인은 남아 있다.
- 현재 환율/리포트는 저장된 과거 자료다. 최신 자료를 새로 생성하거나 운영 데이터로 바꾸지 않았다.

**다음 고정 순서:** 사용자가 기존 앱의 새 이동을 확인 → 리포트 목록/과거 이력과 관리자 상세 정리 → 색상·톤 검토 → 이메일 방식. 다시 A/B 대시보드나 새 모델 시험을 다음 작업으로 끼워 넣지 않는다.
