# 1·2단계 실행 결과: 자료 준비부터 실제 집필 직전까지

2026-10-27 · 로컬 전용 · 실제 리포트·유료 AI 호출 없음

## 두 단계의 상태

| 단계 | 구현·검증한 것 | 아직 완료로 표시하지 않은 것 |
| --- | --- | --- |
| 1 입력 과정 | 최신 환율 수집, 한국 보고서 날짜/칠레 거래일 구분, 두 공식 통계 목록의 최신 기간 탐색, 다운로드·추출·변경 판정, 기존 검토본 연결, 사용 범위 및 부족한 질문 반환을 단일 명령으로 연결 | 실제 INE 접근이 간헐적으로 실패한다. 소매 최신 원본의 재확인과 합법적으로 사용할 수 있는 시장 원인 설명 자료는 미확보 |
| 2 판단 역할 | 코드·집필 모델·검토 모델·관리자의 책임을 기존 생성/검토 계약에 연결. 사실 오류와 문체 개선 구분. 경제 배경을 환율 원인 보고서로 자동 전환하지 않음 | 실제 모델의 의미 판단·새 작성 가치 판단은 호출하지 않았으며 통과로 기록하지 않음 |

결과는 **`hold_before_generation`**이다. 준비 명령이 실패를 숨기지 않고 상태와 이유를 반환하도록 구현한 것과, 오늘 실제 집필할 자료가 모두 준비됐다는 것은 다르다. 이번에는 1·2단계를 넘어 원고를 만들지 않았다.

## 한 번 실행할 때의 순서

`설정·기존 검토 기록 확인 → BCCh 최신 수집 → INE 최신 목록·PDF 수집 및 추출 → 날짜/버전/사용 범위 검사 → 기존 원고 이력 대조 → 집필 검토 자료·부족한 질문·역할 계약 저장 → 종료`

1. **최초 설정**은 기존 가격 입력·INE 검토본·이용 범위 기록·공식 방법론 파일의 위치를 연결한다. 설정은 `.local-reports/private`에 두며 API 키를 넣지 않는다.
2. **기준일**은 한국 시간으로 결정한다. 10월 26일 23시대 UTC는 한국에서 27일이므로 보고서 기준일은 27일이다. BCCh의 실제 거래일은 별도 필드다. 수집시각으로 관측시각을 채우지 않는다.
3. **환율**은 기존 BCCh API 어댑터가 한 번 수집하고 계산한다. 방법론이 바뀌거나 최신 거래일을 확인하지 못하면 보류한다. 이전 저장 환율을 오늘 값으로 올리지 않는다.
4. **통계**는 기존 두 INE 공식 목록에서 자료별 최신 링크를 선택한다. 최신의 의미는 등록 목록에서 확인한 최신 월이다. 두 자료의 최신 월이 다르면 임의로 오래된 공통 월을 고르지 않고 같은 달 비교를 보류한다.
5. **원문**은 PDF 다운로드·해시·추출을 확인한다. 새 월·수정 파일·다른 추출 결과는 새 검토를 요구한다. 바이트와 추출 결과가 기존 검토본과 같으면 원래 근거 카드를 그대로 보존하고, 새 수집 시각/동일성 확인만 별도로 연결한다. 과거 원문이 새로 검토된 것처럼 시각을 바꾸지 않는다.
6. **사용 범위**는 기존 `source-use/1` 검사를 적용한다. BDE의 동일 공급자·동일 시리즈·동일 가격 종류·방법론·출처 표시 범위에만 기존 정책을 새 숫자 캡처에 연결한다. 시리즈나 방법론이 다르면 거부한다. 모델 입력 가능과 공개 표시 가능은 별도다.
7. **기존 원고**는 기존 요약 기능으로 로컬 파일만 읽는다. 같은 원문 해시를 이미 썼는지 확인하지만 이것만으로 새로운 해석의 가치까지 판정하지 않는다. 로컬 이력이 운영 발행·승인 이력 전체라는 주장은 하지 않는다.
8. **출력**은 새 비공개 폴더에 저장한다. 사용 가능한 가격·근거 사본, 자료별 상태, 미해결 질문, 과거 로컬 원고 요약, 작성/검토 계약의 연결 위치와 보류 이유가 함께 나온다. 입력 검토 자료를 실제 작성 프롬프트로 위장하지 않으며 `generationRequest`는 비어 있다.

## 누가 무엇을 판단하는가

| 담당 | 맡기는 것 | 맡기지 않는 것 |
| --- | --- | --- |
| 코드 | 가격·변화율·강약 방향, 기준일·거래일, 파일 동일성·수정 여부, 자료 범위·이용 조건 기록, 중복 이력, 스키마·ID·인용 참조 검사 | 해시 일치를 의미적 사실 확인이나 이용 허가의 증명으로 판단하지 않음 |
| 작성 모델 | 검토된 공개 사실과 출처 귀속 해석을 이용한 설명·요약·영업 환경 맥락 | 외부 검색, 숫자 재계산, 빠진 원인 창작, 기간 변경, 회사 실적 추정, 가격·판촉 지시 |
| 검토 모델/검토자 | 문장 안의 모든 주장에 대한 원문 지지, 인과·범위·반대 근거, 새 설명 가치 | 자신이 출처 이용 권한·게시 승인을 부여하지 않음. 문체가 아쉽다는 이유로 사실 오류로 분류하지 않음 |
| 관리자 | 완성 원고의 승인·반려 | 자료/개인정보/필수 오류 검사를 우회하지 않음 |

작성 계약은 기존 환율 설명용 `currency-input/5`와 경제 업데이트용 `economic-update/3`를 목적별로 구분한다. 목적을 검토하기 전에 임의로 경제 배경 원고를 만들어 대체 성공으로 표시하지 않는다. 모델과 제공 경로는 이번에 선택하거나 변경하지 않았다.

작성 후에는 기존 `prepareClaimReview → claimReviewContract → assessClaimReview`를 사용한다. `claim-review/4`는 문장을 세부 주장으로 나눠 원문 구절과 대응시킨다. `runEditorialWorkflow`의 교정 경로도 유지하지만 이 준비 명령이 교정 호출을 실행하지는 않는다.

- **필수 교정:** 관측/발표시각 혼동, 출처 공식성·귀속 오류, 대상·단위·인과 범위 확대, 근거와 모순, 업무 지시.
- **편집 개선:** 근거가 지지하는 제목의 추상성, 장황한 표현, 의미 없는 반복 경고.
- **미검증:** 원문 또는 적용 조건을 확인하지 못한 상태. 거짓으로 단정하거나 점수를 채워 승인하지 않는다.

## 재현 방법과 결과물

공식 자료를 실제로 읽는 명령은 다음과 같다. OpenRouter 설정 파일을 읽거나 실제 모델을 호출하지 않는다.

```powershell
npm run report:prepare -- --config .local-reports/private/preparation-review-hfdg5x/config.json --live --python "C:/Users/접근금지/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe" --powershell "C:/Users/접근금지/.cache/codex-runtimes/codex-primary-runtime/dependencies/native/powershell/pwsh.exe"
```

저장된 실제 응답으로 외부 요청 없이 같은 판정을 재현한다.

```powershell
npm run report:prepare -- --config .local-reports/private/preparation-review-hfdg5x/config-replay.json
```

- 실제 실행 기록: `.local-reports/private/report-preparation-rFCrBD`, `report-preparation-UCItSQ`, `report-preparation-M7qTqF`.
- 최종 코드로 재현한 결과: `.local-reports/private/report-preparation-DGHP0E/result.json`. 같은 디렉터리의 `history-catalogue.json`, `summary.json`에 이력과 요약을 저장했다. 이후 마지막 표시 필드 검증 재생은 구조화 검증 기록을 따른다.
- [구조화 검증 기록](pre-generation-stages-1-2-20261027.json).

수집 한 회당 BCCh 1회, INE 최대 6회로 제한한다. 자동 재시도·모델 백업은 없다. 이번의 수동 재점검은 각 실행으로 따로 보존했다. 실제 준비 실행 3회는 BCCh 3요청·INE 8요청이었고, 연결 진단용 공개 요청 4회와 웹 열람은 별도다. 비용이 있는 생성/검색 API는 호출하지 않았다.

## 검증 범위와 고정된 종료점

새 검사 10개 실행 사례는 최신 기간 차이, 파일 수정, 추출 실패, 다중 버전, 가격 정책 범위 변경, 한국 날짜, 역할 계약 연결과 생성 차단을 확인한다. 처음 검사 2개가 반환 배열 순서를 잘못 가정해 실패했으며 자료 ID로 확인하도록 고친 뒤 통과했다. 실제 소매 수집 실패는 테스트 수정으로 해결된 것이 아니며 계속 보류 상태다.

전체 89파일·623실행 사례(516선언·매개변수 확장107), 타입·린트·운영/리포트 빌드·번들 경계 통과. 정확히 같은 이름·본문·자기 비교 없음. 의미적 중복 없음이나 실제 새 원고의 품질 합격을 의미하지 않는다. 기존 610,348바이트 entry 경고는 유지된다. 마지막 표시 필드 보강 후에는 관련 10사례와 문법 검사를 다시 확인했다.

**이번 종료점은 실제 집필 전이다.** 1·2단계의 로컬 준비 명령과 역할 계약은 마련했으나, 현재 원고 생성 자격은 보류다. 소매 원본 확인, 이용 가능한 시장 설명 근거, 의미적 주장·새 작성 가치 확인이 해결돼야 3단계 실제 생성으로 넘어간다. 이를 새 개발 단계로 계속 덧붙이거나, 자료가 부족한 상태에서 API 호출로 메우지 않는다.

새 원고·이전 원고 수정·유료 호출·운영 데이터 수정·DB 변경·메일·배포·push 없음. 키는 기존 BCCh 수집에만 사용했고 OpenRouter 키는 읽지 않았다.
