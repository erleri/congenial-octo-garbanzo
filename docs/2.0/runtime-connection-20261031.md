# 운영 연결 공통 실행부 — 로컬 검증 결과

2026-10-31. 사용자 지정 2번 작업. [결과표](../../artifacts/runtime-connection-20261031/index.html). 운영 변경·push·실제 유료 호출 없이 구현했다. GitHub Actions 파일의 로컬 수정은 이번 작업에서 별도로 명시 승인받았다.

## 완료 범위와 남은 경계

**준비된 입력 → 집필 → 별도 문장 검토 → 영속 저장 → 기존 관리자 대기**의 공통 실행부를 구현·검증했다. 대시보드와 같은 저장 기준환율, 기존 발행 판정기·집필기·검사기·승인 RPC·공개 화면을 재사용한다.

각 국가의 실제 최신 수집·자료 검토 결과가 이 입력 저장소에 자동으로 도착하는 연결은 다음 **6통화 준비 확정** 단계에 남는다. 운영에서 사람이 매번 카드를 골라 등록하는 방식을 완성된 자동 수집으로 간주하지 않는다. 새 기사가 없거나 등록 입력의 환율·날짜·이력이 바뀌면 생성하지 않고 보류한다.

정기 점검도 전용 비교 입력이 없으면 보류한다. 누적 변동 보고서로 대체하거나 전회 이후 전체 원인을 추정하지 않는다. 현재 구현에 정기 점검 분기가 있지만, 새로운 공통 기준환율과 노트 기반 자료로 만든 실제 정기 입력의 자동 공급·실제 품질 합격은 아직 없다. 정책 업데이트도 충분한 입력이 없으면 보류한다.

## 연결 구조

1. 기존 수집·검토 도구가 작성한 근거와 사용 범위로 입력을 준비한다. 이 **국가별 자동 공급 연결은 다음 단계**다.
2. `prepareRuntimeTask`가 같은 대시보드 자료로 가격 스냅샷을 다시 만들고, 기존 누적±2%·14일 후 첫 월요일 판정기를 실행한다. 가격·달력·전회 발행본이 불명확하면 보류한다.
3. 공통 집필기 또는 전용 정기 점검 집필기를 사용한다. 입력·스냅샷·이력·규칙·요청·모델 선택을 고정한다. 기사의 환율을 대표값으로 쓰지 않는다.
4. 검토된 입력은 비공개 DB에 등록한다. 작업자는 해당 데이터 커밋의 같은 스냅샷 ID에 맞는 입력만 읽는다. 매니페스트는 실행 승인이나 게시 승인이 아니다.
5. 전송 직전 현재 제공 경로·구조화 출력·ZDR·수집 금지·가격 상한을 검사한다. DB에서 예산과 중복을 한 트랜잭션으로 예약하고 전송 시작을 별도로 확인한다.
6. 집필은 기존 1회 스트림 전송을 사용한다. 120초·자동 재시도0·백업0이다. 부분 응답 ID와 최종 응답/비용을 비공개로 보존한다.
7. 구조 검사가 통과한 원고를 별도 문장 검토 요청에 보낸다. 기존 주장별 세부 주장·근거 인용·범위·기간·문체 분리 검사를 재사용한다. 집필 모델과 같은 모델을 별도 문맥에서 쓸 수 있으며, 서로 다른 모델의 독립 평가를 했다는 의미는 아니다.
8. 모든 필수 내용 검토, 평균4/5·근거4/5·중대한 오류0 조건을 확인한 결과만 내용 검토 통과로 저장한다. 점수만으로 통과시키지 않는다. 미검증·내용 오류·검토 비용/응답 누락은 승인 보류다.
9. 원고·검증·비용·비공개 저장 증명을 원자적으로 기록하고 관리자 대기에 넣는다. 기존 관리자 승인·반려·철회·정확 날짜 조회와 공개 복사를 사용한다. 자동 게시는 실행하지 않는다.

## 저장·용량·복구

새 구조는 `20261031133808_currency_report_runtime.sql`이며 승인된 공식 CLI2.122.0의 `migration new`로 파일을 만들었다. 격리 로컬 DB에 SQL로만 설치했다. 운영 migration 이력이나 운영 DB는 변경하지 않았고, 로컬 migration-history 등록/배포 반영은 이번에 하지 않았다.

| 비공개 대상 | 저장 내용 | 권한·제한 |
| --- | --- | --- |
| runtime control | 활성화·집필 선택·월/요청 한도·변경 버전 | 기본 비활성·월 예산0. 공개 변경 기능 없음 |
| runtime inputs | 날짜·환율에 고정된 준비 입력 | 서비스 전용. 입력당 JSON 크기 제한. 중간 원문/계정/키를 넣지 않음 |
| runtime jobs | 요청·응답·응답 ID·비용 예약·확정 비용·검토 연결 | 서비스 전용. 호출 전 예약·한 번만 시작·응답 덮어쓰기 금지. 요청/응답 각각 DB 크기 상한 |
| runtime checks | 미입력·중지·보류 등 처리 결과 | 서비스 쓰기. 관리자에게는 제한된 상태 요약만 제공 |
| 기존 runs·receipts | 정제 초안·검사·비용·저장 증명 | 기존 active admin 조회/승인과 원자적 공개 구조 유지 |

JSONB는 객체 키 순서를 정규화하므로, 해시로 고정한 입력·요청·응답은 직렬화 문자열도 함께 저장한다. 다시 읽을 때 의미상 객체와 문자열이 같은지 검사하고 원래 순서로 복원한다. 저장 성공을 근거의 진실성·이용 허가·내용 승인으로 바꾸지 않는다.

DB 저장량은 작고 제한된 카드·요청·응답 중심으로 운영한다. 원문 전체, 스크린샷, 비교 HTML, 키, 수신자 정보는 이 저장 경로에 넣지 않는다. 큰 입력을 조용히 자르지 않고 저장/입력 보류로 처리한다. 원문 파일의 별도 보존·이용 범위는 기존 정책을 따른다. 자동 삭제·보존 기간 강제 적용은 켜지 않았고 운영 용량 점검·백업 계획은 유지한다.

응답 비용이 없거나 저장 중 연결이 끊기면 예약을 남긴다. 해당 실행을 새 ID로 다시 호출하지 않는다. 확인된 응답 ID의 비용만 별도 조회로 정산할 수 있고, 원고 응답을 덮어쓰지 않는다. 전송 뒤 중단은 이미 발생한 비용을 취소할 수 없으므로 응답·비용 보존과 후속 호출 차단을 우선한다.

기존 로컬 시험 비용 장부·원고·미확인 예약은 그대로 보존했다. 새 관리자 월 집계는 **새 공통 실행 경로**의 비용이며 과거 시험 장부·다른 검색/자료 검토 비용·OpenRouter 계정 전체 사용량이 자동 합산된 값이 아니다. 운영 활성화 전에 기존 미확인 비용과 자료 검토 비용의 통합 범위·월 한도·책임을 확정해야 한다.

## 실행·중지와 모델 교체

| 설정 | 동작 |
| --- | --- |
| `FX_REPORT_GENERATOR` 미설정/legacy | 기존 경로 유지. 새 작업자는 호출하지 않음 |
| generator=currency | 기존 다통화 생성기와 배타적. 새 작업만 선택 |
| `FX_REPORT_ENABLED`가 true가 아님 | 새 호출 금지. 기존 빌드 설정과도 연결되므로 화면 전체 기능 스위치와 구분 |
| `FX_REPORT_OPERATIONAL_HOLD=true` | 새 currency 작업 중지. 기존 공개 데이터/감사 기록 삭제 없음 |
| DB enabled=false 또는 예산0 | 외부 모델 호출 예약 차단 |
| DB review_enabled=false | 새 내용 검토 차단. 집필된 원고는 검토 보류로만 저장 가능 |
| 제공 경로/가격/지원 기능 불일치 | 실패/보류. 모델이나 제공자를 자동 변경하지 않음 |

기본 집필은 기존 Sol 프로필을 재사용한다. Sol 미국 경로·Sonnet·Argon은 명시적 선택이 가능한 등록 프로필이며 자동 백업이 아니다. 프로필의 가격은 저장된 **전송 상한**이고 최신 광고 가격을 확인한 결과로 표시하지 않는다. 실제 전송 전 최신 메타데이터를 다시 확인한다.

집필·내용 검토는 각각 요청당 최대$0.25, 합계로는 최대$0.50까지 예약될 수 있다. 이는 신규 지출 승인이 아니다. 현재 월 예산은0이며 실제 호출은0이다. 자료 탐색/카드 검토까지 운영 자동화할 때는 그 비용도 전체 운영 예산에 포함해야 한다.

## 자동 작업 파일

사용자의 로컬 수정 승인 후 `.github/workflows/generate-data.yml`에 새 선택 경로를 추가했다. 기존 환율·메일 작업 뒤, 같은 커밋의 데이터로 6통화를 순차 처리한다. 저장소 쓰기 권한 없이 실행하고 비공개 원문·요청·응답을 Actions 공개 artifact로 올리지 않는다. 새 작업의 실패는 기존 환율·메일 작업을 실패로 전파하지 않는다.

수집·검토된 새 입력이 없으면 `reviewed_input_wait`로 기록한다. **이 workflow 자체가 아직 새 기사를 모아 카드 검토까지 끝내는 것은 아니다.** 국가별 자동 공급 연결과 운영 승인 전에는 새 경로를 활성화하지 않는다.

## 재현

```powershell
npm.cmd run report:runtime:local -- --action replay
npm.cmd run report:runtime:local -- --action inspect
node scripts/currency-report/verify-runtime-db-local.mjs --existing --suite
```

`replay`는 합성 메모리 저장소만 사용한다. `inspect`는 고정 로컬 포트56321만 읽고 키를 출력하지 않는다. DB 검사는 고정 컨테이너 `supabase_db_latamfx-2x-isolated`/포트56322만 허용한다. 실제 REST 연동 확인 도구는 합성 기록을 추가하므로 이번 실행 기록을 재사용하고 매번 실행할 필요가 없다.

`prepare`/`stage`는 개발 확인용 연결 도구다. 운영 수동 카드 등록을 최종 수집 방식으로 채택한 것이 아니다. 실행 기록·백업·로그는 `.local-reports/private/runtime-20261031/`에 보존한다.
