## 발견한 문제와 처리

1. 기존 DB 시험 일부가 테이블 전체를 세었다. 합성 승인 자료가 남자 결과가 달라지거나 단일 행 조회가 실패했다. 시험 전용 run ID·기준일로 범위를 고정하고 실제 자료가 남은 상태에서 재시험했다. 자료를 삭제해 통과시키지 않았다.
2. 공개 복사에 자료 출처·수집시각·집필 목적이 빠졌다. 이미 적용한 migration은 보존하고 후속 두 migration으로 공개 메타데이터와 입력 경계를 추가했다. 잘못된 수집시각 문자열의 공개 노출도 통합 시험에서 차단했다.
3. 기존 비용 사전 검사는 캐시 쓰기 $2.5/백만만 상한으로 보았다. 현재 1시간 캐시 쓰기 $4/백만을 확인해 보수적으로 예약한다. 모델·경로·호출당 $0.25·총 $0.75 한도를 유지했다. [공개 엔드포인트 메타데이터](https://openrouter.ai/api/v1/models/anthropic/claude-sonnet-5.5/endpoints)
4. 깨끗한 설치에서 의존성 감사 16건 중 critical 2건이 Vitest/tinypool 경로에 있었다. 별도 폴더에서 Vitest 4.1.11로 동일 회귀를 확인한 뒤 로컬 코드의 테스트 도구와 lockfile을 갱신했다. Vite 8의 JSX 설정도 맞췄다. 감사는 13건(low 1·moderate 1·high 11), critical 0으로 줄었다. `xlsx` 및 브라우저 다운로드/프록시·소스맵 도구 등의 남은 항목은 별도 영향 분석 대상이다. `npm audit fix --force`나 Puppeteer의 제안된 major downgrade는 수행하지 않았다.

- 인쇄 버튼을 호출했지만 현재 인앱 브라우저 자동 제어가 인쇄 대화상자에서 시간 초과로 끝났다. Escape로 화면 복귀는 확인했으나 PDF 저장·A4 페이지 수·실제 줄바꿈/잘림은 미검증이다. 인쇄 CSS 준비를 출력 합격으로 표시하지 않는다.

## 재현과 검토

portable Node를 사용하며 Docker PATH에 `DockerDesktop/resources/bin`을 추가한다. Supabase CLI는 실제 확인한 2.116.0을 사용했다. 명령의 `--workdir`와 `--local`을 유지한다.

```powershell
# 기존 격리 DB의 시험. 운영/기존 1.x DB를 가리키지 않는다.
supabase test db --local --workdir .local-reports/private/release/run-vQZc5n
npm.cmd run report:db -- --action verify

# 새로운 로컬 환경에서만 연결 설정과 합성 계정을 만든다.
npm.cmd run report:db -- --action bootstrap --cli <설치된-supabase.exe> --workdir <prepare-db가-반환한-폴더>

# 공개 공급자 정보 확인이며 실제 생성/키 로딩은 없다.
npm.cmd run report:release -- --action endpoint-preflight

# 실제 시험은 패킷·계획·승인 해시·예산을 포함한 private 입력이 있을 때만 사용한다.
npm.cmd run report:trial -- --input .local-reports/private/event-trial-input.json
```

`event-trial-input.json`은 아직 만들지 않았다. 승인·근거 조건을 충족한 실제 입력이 준비된 뒤 작성한다. 임의로 `authorized=true`를 넣는 것은 사용자 예산 승인이나 내용 검토가 아니다. 새 실행은 private 폴더에 저장되고 자동 검사 통과 후보만 **검토 초안**으로 로컬 미리보기에 투영된다. 내용 검토·DB 게시를 자동 승인하지 않는다.

검토 화면: `http://127.0.0.1:4175/local-experience.html?mode=local-db&design=a#review-db`. 합성 로그인 정보는 Git 제외 `.local-reports/private/local-db/accounts.json`에 있다. 계정·service 키를 채팅이나 브라우저 번들에 복사하지 않는다. 파일 모드와 승인 DB 모드는 서로 다른 캐시를 사용한다.

합성 승인 화면과 권한 경계 이미지는 `.local-reports/reviewable/db-approved-a.png`, `db-revoked.png`, `db-reader-mobile.png`에 저장했다. 이는 실제 AI 작성 품질의 증명이 아니다.
