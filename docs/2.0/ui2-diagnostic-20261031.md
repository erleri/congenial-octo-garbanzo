# LATAM FX 2.0 정밀 진단

검토일: 2026-10-31 · 범위: 로컬 4176 앱, 기존/네이비 정돈 비교안, 주요 UI·데이터 연결 코드, 공식 벤치마크 자료.

## 결론

현재 메뉴와 정보 구성은 버릴 이유가 없습니다. 대시보드의 6통화 비교, 평균·기준일 값·범위·추이, 리포트의 편집형 구조는 강점입니다. 개선 방향은 **구성 보존 → 숫자와 상태의 신뢰성 → 모바일·접근성 → 공통 스타일 → 운영 연결**입니다. 새로운 카드나 AI 기능을 더하는 것보다 기존 기능이 같은 의미로 동작하도록 마감하는 일이 우선입니다.

이번 진단은 운영 전수 감사나 실제 사용자 조사, 금융 데이터 정확성 재검증, 원문 품질 평가가 아닙니다. 운영 API·DB·메일 변경, 유료 모델 호출, 앱 소스 수정은 없습니다. 아래는 확인한 사실과 개선 제안이며 승인된 구현 계획은 아닙니다.

## 유지할 강점

- 대시보드 / 환율 추이 / 환율 리포트의 세 메뉴와 별도 관리자 영역.
- 당월 누적 평균을 중심으로 기준일 값과 MoM·52주 위치를 함께 보는 기존 구조.
- 통화·기간을 URL에 보존하는 추이와 월별 표, 보정 표식.
- 보고서 기준일을 고정하고 과거 사례를 현재 보고서와 구분하는 원칙.
- 국가 목록과 명시적 최신 링크의 구분, 문장→근거 펼침, 이력 페이지 나눔·이전/다음·캐시/정정 분리.
- 새 리포트의 표시가 페이지 열기/모델 재호출과 분리된 구조.

## 진단 항목

### 01. “정상”과 “최신”을 분리해야 합니다 — 출시 전

**확인:** 로컬 4176 화면은 기준일 2026-09-12 자료에 “정상”을 표시했습니다. App.tsx의 상태는 loading/error 중심이며, 데이터가 기대 갱신 시점을 지났는지는 판단하지 않습니다. exchangeRateRepository의 stale도 주로 조회 실패·대체 경로를 뜻합니다.

**영향:** 오래된 자료를 오류 없이 읽은 경우 독자가 최신 환율로 오해할 수 있습니다. 운영 데이터가 실제로 오래됐다는 판정은 아닙니다.

**제안:** 화면별로 “환율 기준일 / 마지막 수집 / 게시일”의 대상을 명시합니다. 연결 성공과 자료 신선도를 나누고, 국가별 달력·공급 주기에 맞춰 지연을 표시합니다. 개발용 build 정보는 관리자 상세로 이동합니다.

**완료 조건 / 한계:** 오래된 정상 응답, 휴일, 캐시, 일부 통화 지연이 서로 다른 상태로 표시되어야 합니다.

코드 근거: `src/App.tsx:146; src/lib/exchangeRateRepository.ts; src/hooks/useExchangeData.ts:507`

### 02. 숫자의 의미는 유지하되, 읽는 방법을 통일해야 합니다 — 출시 전

**확인:** 카드 제목은 BRL / USD이고 큰 값은 당월 누적 평균, 작은 값은 기준일 환율, MoM은 월평균 비교입니다. API 배지는 실제 공급자·가격 정의를 알려주지 않습니다. 리포트에서는 “1 USD당 CLP”, 강약 방향을 더 명확히 표시합니다.

**영향:** 환율 상승과 현지통화 강세를 반대로 읽거나, 월평균 변화와 당일 변화를 섞어 이해할 수 있습니다.

**제안:** MTD 평균을 큰 값으로 유지합니다. 단위는 “1 USD = … BRL”로 일관화하고 “전월 평균 대비”를 풀어 씁니다. 평균에 포함된 관측·보정 규칙과 실제 공급자·가격 정의는 상세 설명에서 확인하게 합니다. 종가라고 확인되지 않은 값은 종가로 부르지 않습니다.

**완료 조건 / 한계:** 대시보드·추이·리포트에서 같은 값의 단위·기준일·정의가 일치하고, 색 없이도 방향을 이해할 수 있어야 합니다.

코드 근거: `src/components/Dashboard.tsx:642–766; src/components/CurrencyReportDetail.tsx`

### 03. 현재 로컬 리포트 화면이 곧 배포용 화면은 아닙니다 — 출시 전

**확인:** vite.app-local.config.ts는 __LOCAL_CURRENCY_REPORTS__를 true로, 기본 vite.config.ts는 false로 설정합니다. App.tsx는 로컬에서 PublishedCurrencyReports/LocalReportReview를, 배포 경로에서는 기존 FxReports/Admin을 선택합니다. 현재 생성 설정도 enabled:false입니다.

**영향:** 4176에서 확인한 국가별 이력·승인 흐름이 기능 플래그만 켜면 그대로 운영된다고 볼 수 없습니다. 이는 의도된 격리이지만 남아 있는 출시 연결 작업입니다.

**제안:** 동일한 공개 화면과 데이터 인터페이스를 사용하고 로컬/운영의 데이터 연결만 교체하도록 마감합니다. 관리 권한은 서버에서 검증하고, 운영 전환은 별도 승인 뒤 진행합니다.

**완료 조건 / 한계:** 배포용 빌드의 프리뷰에서 같은 메뉴·국가 목록·본문·정정·철회·권한 제한이 동작하고, 로컬 시험 정보가 포함되지 않아야 합니다.

코드 근거: `src/App.tsx:26–29,99,137–140; vite.config.ts; vite.app-local.config.ts`

### 04. 환율 초기 조회 실패가 리포트까지 막는 구조입니다 — 출시 전

**확인:** App.tsx:113의 !dataset 분기가 모든 화면보다 먼저 실행됩니다. 캐시도 없이 최초 환율 조회가 실패하면 error가 생겨도 본문은 “데이터를 불러오는 중”을 선택합니다.

**영향:** 리포트 저장소가 정상이어도 리포트·관리 화면을 독립적으로 이용하기 어렵습니다.

**제안:** 환율·리포트·관리 화면의 로딩과 오류 경계를 나눕니다. 각 화면에 필요한 데이터만 기다리고 실패한 화면만 복구 행동을 제공합니다.

**완료 조건 / 한계:** 환율 최초 조회 실패를 재현해도 공개 리포트는 열리고, 환율 화면에는 명시적 실패·재시도가 나와야 합니다. 이번에는 코드 경로를 확인했으며 실제 장애 주입은 하지 않았습니다.

### 05. 모바일은 안 깨지지만, 주요 통화가 너무 늦게 나옵니다 — 우선 개선

**확인:** 390px 프레임(실제 내용 폭 375px)에서 첫 카드 상단 약 971px, PEN 약 2520px, 전체 높이 약 5290px였습니다. 카드 6개가 세로로 쌓이기 전에 헤더·USD 기준·포커스가 상당한 공간을 사용합니다.

**영향:** 빠르게 환율을 확인하려는 모바일 독자가 반복해서 긴 스크롤을 해야 합니다.

**제안:** PC 순서·정보는 유지합니다. 모바일만 상태 상세와 USD 보조 지표를 접을 수 있게 하고, 통화 바로가기 또는 관심 통화 이동을 제공합니다. 모든 통화를 억지로 두 열로 줄여 글자를 더 작게 만들지 않습니다.

**완료 조건 / 한계:** 390px에서 첫 통화 핵심 값에 더 빨리 도달하고, 모든 통화·출처·기존 차트에 접근할 수 있어야 합니다. 삭제된 정보가 없어야 합니다.

### 06. 접근성과 작은 글자는 스타일 변경만으로 해결되지 않습니다 — 출시 전

**확인:** 실제 문서 언어가 en입니다. 대시보드 차트 평균 라벨은 9px·#8a94a3이며 흰색 대비 약 3.07:1입니다. 작은 일반 텍스트의 WCAG 기준 4.5:1에 미달합니다. 리포트는 390px에서 가로 넘침이 없었지만 320px 외곽 프레임의 305px 내용 폭에서는 통계 칸이 약 10px 넘쳤습니다.

**영향:** 저시력·모바일 독자와 화면 읽기 도구 이용자에게 불리합니다. 좁은 프레임 측정은 실제 iPhone Safari·전체 WCAG 인증을 대신하지 않습니다.

**제안:** 문서 언어 ko, 주요 설명·축 라벨의 크기와 대비, 좁은 폭의 통계 칸 최소 너비를 정리합니다. 터치 크기는 우선 40–44px를 사용성 목표로 삼되 WCAG AA의 24px/간격 예외와 혼동하지 않습니다.

**완료 조건 / 한계:** 텍스트 대비·키보드·320 CSS px 내용 폭·200/400% 확대를 별도로 확인합니다. 가로 스크롤이 필요한 데이터 표는 컨테이너 안에서 허용합니다.

코드 근거: `index.html:2; src/components/Dashboard.tsx:111–115; src/components/CurrencyDetail.tsx:45; src/local-report/report.css`

### 07. 화면 이동의 제목·초점·기간 제어를 다듬어야 합니다 — 우선 개선

**확인:** 리포트·추이에서도 브라우저 제목은 모두 “중남미 환율 대시보드”입니다. 공통 화면 전환 후 제목·초점 처리가 없고, applyNavigation의 화면 비교는 URL 변경 뒤에 실행되어 의도한 스크롤 초기화가 무효가 될 수 있습니다. 시작 월 선택지는 2010년부터 긴 목록입니다.

**영향:** 여러 탭·뒤로가기·키보드 이용 시 현재 위치가 모호합니다. 자주 보는 기간 설정도 번거롭습니다.

**제안:** 국가·화면·보고서 날짜를 탭 제목에 반영하고, 새 화면의 제목에 적절히 초점을 옮깁니다. 스크롤 복원과 새 이동을 구분합니다. 최근 1·3·12개월 바로가기와 기존 월 직접 선택을 함께 둡니다.

**완료 조건 / 한계:** 뒤로가기는 이전 목록 위치를 복원하고 새 화면은 의도한 시작점으로 이동해야 합니다. 기간·통화 URL 복원은 보존합니다. 스크롤 문제는 코드 확인이며 모든 경로에서 UI 재현한 것은 아닙니다.

코드 근거: `src/App.tsx:49–58; src/lib/fxNavigation.ts; index.html`

### 08. 미발행·과거 자료·최신 리포트의 행동 문구가 맞지 않습니다 — 우선 개선

**확인:** 현재 카드에는 “최신 리포트 → / 현재 리포트 미발행”이 같이 표시됩니다. 칠레 목록에 과거 승인 사례가 있어도 최신 대상에서 제외되어 전체 목록은 미발행으로 표시됩니다. 역사 자료를 현재 보고서로 취급하지 않는 판정은 올바릅니다.

**영향:** 독자는 “자료가 전혀 없는 것인지, 최신만 없는 것인지”를 다시 클릭해서 확인해야 합니다.

**제안:** 정상 최신은 “10월 28일 해석 읽기”, 과거 자료만 있으면 “지난 리포트 보기”, 아무 글도 없으면 “아직 발행 전”으로 행동을 맞춥니다. 국가 탭→국가 목록, 명시적 최신 링크→최신 본문이라는 현재 규칙은 유지합니다.

**완료 조건 / 한계:** 미발행·과거만 존재·새 글·조회 실패·캐시·철회에 각각 일관된 문구와 행동이 있어야 합니다.

코드 근거: `src/App.tsx:99–109; src/components/PublishedCurrencyReports.tsx:26–40,115–145`

### 09. 정돈안은 좋아졌지만 아직 공통 디자인 체계는 아닙니다 — 우선 개선

**확인:** 원본 App.css와 report.css는 배경·글꼴 크기·버튼·모서리·색 변수 체계가 다릅니다. 정돈안은 비교 도구에서 CSS를 덧씌우며 실제 기본 앱에는 적용하지 않았습니다. 강한 네이비 USD 영역은 여섯 통화보다 눈에 먼저 들어올 가능성이 있습니다.

**영향:** 한 서비스 안에서 대시보드는 도구, 리포트는 다른 사이트처럼 느껴질 수 있습니다. 화면마다 작은 스타일 보완을 반복하기 쉽습니다.

**제안:** 중립 배경·흰 카드·네이비 선택 상태를 공통화하고 색·글자·간격·버튼·배지를 하나의 규칙으로 만듭니다. 리포트의 편집형 구조는 유지합니다. USD의 진한 면적은 두 강도로 비교하고 자동 확정하지 않습니다.

**완료 조건 / 한계:** 대시보드·추이·목록·본문·관리자가 같은 상태·버튼 언어를 사용해야 합니다. 축소 비교 화면뿐 아니라 100% 크기에서 읽기 시험을 합니다.

코드 근거: `src/App.css; src/local-report/report.css; artifacts/ui2-refined-comparison/themes.css`

### 10. 차트의 형태 비교와 변동 크기 비교를 구별해야 합니다 — 후속 개선

**확인:** 대시보드 소형 차트는 통화별 domain과 숨겨진 Y축을 사용합니다. 변화의 모양은 보기 쉽지만, 같은 높이의 선이 같은 변동률을 뜻하지 않습니다. 일별 상세에는 실제 값 표가 있어 보완 경로는 있습니다.

**영향:** 독자가 통화별 선의 기울기·진폭만 비교해 변동 크기를 오해할 수 있습니다.

**제안:** 현재 소형 차트를 유지하면서 “통화별 독립 축”과 기간 변화율을 가까이 표시합니다. 필요하면 추이에 같은 출발점=100 또는 변동률 비교를 추가합니다. 단순 대시보드에 전문 매매 차트를 밀어 넣지 않습니다.

**완료 조건 / 한계:** 강약 방향·기간·독립 축이 분명하고, 실제 값과 비교용 변환 값이 섞이지 않아야 합니다.

코드 근거: `src/components/Dashboard.tsx:790–887; src/components/CurrencyDetail.tsx`

### 11. 관리자는 연결 목록보다 오늘 처리할 일을 먼저 봐야 합니다 — 출시 준비

**확인:** 로컬 관리 첫 화면은 19개 연결의 상태 표가 길게 나오고 보고서 검토가 뒤에 있습니다. “미점검 14 / 표본 정상 5”이며 화면에도 운영 실시간 상태를 보증하지 않는다고 표시되어 있습니다. 운영 장애 대시보드가 완성됐다는 뜻은 아닙니다.

**영향:** 승인 대기와 실제 수집 실패를 우선 처리하기 어렵고, 표본 점검을 전체 정상으로 오해할 수 있습니다.

**제안:** 상단은 승인 대기·수집 실패·예산/호출 상태·최근 성공 시각, 하단은 API 상세로 나눕니다. 계획 변경은 기존 별도 영역 유지. 읽기 조회와 새 외부 호출 버튼을 엄격히 구분합니다.

**완료 조건 / 한계:** 초안·관리 정보는 active admin만 볼 수 있고, 읽기 화면을 여는 것만으로 유료 호출·메일·수집이 발생하지 않아야 합니다. 이번 검토는 로그인·권한 공격 시험을 포함하지 않습니다.

### 12. 이용 현황과 운영 성능은 아직 실측 근거가 없습니다 — 출시 준비

## 현재 공개 벤치마크와 취사선택

시장 전체의 통계적 “최신 유행”을 조사한 것은 아닙니다. 현재 유지되는 공식 제품·오픈소스·접근성 문서를 확인해 적합한 패턴을 골랐습니다.

- **[Tremor / shadcn](https://www.tremor.so/)**: 중립적인 표면, 반복 요소의 일관성, 조작 상태·키보드 사용. 카드·탭·필터·버튼·배지의 공통 규칙만 참고. 라이브러리 전체 이식은 불필요. [추가 자료](https://github.com/tremorlabs/tremor)

- **[Our World in Data](https://ourworldindata.org/redesigning-our-interactive-data-visualizations)**: 데이터와 해설 연결, 출처 강조, 차트/표와 관련 제어. 숫자의 정의·출처·기간을 가까이 배치. 기존 상세 표와 근거 펼침을 발전. 2023년 설계 설명을 현재 참고한 것임.

- **[WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)**: 텍스트 대비·언어·재배치·목표 크기의 검증 기준. 유행이나 취향으로 정하지 않고 실측. 작은 버튼은 간격 예외까지 보고 판정. [추가 자료](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
