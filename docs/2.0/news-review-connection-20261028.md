# 뉴스 수집 이후 자동 검토 연결 — 로컬 준비·저장 재생

2026-10-28 · 기존 계획 4단계 · 신규 유료/외부 호출·운영 변경 없음

## 완료 범위와 남은 경계

기존 수집·사실/견해 카드·범위 검사를 재사용해 **검토 입력 준비 → 검토 응답 확인 → 기존 근거 카드 검사**를 연결했다. 특정 통화의 원고를 수정하거나 기사 제목을 정규식으로 읽어 원인을 승인하는 경로를 만들지 않았다.

실제 기사 19건에서는 검토 입력 준비와 무결성·시점 표기까지만 실행했다. 실제 내용 판단을 수행하는 무인 검토기는 아직 연결하지 않았다. 따라서 `automatic_review_unavailable`을 유지한다. 이번 결과는 **연결 코드와 저장 검증 완료**이며 **19건 내용 검토 또는 4단계 전체 완료가 아니다**. 사용자 수동 수집/확인 작업으로 바꾸지 않는다.

## 연결 구조

```text
기존 출처 선택·수집 결과(원문·날짜·내용 해시)
  → 원문/카드 변경 여부 확인
  → 비공개 검토 입력: 전체 추출 문단 + 시간/전재/사용 상태 + 공통 지침
  → 로컬 검토 어댑터(미연결이면 검토 불가, 저장 응답이면 재생)
  → 기사 역할·사건일·가격 종류·문장별 근거 위치 검사
  → 기존 selected-material-review의 사실/견해·범위 검사
  → 검토 판단 기록 또는 부족/실패 (집필·게시 승인은 별도)
```

### 코드가 확인하는 것

- 원문/검토 입력의 해시와 규칙 버전이 일치하는지. 원문이 바뀌면 과거 응답을 재사용하지 않는다.
- 발표일을 국가 시간대의 날짜로 환산한다. 발표시각·사건일·가격 관측시각·수집시각을 별도 필드로 둔다.
- 날짜만 있는 자료는 정확한 시각 미확인으로 남긴다. 현재 페이지를 회고 수집했으면 당시 이용 가능했던 원문이라고 승인하지 않는다.
- 검토 응답의 기사 역할을 원인 설명/가격 정보/소비 배경/정책 배경/무관으로 구분한다. 원인 설명의 대상일은 요청한 거래일과 맞아야 한다.
- FIX·공식 기준·종가·장중 및 ARS 도매/소매/MEP/CCL/blue의 검토 결과를 별도 가격 종류로 요구한다. 미기재·혼합 상태도 표현한다.
- 요지의 모든 하위 주장에 대한 검토 결과, 실제 원문 문단 위치, 기존 사실·귀속 견해 및 범위 계약이 함께 있어야 근거 카드 검사로 넘어간다.
- 내용상 부족/관련 없음과 검토기 미연결·응답 형식 실패·시간 초과를 구분한다. 처리 한도를 넘거나 시간 초과가 나면 재시도·백업 없이 중단/보류한다.

### 여전히 의미 판단이 필요한 것

문단 위치가 존재한다고 그 문장이 지지되는 것은 아니다. 사건일·가격 종류·원인 연결이 실제 원문에 있는지, 중요한 조건이 빠지지 않았는지, 전재 기사들이 독립 확인인지 등은 검토기가 판단해야 한다. 검사 코드나 모델의 체크 표시만으로 그 정확성을 입증하지 않는다.

검토 응답은 원문 이용 허가·모델 전송 허가·집필 자격·공개 승인을 만들 수 없다. 기존 이용 범위와 승인 흐름을 유지한다. 신설 어댑터에 기본 모델, 키, 외부 전송, 유료 호출, 자동 모델 교체 기능은 없다.

## 실제 저장 기사 재생

[전 단계의 10개 수집 경로/19건](free-news-expansion-20261028.md)을 다시 수집하지 않고 사용했다.

| 통화 | 저장 기사 | 검토 입력 준비 | 실제 내용 검토 |
| --- | ---: | ---: | --- |
| BRL | 1 | 1 | 미수행 |
| MXN | 6 | 6 | 미수행 |
| COP | 1 | 1 | 미수행 |
| CLP | 2 | 2 | 미수행 |
| ARS | 3 | 3 | 미수행 |
| PEN | 6 | 6 | 미수행 |

19건 중 요청 날짜와 **발표 현지 날짜**가 같은 자료는 7건, 다른 자료는 12건이었다. 이는 실제 사건/가격 관측일 일치 여부가 아니다. Andina 2건은 정확한 발표시각이 미확인이었다. 3건에서 Reuters 전재 단서를 보존했다. 이 숫자를 19건의 당일 원인 근거 또는 독립 확인으로 계산하지 않는다.

이 기사들은 여러 날짜를 포함한 수집 경로 시험 자료다. 입력에 남아 있는 조사 질문의 범위도 검토 대상이며, 실제 보고서 집필 자격을 승인한 입력 묶음으로 바꾸지 않았다. 원문 문단은 생략·재작성하지 않고 비공개 검토 입력 파일에만 저장한다.

비공개 결과: `.local-reports/private/news-review-connection-20261028/replay-ICBase/summary.json`. 각 결과의 `directory`가 원본 검토 결과와 비공개 입력 파일을 가리킨다. 기존 기사·원고 파일은 덮어쓰지 않았다.

## 재현 명령

기존 Node 20 환경에서 저장 수집 결과 JSON을 대상으로 실행한다. 예전 검증 파일이 `{result, ...}` 형식이면 그 `result`만 새 비공개 파일로 저장해 전달한다.

```powershell
npm run report:research:review-batch -- --collection ".local-reports/private/collection.json" --news
```

출력 폴더의 `news-review-jobs.json`은 비공개 원문을 포함한다. 브라우저/public/디자인 도구/모델에 자동 전송하지 않는다. 명령의 표준 출력은 상태 요약만 반환한다.

저장된 검토 응답은 `[{cardBinding, response}]` 형식으로 같은 비공개 폴더 아래에 둔다. 명시적으로 `--newsResponses`를 추가하면 외부 호출 없이 재생한다. 누락/중복/다른 카드의 응답은 거부하거나 실패로 남기며 자동 생성으로 채우지 않는다.

## 검증

- 새 8개 행동 검사: 전체 문맥/시점 분리, 현지 날짜와 시각 정밀도, 원문/지침 변경, 기존 카드 검사 연결, 하위 주장/문단/거래일 모순, 관련 없음/미연결 구분, 실패 후 계속 및 처리 한도, 시간 초과 후 겹치는 호출 방지.
- 합성 검토 응답은 연결 동작만 검증했다. 실제 19건의 검토 결과나 모델 품질 표본으로 계산하지 않는다.
- 타입·린트·전체 회귀·운영 빌드·앱 리포트 빌드·별도 리포트 빌드·번들 경계 검사 통과. 116파일/862개 실행 사례이며 테스트 수는 실제 원고 품질이 아니다.
- 기존 500kB 번들 경고는 유지한다. DB/UI 동작은 이번 변경 범위가 아니며 새 DB/브라우저 검증은 수행하지 않았다.
- 초기 새 테스트는 공통 시험 입력 도우미의 호출 형식을 잘못 사용해 실패했다. 시험 설정을 바로잡고 관련 검사와 전체 회귀를 다시 통과했다.
- 기존 원고·환율·입력·비용 등 보호 파일 12,045개를 작업 전 해시와 비교해 변경·누락 0을 확인했다. 보존 결과는 비공개 `preservation-result.json`에 기록했다. 신규 유료 호출·네트워크 호출·운영 변경은 0이다.

## 원래 작업 순서에 따른 다음 경계

4단계의 미완료 항목은 **새 기사에 대한 실제 무인 내용 검토와 사용 범위 판단**이다. 이번 연결부에 실행할 검토기를 선택하고, 입력·전송 가능 범위·비용 및 표본 평가를 준비해야 한다. 신규 유료 실행은 별도 예산 범위에서만 한다. 그 결과가 나와야 국가별 작성 자격과 5단계 품질 시험 여부를 판단한다. 수집 성공이나 모의 응답 검증을 근거로 6개국 준비 완료·출시 가능으로 변경하지 않는다.
