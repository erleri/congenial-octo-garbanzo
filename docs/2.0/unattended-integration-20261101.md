# 기존 환율과 무인 리포트 통합 연결

> **현재 상태 갱신 — 2026-11-01:** 아래는 당시 기록이다. 이후 6통화 공식 자료 입력·서비스 전용 원자료 캐시·공개 고지의 로컬 연결과 검증을 마쳤다. [1~3단계 마감과 남은 제한](report-operations-stage123-20261101.md)을 우선 확인한다. 실제 내용 검토·유료 생성·운영 전환은 별도다.

후속 1번의 최신 상태는 [공식 통계 연결 기록](official-background-connection-20261101.md)을 따른다. 공통 검사·집필 연결과 MXN 저장 통계4개 재생을 완료했으며, 다른5개국 공식 숫자 자동 채택과 정정 후보 자동 기록은 남아 있다. 아래는 그 후속 구현 전의 1~3번 기준 기록이다.

2026-11-01. 사용자가 승인한 1~3번의 로컬 구현 기록이다. 기존 운영의 환율 선택·이어받기를 재사용하고, 자료 확인과 유료 제작을 분리했다. 실제 모델 호출·과금·운영 반영은 0이다. 공식 통계의 자동 내용 검토와 정정 후보 자동 공급은 남아 있으므로 무인 운영 완료로 판정하지 않는다.

## 1 공통 환율과 독립된 자료 시각

- 대표값·차트·변화율은 기존 `getDashboardDaily`와 `getDashboardPreviousDaily`를 사용한다. 원래 환율 수집·이어받기 로직의 값은 변경하지 않는다.
- 대시보드의 갱신 안내에 쓰던 주말 제외·UTC 18시·2영업일 기준을 `src/lib/reference-freshness.js`로 추출해 함께 사용한다. 국가별 휴일이나 종가 인증으로 부르지 않는다.
- `IMPUTED/FFILL`은 일괄 거부하지 않는다. 이어받은 값과 가장 가까운 원래 API 행의 값·통화·단위·상태를 대조하고 원래 날짜를 보존한다. 중간 값이 다르거나 원본이 없으면 보류한다. 데이터 갱신 지연·상류 환율 작업 실패는 별도 상태로 남긴다.
- 기사는 국가 현지 날짜의 최근 최대 4개 조사일에서 새 날짜부터 확인한다. 조사일은 거래일 인증이 아니다. 원문 대조 후 확인한 사건일을 설명 기준으로 사용하고, 원래 발표·수집시각을 바꾸지 않는다. 범위 밖 기간은 확인하지 못한 기간이다.
- 원래 기준환율 뒤에 나온 주말 뉴스도 연결할 수 있다. `materialCutoff`의 독립된 자료 기준시각 안에서만 허용한다. 가격 기준일·관측일·숫자는 그대로이며 이후 자료를 과거 가격의 원인으로 소급하는지는 필수 내용 검토 대상이다. 공통 규칙 버전은 `currency-rules/9`다. 과거 원고와 당시 판정은 덮어쓰지 않는다.
- 기존 공식 자료 수집기도 별도 배경 경로에 연결했다. 수집된 통계는 대상 기간·지표 정의·발표일·이용 범위 검토 전까지 대기한다. 현재 자동 통계 검토 어댑터는 미완료다. 저장 기사 재생에 공식 자료 캡처가 없다는 결과를 해당 기관에 자료가 없다는 뜻으로 사용하지 않는다.

## 2 자료 확인과 유료 중복 방지 및 복구

```text
기존 환율 스냅샷 ──────┐
                      ├─ 가격·발행 이력·새 자료 판단 ─ 근거·예산 확인 ─ 제작 ─ 관리자 승인
뉴스·공식 자료 확인 ────┘
       ↓
원래 판본·실패 상태 저장
       ↓
동일 판본 분석 재사용 / 새 판본 검토 / 자료 부족 유지
```

완료 배치를 찾기 전에 무료 자료 확인을 실행한다. 이전 실행이 끝났거나 모델 키가 없더라도 새 자료 확인을 생략하는 이유로 사용하지 않는다. 실제 전송은 설정·예산·키·자료 조건을 모두 통과해야 한다.

마지막 공개본에 사용한 기사 판본을 비공개 실행 기록에 남긴다. 같은 판본은 새 사건이 아니다. 이후 발표·수정 또는 이미 사용한 URL의 실제 내용 변경은 조사 후보가 될 수 있다. 과거 미확인 기사는 새 사건으로 자동 승격하지 않으며, 누적 변동·정기 점검이 도래했을 때 검토할 수 있다. 기사 수·해시 변화는 의미적 중요성의 증명이 아니다.

배치의 재개 기준은 환율 값·가격 정의·기사 판본·발행 기준점·처리 설정이다. 단순 수집시각·조회 횟수·같은 기사에 연결된 질문 수가 늘어났다고 새 유료 실행을 만들지 않는다. 중단 배치에는 실제 입력 데이터와 기준시각을 고정한다. 다음 날에는 현재 자료 상태와 새 공개본을 확인한 뒤 원래 입력으로 재개하거나 보류한다. 현재 시각으로 옛 원고를 다시 표시하지 않는다.

| 중단 상태 | 처리 |
|---|---|
| 전송을 시작하지 않은 예약 | DB의 시작시각·응답·배치 임대를 확인해 미전송 예약만 해제. 같은 요청·같은 배치·같은 예산으로만 재예약 가능 |
| 유효한 응답과 비용이 확정됨 | 저장 응답 재사용. 이미 처리한 집필·추출을 다시 요청하지 않음 |
| 응답은 있고 비용만 미확인 | 기존 응답 ID의 비용만 조회. 확정 장부를 사용하되 원래 응답의 비용 누락은 그대로 보존 |
| 응답 ID 또는 응답이 없음 | 비용 미확인·응답 손실 상태로 보류. 새 요청으로 우회하지 않음 |
| 원문·공개본·가격 정의가 달라짐 | 이전 판본을 보존하고 새 판단. 과거 검토·승인을 새 입력으로 옮기지 않음 |

무료 확인 결과는 비공개 상태 기록에 남긴다. 출처 ID·상태만 허용하고 본문·키·추가 임의 필드는 제거한다. CLI 결과는 정상·대기·승인 대기·장애·조치 필요로 나누며 장애와 비용 조치는 종료 코드로 전달한다. 기존 Actions의 환율·메일 보호 경계는 유지한다. 새 환율 커밋이 없을 때도 저장 자료로 무료 조사를 할 수 있지만 갱신 성공으로 표시하거나 유료 집필 자격을 부여하지 않는다. 워크플로 변경은 로컬 파일에만 있다.

## 3 일회 시험 권한과 운영 경로

일회 시험과 지속 운영은 같은 제작 경로를 사용한다. 일회 설정에는 승인 참조·데이터 해시·만료시각·총액·호출 수를 묶고 월 반복 권한은 `not_authorized`로 둔다. 기존 월 장부는 회계 상한으로만 재사용하며 월 운영 승인으로 해석하지 않는다.

DB는 같은 일회 승인 참조의 재등록, 두 번째 배치, 다른 데이터, 만료된 설정을 차단한다. 활성화·실행 직전에도 같은 정책·예산을 확인한다. 코드나 제안 파일 생성은 활성화가 아니다.

`draft-trial`은 Git에서 제외된 로컬 JSON으로 일회 설정 제안 파일만 만든다. `configure-policy`는 설정 저장만 하며 생성·예산을 활성화하지 않는다. 이번 작업에서는 실제 승인된 유료 시험 설정을 설치하지 않았다. 격리 DB의 합성 시험 후 생성·검토 중지와 예산0을 복구했다.

## 남은 판정

1. 공식 통계의 지표 정의·발표/수정·이용 범위를 자동 검토해 집필 카드로 연결하는 부분을 마감해야 한다. 현재 수집 성공만으로 사용하지 않는다.
2. 새 자료와 기존 공개본의 관계를 검토한 결과를 정정 후보 기록으로 자동 연결하는 부분이 남아 있다. 새 기사 발견과 사실 오류 확정은 다르다.
3. 실제 최신 기사 확보율, 외부 비용 조회 성공, 실제 6통화 원고 품질·비용, Actions 실측은 미검증이다. 합성 시험을 실제 품질 표본으로 세지 않는다.

다음은 이 공백과 현재 연결을 독립 검토하는 단계다. 실제 유료 실행·운영 활성화·공개 전환을 이번 로컬 검증의 통과로 대신하지 않는다.
