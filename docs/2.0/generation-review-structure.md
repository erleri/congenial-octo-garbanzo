# 리포트 생성과 문장 검토 구조

환율의 기준시각·데이터 제공 경로와 승인된 달러 결제 환산 설명은 코드가 담당한다. AI는 기사에 근거한 정책 신호·시장 반응의 해석과 관찰 변수를 작성한다. 검토는 문장을 세부 주장으로 나누어 각각의 근거를 기록한다. 이번 로컬 구현에는 새 AI 호출이 없으며 생성 품질 합격은 아직 확인하지 않았다.

## 작성과 조립

현재 버전은 입력 `currency-input/4`, 공통 대응표 `currency-rules/4`, 조립 `currency-assembly/1`, 문장 검토 `claim-review/3`이다. 경제 원리 목록 `fx-mechanisms/1`과 편집 기준 `currency-editorial/5`는 유지한다.

| 내용 | 담당과 검증 |
| --- | --- |
| 환율·차트·변화율 | 기존 계산 코드. 단위는 현지통화 / 달러이며 실제 관측일을 사용 |
| 관측시각 | 환율 행의 유효한 observedAt만 사용. 수집시각으로 대신하지 않음 |
| 수집시각·제공 경로 | 발행 입력에 저장한 fetchedAt과 API/JSON/EXCEL 구분. API라는 이유로 공식 자료라고 부르지 않음 |
| 기사 출처 | 검토된 유형으로 공식 자료·시장 보도·일반 원리를 표시. 유형이 없으면 미기록 |
| 달러 환산 | 사람 적용 승인을 받은 동일 USD 금액·미헤지·LOCAL_PER_USD 조건의 고정 문구 |
| 제목·요약·배경·관찰 | AI가 정제 원문과 허용된 원리로 작성. 공식성·관측시각이나 달러 환산 문구를 다시 만들지 않도록 지시 |

리포트는 발행 당시의 `marketData`를 사용한다. 현재 환율 데이터에서 예전 보고서의 출처·시각을 추정하지 않는다. 과거 비교 기록의 수집시각은 호환 표시할 수 있으나 실제 관측시각으로 쓰지 않는다.

새 AI 출력의 `implications`는 빈 배열만 허용한다. 승인된 달러 환산 적용이 있으면 코드가 다음 문구를 조립한다. 승인이 없으면 해당 부분을 넣지 않는다.

> 같은 달러 결제금액을 헤지하지 않고 비교한다면, 현지통화 환산액은 달러당 현지통화 환율에 비례합니다. 헤지·선결제·고정 계약 환율이 적용된 결제에는 이 비교를 그대로 적용할 수 없습니다.

고정 문구에는 적용 조건의 사실 ID와 원리 적용 ID를 연결한 대응표를 코드가 추가한다. RBA 출처는 일반 원리로 표시한다. 기업의 실제 결제·장부 평가·판매 효과를 관측한 문구로 바꾸지 않는다. 모델의 대응표 오류를 이 과정에서 고치거나 승인하지 않는다.

검토·교정에는 코드 작성 문장임을 표시하고 수정 대상으로 넣지 않는다. 조건 확인이 필요하면 미확인으로 남기며, 모델이 문구를 바꾸려 하면 중단한다. 고정 문구 변경은 코드와 검증 기준의 수정으로 처리한다.

## 문장 전체의 근거 확인

검토자는 문장을 원문 순서의 `subclaims`로 나눈다. 각 조각에 지지 여부·사유·원문 인용 위치와 해시 또는 승인된 원리 적용 ID를 기록한다. 조각을 합친 내용이 원래 문장을 빠짐없이 덮는지, 조각별 참조가 유효한지 코드가 확인한다.

‘정부는 공급 계획을 발표했고 실제 매각도 완료했다’라는 합성 문장에서는 발표와 집행 완료를 따로 대조한다. 발표의 유효한 인용이 있어도 집행 완료가 미지원이면 문장 전체를 교정 대상으로 분류한다. 문장 전체의 인용 하나만 붙이거나 일부 주장만 검사한 결과는 충분하지 않다.

전체 판정은 미확인 → 모순 → 미지원 → 부분 지지 → 지지 순으로 가장 약한 세부 판정을 따른다. 일부 미지원인데 문장 전체를 지지로 반환하거나 세부 주장 인용을 생략하면 검토 결과가 거부된다. [필수 교정과 문체 권고 기준](review-error-and-style-policy.md)은 그대로 적용한다.

이 검사는 문자 누락·참조·판정 일관성을 확인한다. 모델이 복합 의미를 충분히 나누거나 인용의 지지 범위를 정확히 판단한다는 보증은 아니다. 여러 의미를 한 조각으로 묶어 놓치는 경우는 저장 원고 평가와 실제 모델 시험에서 확인해야 한다. 모델 검토 결과는 게시 승인이 아니다.

## 기존 결과와 로컬 예시

기존 원고·점수·비용·입력·승인 기록은 각 버전으로 보존한다. 이전 보고서를 새 규칙 통과 결과로 바꾸지 않았다. 공개 URL과 기본 콘텐츠 구조를 유지하며 `marketData`, `assemblyVersion`을 선택 필드로 추가했다. 이전 편집 예시의 자유 작성 영업 의미는 오프라인 재생 경로에서 유지한다.

`node scripts/currency-report/preview-owned-content-local.js`는 저장된 칠레 원고를 재사용하고 달러 환산 부분만 코드로 조립하는 일회성 예시 명령이다. API·키·네트워크를 사용하지 않으며 입력·원고·비용 해시를 대조한다. 기존 파일과 이전 예시 결과는 덮어쓰지 않는다.

[A안 조립 예시](http://127.0.0.1:4175/local-experience.html?mode=live-local&design=a&run=CLP-2026-10-05-1791381782191#report/CLP/2026-10-05)는 편집 예시·미채택으로 표시한다. 기존 요약의 ‘공식 관측 이후’ 문제는 남아 있다. 이를 새 AI 결과나 내용 합격으로 표시하지 않았다. 과거 원고에 시각·제공 경로가 없어 해당 표시가 미기록인 것은 의도된 동작이다.

검토 입력과 결과는 `.local-reports/private/assembly-preview-v1/`, 정제된 예시는 `.local-reports/reviewable/CLP-2026-10-05-1791381782191.json`에 Git 제외로 저장했다. 원문 응답·검토 기록·사람 적용 승인·키는 화면 응답과 번들에 넣지 않는다.

## 완료한 검증과 다음 확인

- 타입·린트·55개 파일의 300개 테스트 정의, 394개 실행 사례와 운영/리포트 빌드가 통과했다. 정확한 중복 이름·동일 테스트 본문·자기 비교 감사는 검출 0건이다. 기존 운영 번들 804,454바이트 경고는 유지한다.
- 기존 담당 테스트를 확장해 AI 환산 문구 거부, 승인 누락 시 생략, 고정 문구와 대응표 결합, 코드 문구 교정 차단, 세부 주장 누락·과대 판정·인용 누락을 확인했다. 합성 계약 검사이며 실제 언어 이해 성능으로 계산하지 않는다.
- A안 PC·390px 모바일에서 시각·출처·단위 표시, 고정 문구, RBA 근거 펼침을 확인했다. 모바일 콘텐츠와 문서 폭은 모두 375px로 가로 넘침이 없다. 화면은 `artifacts/clp-code-assembly-desktop.jpg`, `artifacts/clp-code-assembly-mobile.jpg`에 저장했다.
- 원본 칠레 원고·snapshot·비용 기록의 SHA256은 이전 분류 문서와 같다. 새 호출과 비용은 0이다.

다음은 저장 원고로 세부 주장 분리가 실제 오류를 드러내고 정상적인 조건부 설명을 과도하게 차단하지 않는지 평가하는 단계다. 실제 생성·검토의 품질과 비용은 별도의 제한된 시험으로 확인한다. 운영 반영·원격 push·DB·메일은 이번 로컬 구현에 포함되지 않는다.
