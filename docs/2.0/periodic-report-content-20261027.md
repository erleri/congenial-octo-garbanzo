# 짧은 정기 점검 리포트 — 콘텐츠 구성안

2026-10-27 · 문서 설계 · 앱·생성 설정·운영 적용 없음

후속 검토 자료: [저장 자료로 작성한 세 가지 편집 샘플](periodic-report-samples-20261027.md). 실제 발행본이나 새 모델 출력과 구분한다.

후속 로컬 구현: [정기 점검본 공통 생성·검토 연결](periodic-check-generation-20261027.md). 상태 선택·집필 입력·조립·문장 검토를 연결했으며 실제 모델 품질·게시 승인은 미검증이다. 아래 구성 제안과 모델의 실제 생성 성공은 구분한다.

## 1. 확정된 발행 기준과 이 문서의 역할

사용자 확정: **CLP·MXN·BRL·COP**, 마지막 정상 환율 점검 보고서 대비 **절대 누적 변화 2% 이상**, 또는 **2주 미발행 후 정기 점검**. 정기 점검일은 한국 날짜 기준 마지막 유효 발행일에 14일을 더한 뒤 처음 오는 월요일이다. 월요일이면 당일이며 최초 예정 간격은 14~20일이다.

이는 조사·발행 검토의 계기다. 가격 상승·하락을 모두 보며, 근거·내용 검토·관리자 승인 없이 자동 게시하지 않는다. 급변·중요 사건 경로는 별도로 유지한다. 같은 날 여러 계기가 겹치면 한 건으로 합치고, 자료가 부족하면 다음 확인 때 이어간다. 운영 적용은 아직 보류한다.

**아래 분량·배치·문장 구성은 이번에 정리한 콘텐츠 제안**이다. 2% 정책의 확정과 구분한다. 기존 원인 분석 원고와 A안은 보존하며, 이 문서를 작성했다고 새 형식이 구현된 것은 아니다.

## 2. 독자에게 답할 세 가지

1. **지난 보고서 이후 환율이 얼마나 달라졌나?**
2. **그때 설명했던 흐름은 지금 어떻게 보아야 하나?**
3. **다음에는 무엇이 확인되면 판단이 달라질까?**

30~60초 안에 읽는 짧은 점검본을 권장한다. 본문은 대략 300~600자로 시작하되 수치·출처는 별도 표시한다. 글자 수를 합격 기준으로 만들거나 분량을 채우려고 문장을 추가하지 않는다.

정기 점검본은 **가격 비교와 확인 결과**를 전달한다. 큰 변화의 원인을 설명해야 할 상황이면 기존 원인 리포트로 범위를 넓히고 그 근거 기준을 적용한다. 원인 설명에 실패한 원고를 이름만 정기 점검으로 바꾸어 통과시키지 않는다.

## 3. 화면에 넣을 내용

| 순서 | 항목 | 담을 내용 | 분량·표시 제안 |
| --- | --- | --- | --- |
| 1 | 머리말 | 국가·통화, `정기 점검`, 실제 자료 기준일·관측일, 지난 기준 보고서 링크 | 날짜·시각 표시는 코드 담당. ‘오늘’ 대신 실제 날짜 |
| 2 | 한 줄 결론 | 지난 보고서 대비 확인된 변화와 가장 중요한 점검 결과 | 한 문장. `소폭`, `안정`, `변동성 확대` 등 평가도 근거가 있을 때만 |
| 3 | 숫자로 보는 변화 | 지난 보고서의 관측값 → 최신 비교 가능한 값, 누적 변화율과 현지통화 강약 | 3개 값 묶음. 공급자·가격 종류·단위·양쪽 관측일 연결 |
| 4 | 기존 설명의 현재 상태 | 주요 설명 최대 2개의 유지·변경·재확인 필요 상태와 이를 지지하는 새 확인 | 최대 2개 짧은 문단. 이전 문장 반복 대신 무엇을 확인했는지 제시 |
| 5 | 다음 확인 사항 | 확정된 발표·사건 최대 2개, 무엇을 확인하기 위한 것인지 | 일정·출처가 확인된 항목만. 업무 지시나 목표환율 제외 |
| 하단 | 근거·확인 범위 | 문장별 출처, 발표일·지표 대상 기간, 확인 범위와 중요한 한계 | 펼침 영역. 공통 주의사항은 한 번만 |

기존 차트는 같은 가격 기준으로 제공할 수 있을 때 사용하고 지난 기준 보고서의 관측 위치를 표시하는 안이다. 독립적인 새 대형 차트나 일간·월초·52주 수치를 모두 넣는 것은 기본 구성으로 요구하지 않는다. 기존 A안 구성요소 재사용 여부는 구현 단계에서 검토한다.

**영업 환경은 선택 항목**이다. 해당 통화·기간에 맞는 소비·구매력·수입 환산·금융 여건 자료가 새로 확인됐을 때만 1~2문장을 넣는다. 월간 통계는 대상 월을 표시하고 당일 환율 원인으로 쓰지 않는다. 회사 매출·마진·재고·가격 정책을 추정하지 않는다. 쓸 자료가 없으면 칸 자체를 생략한다.

## 4. ‘기존 설명의 상태’는 이렇게 판정한다

| 상태 | 필요한 근거 | 쓸 수 없는 표현 |
| --- | --- | --- |
| 유지 | 이번 점검 기간의 자료가 이전 설명의 핵심 조건을 계속 지지함 | 새 반대 기사를 못 찾았다는 이유만으로 ‘원인이 유지됐다’ |
| 변경 | 새 발표·수정·반대 근거가 이전 설명을 바꿈 | 단순 새 기사·동일 보도의 재전송을 새 사건으로 표시 |
| 재확인 필요 | 가격은 비교 가능하지만 특정 설명을 재확인할 자료가 부족함 | 근거 공백을 모델의 일반 상식으로 채움 |

출처에서 달러가 강해졌다는 가격 사실만 확인되면 ‘달러 선호 자금 유입’까지 확대하지 않는다. 전문가 한 사람의 견해를 시장 전체 결론으로 바꾸지 않는다. 기존 설명이 유지된다는 판단에도 어떤 최신 자료를 확인했는지 연결해야 한다.

‘재확인 필요’가 일부 항목에 있어도 유용한 숫자 비교와 검증된 다른 정보가 있으면 사실 중심 점검본을 검토할 수 있다. 다만 모든 설명·일정이 미확인이고 가격만 반복하는 원고라면 대시보드의 수치 갱신으로 충분한지 판단하고 발행을 보류한다. 점검 날짜를 지키려고 원고를 강제로 만들지 않는다.

## 5. 자료 상태에 따른 발행 범위

| 상황 | 처리 |
| --- | --- |
| 정상 가격·자료 확인 완료, 큰 새 사건 없음 | 변화 수치·검토 범위 내 설명 상태·확인된 다음 일정으로 짧게 작성 가능 |
| 가격은 정상, 특정 원인 근거만 부족 | 그 원인을 단정하지 않고 확인된 부분만 작성. 읽을 가치·범위를 검토 |
| 뉴스 수집 전체 실패 | ‘중요한 변화 없음’ 판단 금지. 조사 실패 기록. 다른 정상 자료로 유용한 사실 점검이 가능한지 별도 검토 |
| 최신 가격 지연·가격 종류 충돌 | 환율 점검 기준 보고서로 발행하지 않음. 기준점·기한 유지 |
| 큰 새 사건 또는 추가 2% 변화 확인 | 정기 계기와 통합해 원인 분석 필요성 검토. 적합한 원인 근거가 없으면 배경 확인 중 |
| 관리자 부재·검토 미완료 | 초안 대기. 이전 정상 공개본과 원래 날짜 유지 |

**‘추가 해석 없음’은 정상적으로 확인한 결과이지, 수집 실패의 다른 이름이 아니다.** 최신 조회시각을 갱신해도 기존 보고서 기준일은 바꾸지 않는다.

## 6. 반복 경고 대신 한 번의 확인 범위

본문은 사실과 설명에 사용한다. ‘이것만이 원인은 아니다’, ‘기여도를 계산하지 않았다’, ‘전문가 한 명의 견해일 뿐이다’를 문단마다 반복하지 않는다. 전문가 귀속은 해당 문장에 자연스럽게 두고 공통 확인 범위는 하단에 모은다.

하단에는 실제 필요한 항목만 표시한다: 비교 가격의 종류, 마지막 관측일, 검토한 발표의 기간, 중요한 미확인 사항. 해석을 바꾸는 조건이나 반대 근거는 해당 본문에 남긴다. 출처 발행시각이 늦은 해설을 앞선 가격 움직임의 직접 원인으로 쓰지 않는다.

## 7. 작성 틀 — 실제 보고서가 아닌 빈 템플릿

아래 대괄호는 확인된 사실로만 채운다. 빈칸을 모델이 추정해 채우지 않는다.

> **[통화] 정기 점검 · [자료 기준일]**  
> **[지난 보고서 이후의 변화와 핵심 확인 결과 한 문장]**
>
> **지난 보고서와 비교**  
> [이전 관측일·환율] → [최신 관측일·환율]  
> [누적 변화율] · [현지통화 강세/약세/변화 없음]  
> [단위·동일 가격 기준]
>
> **달라진 점 / 유지되는 흐름**  
> [이번에 확인한 사실 → 이전 설명에서 유지·변경되는 내용]. [출처]  
> [두 번째 핵심 확인이 있을 때만 추가]. [출처]
>
> **다음 확인 사항**  
> [공식 일정·발표일]: [앞선 설명의 어떤 조건을 확인하는지]. [출처]
>
> [근거 있는 새 영업 환경 정보가 있을 때만 추가]  
> [하단 펼침: 출처·발표일·지표 대상 기간·중요한 확인 한계]

## 8. 생성·검토의 역할

- **코드:** 가격 기준·관측일·변화율·표시 숫자·이전 보고서 연결. 일정은 확인된 일정 자료에서 표시한다.
- **자료 검토:** 이전 설명을 재확인할 자료, 설명 범위, 새 사실, 중요한 반대 근거, 출처 이용 범위를 정리한다.
- **집필 모델:** 기본 선택인 Sol이 채택된 사실과 확인 결과를 간결하게 설명한다. 호출 자체가 검색이나 승인 역할을 하지는 않는다.
- **검토·승인:** 내용의 모든 주장·기간·귀속 확인, 독자에게 전달할 가치 확인, 관리자 승인. 코드 형식 통과만으로 공개하지 않는다.

단순 숫자·일정만 있는 경우에는 코드로 사실을 표시하고 사람이 검토하는 방식도 검토할 수 있다. 정기 계기가 생길 때마다 유료 호출하는 것으로 확정하지 않는다. 실제 호출 정책·예산은 후속 결정이며 이번에는 호출하지 않았다.

## 9. 정기 점검본의 합격 기준 제안

필수 통과: 비교 가격이 동일 기준이고 최신성·관측일·계산이 확인됨, 모든 설명의 출처·기간·귀속이 적절함, 확인 실패를 무변화로 표시하지 않음, 근거 없는 원인·예측·업무 지시·개인정보가 없음, 관리자 승인 완료.

독자 검토: **변화 전달 / 점검 결과의 유용성 / 가독성 / 근거 충실도**를 각각 5점으로 평가하고 평균 4점·근거 4점 이상을 초기 목표로 제안한다. 필수 오류가 있으면 평균 점수로 통과시키지 않는다. 새 인과 설명이나 영업 문단을 억지로 요구하지 않되 숫자만 복제한 원고의 유용성을 높게 평가하지 않는다.

이 평가는 기존 원인 분석 평가와 목적이 다르다. 두 유형의 점수·승인율·교정 부담을 따로 기록하며 하나의 개선 점수로 합산하지 않는다. 위 평가표는 아직 사용자 독자 검토·실제 원고로 검증하지 않았다.

## 10. 다음 작업

다음에는 저장 자료로 **정상 점검 / 설명 변화 / 일부 근거 부족** 세 가지 짧은 사본을 만들어 분량과 유용성을 비교할 수 있다. 실제 최신 보고서·AI 생성 성공본으로 표시하지 않고 원고·비용 기록을 보존한다. 이 문서 작성에서는 샘플 생성·유료 호출·운영 반영을 수행하지 않았다.
