# LATAM FX 공통 리포트 규칙과 검토 기준

2026-11-02 **현재 런타임 검토 계약:** [공통 경로 마감 기록](common-runtime-closeout-20261102.md). 새 런타임은 근거 참조를 코드가 복원하는 runtime-review-refs/1을 사용하며 내부 문장·세부 주장 판정은 유지한다. 입력은 기존 키 이름/본문 사전 형식을 유지한다. 원고 스키마 크기의 검토 공간이 부족하면 선택적인 소비/정책 자료만 생략 사유를 기록하고 핵심·반대 근거는 보존한다. 날짜/기간이 맞는 연결된 시장 카드의 방향 표현은 내용 검토 대상으로 허용하되, 대시보드 기준환율 인과의 승인은 아니다. 원문 경로8은 대조한 문맥 위치와 직접 지지 위치를 구분하며, 조건·귀속 누락은 보류한다. 과거2~7 요청/원고는 원래 버전으로 보존한다. 실제 새 모델 품질·게시 승인은 별도다. 아래 과거 버전 표기와 작업 이력보다 이 변경을 우선한다.

2026-11-02 **현재 조사 범위·본문·측정치 기준:** [공통 보완·저장 검증](scope-body-common-repair-20261102.md)을 적용한다. 논리 조사 날짜와 실제 조회 한도를 분리하고 주말을 포함해 의도한 날짜를 유지한다. 수집→선별→추출/대조→시장 날짜 선택은 같은 날짜 집합을 쓰며 과거 검토 카드가 이를 축소하지 않는다. 목록의 조건·인용도 원문 순서대로 보존한다. `original-news-pipeline/7`의 추출·독립 대조와 공통 집필은 명목/실질·위험도/주식·실제/전망·가격 종류·기간을 구분하고 기존 scopeMatches 검사로 연결한다. 수치 없는 정상 환율 해설은 허용하며 전망/배경만으로 환율 설명 자격을 만들지 않는다. 아래 버전 표기는 과거 작업 당시의 이력이다.

2026-11-02 **날짜·사건·세션 공통 기준:** [6통화 입력 검증 마감](source-readiness-closeout-20261102.md)을 적용한다. `original-news-pipeline/3`·`news-event-date/2`는 대표 기준환율, 현지 기사 세션, 예정 정책행사, 통계 대상기간을 분리한다. 명시 날짜의 모순 없는 중복 필드는 허용하되 날짜 자체의 원문 지지를 완화하지 않는다. 관측과 FX 원인 해석이 함께 있는 가장 최근 검토 세션을 선택하고, 더 최신의 가격 나열이 이를 밀어내지 않는다. 원문 내부 가격 모순은 일반적인 시각 미상과 구별해 필수 대조 대상으로 둔다. 과거 `/2` 원응답·결합값·비용은 보존하며 새 지침의 모델 품질은 별도 실제 시험 전까지 미검증이다.

2026-11-02 현재 자동 생성 우선 기준: [환율 중심 생성·검토](fx-first-generation-20261102.md). 환율 관측·해설을 최초/정기/업데이트 모두 필수로 하며, 소비·정책 자료만으로 대신 집필하지 않는다. 이 변경은 아래 과거 경제 업데이트 예외보다 우선한다. 버전: fx-report-priority/1, shared-input-policy/3, claim-review/8, original-news-pipeline/2. 기존 기록은 당시 기준의 이력이다.

2026-10-29 **준비 검토 적용:** [반복 적용 방식과 검증](reference-review-application-20261029.md)의 `reference-materials/2`, `reference-material-review/1`을 사용한다. 선택 제외는 의존성이 없는 소비/정책/관찰 배경에만 허용하며, 제외 자료는 본문과 출처 전달 목록에서 함께 빠진다. 예정 일정은 반대 근거가 아니고, 최근 해설·장중/거래구간 관측·전일 사건을 구분한다. 수정 판본의 수집시각을 최초 게시시각으로 소급하지 않는다. 내부 제약을 경고 문장으로 반복 복사하지 않는다. 같은 입력·가격·해설일의 검토만 적용하며, 실패한 검토 파일을 미수정 입력으로 대체하지 않는다. 원인 승격·기간 변경·출처 이용/게시 승인은 이 단계에서 만들지 않는다. 아래 `/1`은 최초 연결 이력이다.

2026-10-28 **근거 재연결:** [통화별 준비·보류와 공통 검사](reference-material-reconnection-20261028.md)의 `reference-materials/1`을 적용한다. 명시적 시장 해설 대상일과 기준환율 저장 날짜를 구분하고, 다른 거래일의 시장 주장은 archive로 보존한다. 소비·정책 배경은 원래 발표일/대상 월·분기와 역할을 유지한다. 기존 범위/역할·용도·출처 검사 결과를 재검증하지만 새 독립 내용 승인으로 승격하지 않는다. archive·held·기존 가격·사용한 호출 승인은 집필 전송 대상에서 제외한다. 공통 기준환율 정책 `/3`과 기존 내용 품질 기준은 유지한다.

2026-10-28 **최신 사용자 결정:** [기준환율 공통 정책](reference-rate-policy-20261028.md)을 우선 적용한다. `shared-dashboard-report/3`, `dashboard-reference-policy/1`: 현재 API/대시보드 환율을 회사 기준과 같다고 가정해 개발하고 사용자가 추후 확인한다. 회사 공식 환율 인증은 아니며 `assumed_pending_user_confirmation`으로 남긴다. 6통화 대표값·차트·계획 대비·발행 판단은 같은 저장 기준환율을 사용하고, 종가는 필요한 설명에만 선택적으로 참고한다. 종가 미확인은 기본 가격 준비의 차단 사유에서 제외했다. 실제 카드 기간/주장 지지/출처 이용·품질·게시 승인은 유지한다. 아래 `/1`·`/2`의 ‘현지 거래일 미확인 시 일괄 보류’는 당시 이력이며 최신 정책에 합산하지 않는다.

2026-10-28 수집 기록 후속: 현재 공통 가격 검사 `shared-dashboard-report/2`는 [공급자·갱신시각·가격 성격 기록](price-provenance-hardening-20261028.md)을 읽는다. 선택한 저장 가격과 기록의 값이 일치해야 하며, 기록된 환산 참고값/일별 close를 국가별 현지 종가로 자동 승인하지 않는다. 기사 가격 대체 금지·주장별 근거·소비 배경 구분은 동일하다. 아래 `/1`은 최초 구현 이력이다.

2026-10-28 가격 기준 통일: [대시보드·리포트 공통 기준](shared-dashboard-report-standard-20261028.md)의 `shared-dashboard-report/1`을 새 6통화 준비에 적용한다. 대표 환율은 대시보드 저장 데이터와 동일하게 선택·계산하며 기사 가격은 참고만 허용한다. 공급자·현지 거래일·가격 종류를 확인하지 못하면 직접 원인 연결을 보류한다. 이전 별도 가격 원고·검토는 과거 이력으로 보존하며 새 기준의 승인으로 넘기지 않는다. 아래 편집/내용 기준은 유지한다.

2026-10-27 정기 점검 집필 보강: [결론형 제목·경고 배치 기준](periodic-writing-rules-20261027.md)의 `periodic-writing/2`를 적용한다. 제목·요약은 확인한 내용의 결론, 설명은 귀속된 경로·추가 의미를 전달하고 범용 한계는 코드가 별도 영역에 한 번 표시한다. 중요한 조건은 보존하며 기존 원고와 점수는 변경하지 않는다.

2026-10-27 정기 점검 연결: [정기 점검본 공통 생성·검토](periodic-check-generation-20261027.md)의 `periodic-check/1`을 선택적으로 적용한다. 기존 설명 재확인·설명 보완·일부 미확인을 구분하며, 정기 점검에 새 사건·원인 전환을 강제로 요구하지 않는다. 일반 환율 설명·경제 업데이트의 기본 경로와 기존 기록은 보존한다.

## 현재 기준 — 2026-10-27 역할 분리

현재 버전은 `currency-input/10`, `writer-links/1`, `report-reasoning/4`, `currency-editorial/9`, `currency-rules/7`, `claim-review/7`이다. 아래 날짜별 실험 기록의 과거 지침을 현재 프롬프트에 합산하지 않는다. 공통 기준은 환율 설명과 경제·소비 업데이트에 적용하되, 경제 업데이트에 환율 원인을 요구하지 않는다.

**확인한 자료 → 채택 범위·조건 → 집필 → 코드의 문장별 검토 준비 → 내용 검토 → 별도 게시 승인** 순서다.

| 담당 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 입력 준비 | 사실·귀속 견해·기간·가격 기준·조건·허용 원리 보존, 설명 후보 선별 | 없는 현지 연결을 상식으로 보충, 기사 수로 중요도 판단 |
| 집필 AI | 제목·요약·설명·관찰과 위치별 출처 연결 작성 | 문장 분리·긴 대응표·자기 점수·승인 작성 |
| 코드 | 수치·시각·출처 표시, 문장 분리, 위치별 출처를 검토 후보로 연결, 구조·ID 검사 | 내용 지지·인과·순위 판정, 원고 자동 수정 |
| 내용 검토 | 문장의 모든 주장과 근거·조건 대조, 오류와 편집 개선 구분 | 출처 ID·정규식·길이를 정확도의 증거로 사용 |
| 승인 | 검토와 품질 평가를 확인하고 별도 승인 | 구조 통과를 게시 승인으로 승격 |

집필은 **새 사건 → 출처가 설명한 반응 경로 → 확인 가능한 통화 연결**을 따른다. 현지 연결이 없는 글로벌 요인은 맥락으로 제한하거나 생략한다. 근거 없는 칠레 현지 달러 수요로 바꾸지 않는다. 두세 문장은 권장일 뿐 최소 글자 수·할당량이 아니다. 최대 세 배경·두 관찰을 채우지 않아도 된다.

전문가 이름은 본문에 귀속한다. 실제 조건·반대 근거는 의미가 달라지는 위치에 유지한다. 기여도 미산출 같은 공통 한계는 별도 영역, 발행 시각과 집계 이후 자료 여부는 출처 표시가 담당한다. 시각 경고를 지웠다는 이유만으로 오류가 되지 않지만, 사후 해설을 선행 신호로 쓰면 필수 교정이다.

### 현재 입력·출력 계약

기존 `evidence`의 사실·귀속 견해, `scopeCards`의 채택 범위, `researchBrief` 또는 `explanationCards`, 승인된 `applicableMechanisms`를 재사용한다. 같은 집필 지시를 사용자 입력과 시스템 지침에 동시에 넣지 않는다. 카드의 금지 범위는 복사할 경고문 목록이 아니다.

환율 집필의 `ruleLedger` 이름은 유지하되 신규 출력은 `version=writer-links/1`이다. 각 위치에 `target`, `kind`, `evidenceIds`, `mechanismId`, `applicationId` 다섯 항목만 제출한다. 제목·요약·소제목·본문의 연결 누락·중복·없는 위치·없는 출처·미승인 원리를 거부한다. 경제 업데이트도 `writingContractVersion=writer-links/1`과 위치별 `target/evidenceIds`를 사용한다.

코드는 본문을 바꾸지 않고 문장별 검토 대상을 만든다. 상위 위치의 출처는 각 문장의 **검토 후보**이며 지지 판정이 아니다. 준비 상태는 `candidate_only/unverified`다. 문장 구분과 세부 주장 분해는 다르므로 검토자는 문장 안의 모든 주장을 다시 확인한다. 명시적으로 요청된 교정도 같은 문장 경계와 원고 해시를 사용한다.

모델이 `newInformation/transmission/currencyConnection/eventKey/pathwayKey/watchPurpose`를 본문과 중복 작성하지 않는다. 내부 대응표의 이 값은 비어 있으며 R02·R05·R08의 **내용 검토**는 계속 필수다. 작성 부담을 없앤 것이 경제적 연결·중복·관찰 목적의 품질 기준을 없앤 것은 아니다.

### 판정과 보존

- 형식 오류: 필드·출처 연결·수치·기간·개수 검사와 이유를 기록한다.
- 필수 내용 교정: 잘못된 귀속·인과·단위·시점·전체 순위·현지 수급 확대. 제목과 요약도 같은 기준이다.
- 편집 개선: 지지된 설명의 반복 경고·추상적 제목·장황함. 사실 오류와 구분하며 별도 독자 품질 평가에는 반영할 수 있다.
- 미검증: 자료·조건·대조가 부족함. 거짓이나 통과로 바꾸지 않는다.

평균 4/5·근거 충실도 4/5·중대 오류 0건과 사람의 내용 검토는 유지한다. 기존 원고·점수·비용·보류 기록을 그대로 두며 새 구조의 재생 결과는 별도 호환성 검사다. 이번 작업은 유료 호출·새 집필·운영 반영이 없다.

저장 AI 원고 두 건과 수동 편집본 한 건의 본문을 보존해 재생했다. 고정 판단 11사례에서 ‘전체 중심 요인’·‘현지 달러 수요’ 확대는 필수 교정, 반복 경고는 편집 개선, 실제 경제 조건은 유지로 분리했다. 이는 검토 판단의 처리 검증이며 모델의 자율 의미 판단 성공이나 새 원고 품질 개선이 아니다.

## 경제 지표의 설명 범위 검토

공통 카드의 [생성·검토 코드 연결 결과](economic-scope-implementation-20261011.md)는 `evidence-scope/1`을 적용한다. 신규 경제 요청에는 검토된 범위 카드를 요구하고, 문장 대응표의 출처가 해당 블록에서 빠지면 검토에서도 참조 오류로 남긴다. 실제 모델의 새 입력 품질은 아직 미검증이다.

2026-10-11 [주장 범위와 근거 카드 검토](economic-scope-review-20261011.md)는 기존 R03·R04·R06·R07·R10을 순위, 지수와 가계, 자료 부재, 교차 기간, 제목에 구체적으로 적용한다. 확인된 지수 구성과 조건부 설명은 유지하고, 근거 부족을 거짓으로 단정하거나 문체 문제를 사실 오류로 처리하지 않는다. 이 독립 검토 이후 위 코드 연결을 수행했다. [카드 보완안](economic-evidence-card-proposal.json)은 과거 요청에 자동 전송되지 않으며 명시적 원문 대조와 새 검토 결합을 거쳐 사용한다.

## 2026-10-11 당시 생성과 세부 주장 검토

## 조건부 환산 적용과 이전 실제 시험

당시 대응표는 `currency-rules/3`, 입력은 `currency-input/3`이었다. 편집 `currency-editorial/5`, 원리 목록은 `fx-mechanisms/1`이었다. 달러 결제 환산 원리는 기사 근거와 구분하여 계산된 사실(`LOCAL_PER_USD`·spot·비교 fact ID)과 명시적 가정(같은 달러 금액·미헤지), 예외(헤지·선결제·고정 계약 환율)를 연결한다. 이 형식은 해당 산술 원리에만 허용하며 사람 적용 승인과 해시 결합을 계속 요구한다. 기사에서 실제 기업 노출을 확인한 것으로 표시하지 않는다.

원리 문장의 기사 참조는 비어 있을 수 있지만 ledger에는 승인된 application과 조건의 fact ID를 연결해야 한다. 나머지 해석의 기사 근거 요건과 실제 시장 배경의 출처 요건은 유지한다. 일반 원리의 공식 자료는 공개 근거 영역에 따로 표시한다.

DF·La Tercera의 검토한 칠레 기사 두 URL은 본문 추출·문맥 선택을 연결했다. 다른 URL의 일반 수집기를 완료한 것으로 간주하지 않는다. [실제 네 단계 시험](clp-editorial-trial-results.md)은 $0.044439750로 끝났으나 내용 품질은 보류다. 같은 모델의 검토가 공식성·관측시각·설명 범위 확대를 놓쳤으므로 모델 통과를 내용 승인으로 삼지 않는다.

## 2026년 10월 7일 근거 대조와 제한된 교정

이 단계 당시 공통 입력은 `currency-input/3`, 편집은 `currency-editorial/5`, 대응표는 `currency-rules/2`, 원리는 `fx-mechanisms/1`이었다. 과거 원고의 당시 버전·점수·비용·승인은 보존한다.

조사·집필·교정을 분리하는 [Stanford STORM](https://github.com/stanford-oval/storm), 부족한 근거를 확인하는 [Google 연구 에이전트 예제](https://github.com/google-gemini/gemini-fullstack-langgraph-quickstart), 주장과 원문을 대조하는 [ReportBench](https://github.com/ByteDance-BandAI/ReportBench)를 참고해 기존 Node 경로에 문맥 보존과 문장별 대조·교정·재검토를 추가했다. 외부 프레임워크나 추가 검색 API는 설치하지 않았다. 이 사례들이 환율 설명의 정확성을 보증하지는 않는다.

### 근거 전달과 주장 대조

`extractArticleBlocks`는 어댑터가 지정한 본문 HTML 조각에서 문단·인용·인용 안의 귀속을 추출하고 추천 영역을 제외한다. 임의 웹페이지 전체에서 본문을 자동 판별하는 파서는 아니다. 사이트별 본문 영역 지정은 원문 수집 어댑터의 후속 작업이다.

기사 어댑터는 본문을 순서 있는 `paragraph`·`quote` 블록으로 준비한다. 중요한 구절을 명시적으로 선택하면 앞뒤 블록도 보존한다. 추천 기사 템플릿은 제외하고 선택 근거가 모두 사라지면 실패한다. 본문과 전달 구절의 해시를 따로 기록하며 설명 카드도 이 해시에 연결한다. 원문 확인 기록 없이 문맥을 전송하거나 변경된 문맥에 옛 검토를 재사용하지 않는다.

블록 선택은 진실 판정이 아니다. 인용 누락·불완전한 발췌는 미확보 상태로 남기며 현재 페이지를 당시 보관 원문으로 표시하지 않는다. 기존 메타데이터 수집기는 후보 탐색용으로 유지한다. 본문 블록 선택과 원문 검토는 별도 어댑터 입력이며 자동 크롤링 완료로 보고하지 않는다.

제목·요약·소제목·본문을 문장별로 대조한다. 판단에는 원고 위치·해시, 원문 구절의 출처·위치·해시·인용, 원리 적용 조건과 이유가 필요하다. 출처 ID나 요약만 있으면 내용 검토는 미검증이다. 인용 위치 검사는 원문이 주장을 실질적으로 지지하는지 판단하는 의미 검토를 대신하지 않는다.

| 판단 | 편집 처리 |
| --- | --- |
| `supported` | 의미·기간·귀속·조건이 지지됨. 유지하거나 문체만 `refine` |
| `limited` | 현재 표현이 지지 범위를 넘어섬. 반드시 `rewrite` |
| `unsupported`·`conflicting` | 근거 없음·충돌. 수정 또는 삭제 |
| `unverified` | 원문·조건·검토 부족. 승인으로 승격하지 않음 |

발표를 집행으로, 가격 반응을 거래량으로, 당일 변화를 장기 추세로 확대하면 수정한다. 같은 분석가·기관·통신사를 인용한 보도는 독립 검증 횟수로 세지 않는다. 기사와 저장 환율의 시점이 다르면 본문에서 구분한다. 같은 미헤지 달러 대금의 환산 부담은 검증된 원리와 적용 조건으로 설명하되 실제 수입 단가·가격 전가·판매·마진 효과로 확대하지 않는다. 정부의 매도 사실은 허용하고 매매 추천·업무 지시는 차단한다. 정규식으로 잡히지 않는 우회 표현은 내용 검토 대상이다.

### 한 번 교정하고 다시 대조하는 흐름

`runEditorialWorkflow`는 명시적 편집 작업에서 검토 → 수정 대상 선택 → 한 번 교정 → 자동 검사 → 새 원고 전체 대조를 수행한다. 생성 실패 뒤 자동으로 호출되지 않는다. 사실 오류·업무 지시는 필수 수정이며 문체 개선은 기본적으로 선택 대상에서 제외한다. 부분 검토에서 확인한 결함은 고칠 수 있지만 나머지 문장은 미검증으로 남는다.

교정은 지정 문장만 변경·삭제한다. 사실·차트·출처 ID·기준일을 바꾸지 않고 모든 변경을 원래 위치에 동시에 적용한다. 오래된 해시·지정하지 않은 수정·두 번째 교정은 차단한다. 기존 대응표와 사람 검토는 무효화하고 새 검토를 요구한다. 재검토 실패 시 추가 교정이나 모델 교체로 반복하지 않는다.

검토·교정 콜백에는 공개 근거와 구조화 출력 계약을 전달한다. 실제 제공자·모델·개인정보 조건·예산 예약·비용은 승인된 호출자가 담당한다. 오프라인 명령은 키를 읽거나 API를 호출하지 않는다. 모델 검토는 `origin=agent`이며 사람의 승인이나 게시 승인을 만들지 않는다.

### 로컬 명령

`npm run report:edit -- --action prepare --input input.json`은 private 폴더의 `{packet, content}`로 검토 계약을 준비한다. `--action review --review review.json`은 대조 결과와 수정 계획을 확인한다. `--action apply --review review.json --patches patches.json`은 교정 예시와 새 검토 입력을 저장한다. 파일명은 `.local-reports/private` 기준으로 안전한 하위 폴더도 허용하며 결과는 새 시각 폴더에 기록한다. `--refinements`는 문체 개선을 포함하는 명시적 선택이다.

`npm run report:edit:replay`는 저장된 10월 5일 칠레 원고의 알려진 결함을 교정하는 예시다. 실제 AI 재생성이 아닌 에이전트 작성 교정이며 원본·원문·과거 비용을 보존한다. 자동 검사 통과와 내용 재검토 미완료를 따로 기록한다. 누락된 원문을 확보한 것처럼 추가하지 않는다. 공개 저장 경계에서는 원문 문맥·대응표·원리 적용·검토 입력을 제외한다. 화면 계약과 URL은 유지한다.

아래 날짜별 기록은 당시 결과다. 현재 코드의 검증 결과와 실제 AI 품질 검증은 진행표에 따로 기록한다.

2026-10-05 실제 계약 시험에서 Azure가 무타입 규칙 버전 필드를 거부했다. 명시적 문자열 단일값 enum과 모든 kind의 문자열 타입을 추가했고, 유료 요청 전 제공자 스키마 검사를 연결했다. 로컬 AJV 통과는 제공자 스키마 수락을 보장하지 않았음이 확인됐다. 실제 오류 재현을 포함한 전체271개 테스트와 빌드는 통과했지만, 수정본의 실제 모델 응답·내용 품질은 아직 미검증이다. 실패 요청·원고 부재·비용 예약은 [진행표](release-backlog.md)에 기록했다.

영업·손익·가격 관리 독자가 공개 정보로 변화의 배경과 소비 환경을 이해하도록 하는 공통 계약이다. 특정 칠레 원고의 문구를 정답으로 외우게 하지 않는다. 2026-10-06 입력 개선 이후 새 생성은 `currency-input/2`, `currency-rules/2`, 편집은 `currency-editorial/4`, 경제 원리는 기존 `fx-mechanisms/1`을 사용한다. 기존 규칙 버전의 기록·본문·점수·비용·화면은 당시 상태로 남긴다.

## 입력 프롬프트 개선 2026년 10월 6일

공통 프롬프트를 역할·근거 읽기·독자용 설명·출력 계약·주장 대응표로 정리했다. [OpenAI 공식 안내](https://developers.openai.com/api/docs/guides/prompt-engineering)의 지침·예시·맥락 분리를 참고하되, 특정 모델의 품질 향상을 보증하는 것으로 해석하지 않는다.

- **설명을 소개하지 말고 설명한다.** ‘전문가가 수급 경로를 설명했다’로 끝내지 않고 누가 무엇을 바꾸고 어떤 공급·기대·환산 부담에 연결되는지 본문에 쓴다. 원문에 그 연결이 없으면 해당 항목을 생략한다.
- **기사 해석과 일반 원리를 구분한다.** `applicableMechanisms`가 비어 있어도 원문이 직접 설명한 경로는 채택 범위 내에서 출처에 귀속해 풀어 쓸 수 있다. 빈 배열을 임의 원리의 허가나 사람의 승인으로 바꾸지 않는다.
- **문체 예시를 사실에서 분리한다.** 좋은 설명과 빈약한 설명의 합성 예시를 `writingExamples`로 제공한다. 예시는 출처 ID나 사실이 아니며 대응표 근거로 사용할 수 없다. 출력 스키마의 출처 ID 목록은 실제 근거에서만 만든다.
- **시간 정보를 잃지 않는다.** 실제 환율 `observationAt`과 기사 `eventAt`을 전달한다. 없으면 `null`이며 수집시각으로 대체하지 않는다. 기사 발표시각·대상 기간·채택 범위를 함께 보존한다.
- **숫자와 대응표 지시의 모순을 해소한다.** 숫자·날짜 금지는 읽을 본문에 적용한다. JSON의 버전·ID·대응표 날짜·점 표기 위치는 스키마대로 작성한다.

원문에서 연결을 추출할 때는 기존 `explanationCards`에 사건, 기대 대비 차이의 확인 여부, 전달 경로, 통화·소비 연결, 귀속, 원문 위치, 제외 범위를 기록한다. 원문 검토와 출처 해시가 일치해야 전송할 수 있다. 카드 생성은 자동 원리 승인이나 자동 내용 합격이 아니다. 원문 설명을 확보하지 않은 채 프롬프트만 강화해서 빈 연결을 만들게 하지 않는다.

이번 로컬 칠레 입력에는 [재무부 매각 보도](https://www.emol.com/noticias/Economia/2026/10/05/1213245/dolar-mercado-cambiario-local.html)의 추가 달러 공급 경로와 [전주 회고](https://www.emol.com/noticias/Economia/2026/10/04/1213173/economia-dolar-mercado-local-cambiario.html)의 미국 금리·자금 유입, 조건부 수입 비용 경로를 별도 카드로 준비했다. 구리 가격 보도에 없는 통화 연결은 추가하지 않았다. 저장된 운영 환율·차트·게시 차단 판정은 유지한다.

새 입력은 자료와 예시가 추가되어 전체 길이가 늘었다. 문자·바이트 수는 토큰이나 실제 청구액이 아니다. 다음 유료 시험 전 전체 요청의 예산을 다시 계산해야 한다. 기존 원고·검토 기록은 그대로 보존하며 새 입력의 실제 생성 품질은 아직 미검증이다.

## 2026-10-06 개정 — 읽을 가치를 유지하면서 설명을 다듬기

이번 개정은 새 원고 생성이나 기존 Gemini 원고 수정이 아니다. 무료·유료 공통 생성 지침, 출력 스키마의 설명, 독립 검토 기준에 연결했다. 과거 대응표 표기 오류를 고쳐 합격시키거나 과거 요청의 예산을 늘리지 않는다.

### 작성 기준의 구체화

- **제목:** ‘요인 목록’보다 근거 있는 핵심 해석을 먼저 전달한다. 본문에서 가능한 배경으로 설명한 것을 제목에서 확정 원인으로 바꾸지 않는다. 요인 순위가 미확인이라면 가장 중요한 원인이라고 쓰지 않는다. 현재 통화 방향은 기존 코드 표시를 사용한다.
- **배경:** 첫 문장에서 새 정보가 무엇인지 밝히고, 전달 경로와 통화 연결을 본문에도 쓴다. 대응표에만 연결을 숨기지 않는다. 예상 대비 차이·실제 시장 반응은 확인된 경우만 쓴다. 출처 또는 승인된 원리가 빈 연결을 뒷받침하지 못하면 항목을 줄이지, 일반 상식으로 채우지 않는다.
- **관찰:** 변수 이름보다 ‘어떤 변화로 앞선 설명을 확인할 것인가’를 보여 준다. 높은 수준이라는 상태와 기대·가격의 변화를 구별한다. 지지·약화 양쪽을 억지로 채우거나 미확인 기준·일정·시차·전망을 만들지 않는다. 근거가 한쪽만 있으면 한쪽만, 판단 기준이 없으면 생략한다.
- **지면:** 새 정보와 이해에 필요한 경로에 쓴다. 긴 글·문장 수·항목 수 자체는 품질이 아니다. 같은 주의문은 반복하지 않되 실제 반대 근거와 중요한 조건은 남긴다.

다음은 구조 비교용 **합성 예시**이며 조사된 사건이나 승인 원고가 아니다. 개선 문장도 근거가 해당 관계를 지지할 때만 사용한다.

| 대상 | 다듬을 표현 | 개선 구조 |
|---|---|---|
| 제목 | ‘물가·원자재·국내 여건이 함께 맞물린 시장’ | ‘물가의 구성 차이가 바꾼 금리 기대’ — 본문에서 확인한 핵심 해석을 먼저 |
| 배경 | ‘물가가 높았고 달러를 지지했다’ | ‘보도는 물가의 예상 대비 차이를 전했다 → 분석가가 금리 기대 재평가를 설명했다 → 같은 보도에서 통화와의 관계를 연결했다’ |
| 관찰 | ‘수익률과 달러 지수를 지켜본다’ | ‘근거가 허용하는 수익률·달러의 후속 변화로 앞선 금리 기대 해석과 실제 시장 반응이 맞물리는지 판단한다’ |

### 읽을 가치와 합격 판정의 분리

새 검토의 `readerReview`는 네 기준(`headlineConclusion`, `transmissionSpecificity`, `diagnosticWatch`, `informationEconomy`)별로 이유와 결정을 기록한다. 관찰이 근거 부족으로 생략됐다면 생략이 적절한지 검토하며 개수를 채우도록 요구하지 않는다.

| 결정 | 의미 | 검사 효과 |
|---|---|---|
| `keep` | 읽을 가치가 있고 기준에 부합 | 독자 관점 `usable` 가능 |
| `refine` | 읽을 만하지만 특정 부분을 개선하면 더 좋음 | `usable` 유지, `needsRefinement=true`. 이것만으로 보류하지 않음 |
| `rewrite` | 핵심 설명이 비어 있거나 독자에게 의미가 전달되지 않음 | `needs_revision`, 해당 내용 규칙 보류 |
| 누락·옛 버전·모델 자기 평가 | 별도 판단이 없음 | `unverified` |

읽을 가치 판단은 **사실 정확성·출처의 실질적 지지·형식·게시 권한을 승인하지 않는다.** 읽을 만해도 근거 오류나 대응표 오류가 있으면 그 검사 결과는 유지한다. 반대로 형식 미통과를 ‘읽을 가치 없음’으로 해석하지 않는다. 전체 통과에는 기존 문장별 근거 검토, 필수 내용 항목, 평균 4/5·근거 4/5·중대한 오류 0건이 여전히 필요하다.

새 검토 해시에는 편집 버전도 포함한다. 옛 검토를 새 기준의 승인으로 재사용하지 않는다. 정규식은 좁은 검토 신호일 뿐이며 문장을 고치거나 내용 합격을 자동 판정하지 않는다.

### 형식 안내와 변경 범위

대응표 위치는 `drivers.0.text` 같은 점 표기를 지침과 스키마 설명에 명시했다. `drivers[0].text`를 자동 변환하거나 허용한 것은 아니다. 공개 보고서 구조·URL·A안·기존 원고·비용 기록은 유지한다.

오프라인 재평가는 이전 기록과 별도 파일이다. 저장된 Gemini 원문에도 나열형 제목과 수준 유지형 관찰의 신호가 나타났으나, 새 대응표 및 사람 검토가 없는 원고를 새 규칙 통과로 간주하지 않는다. 이것은 규칙 회귀 확인이지 재생성 품질 시험이 아니다.

공통 평가뿐 아니라 편집 채택 및 비교 선택도 같은 독자 검토를 요구한다. 불완전한 검토나 재작성 판단을 비교 경로로 우회해 기본 원고로 선택하지 않는다.

검증: 새 경계 6개 포함 49파일/257개 테스트 정의/330개 실행 사례, 타입·린트·운영/리포트 빌드 통과. 합성 고정 16사례의 예상 결과 일치, 저장 원고 4건 별도 재평가. 비밀값·비공개 HTTP 경계 및 기존 입력 일치 확인. A안 산출물은 기존과 동일하며 새 시각 시험은 하지 않았다. 추가 모델 호출·비용 0, 기존 번들 용량 경고 유지.

## 작성 기준

아래 합격 예는 구조를 보여 주는 합성 문장이다. 실제 사건이거나 승인된 시장 설명이라는 뜻이 아니다. 원문이 뒷받침할 때만 같은 구조를 사용할 수 있다.

| 규칙 | 합격 기준과 예 | 보류할 예 |
|---|---|---|
| R01 새 정보 | 첫 문장에 새 사건. “보도는 정책 기대가 바뀌었다고 전했다.” 예상과의 차이는 비교 자료가 있을 때만 | “시장은 복잡하다.” 미확인 서프라이즈 |
| R02 연결 | 새 정보 → 상대 수익률 등 전달 경로 → 해당 통화와의 연결을 근거로 설명 | 제목 반복, “국내 요인도 더해졌다”로 종료 |
| R03 지위 | 관측 사실·출처 귀속 해석·조건부 일반 원리를 구분 | 일반 원리로 오늘의 직접 원인 확정 |
| R04 선별 | 기간·통화 적합성, 원문 직접성, 새 정보 순서. 오래된 소비 자료는 맥락으로만 | 보도 건수·자극적 제목을 중요도 근거로 사용 |
| R05 중복 | 동일 사건과 전달 경로는 합침. 배경 1~3개, 의미·관찰 각각 0~2개 | 같은 금리 해석으로 세 항목 채우기 |
| R06 영업 의미 | “명목소득이 물가를 따라가지 못한다면 구매력에 부담.” 조건·근거를 함께 제시 | TV 수입 비중·판매·마진 추정, 소비 효과가 환율보다 빠르다는 미확인 비교, 가격 지시 |
| R07 한계 | 공통 관측 한계는 한 번. 특정 반대 요인은 해당 설명 옆에 | 매 문단 절반을 “이것만이 아니다”로 채우거나 반대 증거 삭제 |
| R08 관찰 | 어떤 반응이 어느 설명을 지지·약화하는지 명시 | “연준을 지켜봐야 한다”만 반복 |
| R09 보류 | 새 관측·설명 근거가 없으면 이전 기준일 유지 | 실패 결과를 새 최신 보고서로 대체 |
| R10 대응 | 제목·요약·소제목·본문의 모든 문장을 주장 대응표로 연결 | 존재하는 출처 ID만 붙이고 실제 지지 여부 미확인 |
| R11 기초 검사 | 코드 계산 수치·방향, 스키마·날짜·비밀값·금지 표현 검사 | AI가 수치·회사 실적·목표환율을 추가 |
| R12 기록 | 규칙·원리 버전, 입력/원고 해시, 적용 조건, 독립 검토 | 모델의 자기 승인, 옛 점수 재사용 |

목표는 경고를 없애는 것이 아니라 설명에 필요한 경고만 남기는 것이다. 주의문 비율은 검토 신호이지 삭제 명령이나 진실 판정이 아니다. 반대 요인이 실제로 중요하면 본문에 유지한다.

## 생성과 검토의 계약

1. 기존 계산기로 관측·보간·방향·기준일을 확인한다. 새 정보가 없거나 급변 원인 시각을 확인할 수 없는 기존 발행 차단은 유지한다.
2. 정제된 자료를 기간·통화·원문 확인·발표 최신성 순으로 정렬한다. 최신성은 새 설명의 대용 지표일 뿐이다. 실제 새 정보·중요도는 R01/R04/R09 내용 검토로 결정한다.
3. 사용할 원리는 **로컬 검토자가 작성한 적용 기록**에서만 선택한다. 모든 조건의 근거 ID·설명, 반대 요인 검토, 통화·날짜·입력 해시·원리 목록 해시·검토 결과가 필요하다. 원리 자료는 당일 원인 후보에 섞지 않는다.
4. 모델은 동일한 공통 지시와 스키마로 본문 및 `ruleLedger`를 제출한다. 문장별 위치와 원문 인용, 사실/출처 ID, 종류, 원리/적용 ID, 사건/경로 식별자, 새 정보·전달·통화 연결·관찰 목적을 기록한다. 소제목·요약도 예외가 아니다.
5. 자동 검사 후 원고·입력·원리·대응표를 묶은 `binding`을 만든다. 별도 검토자는 각 문장이 출처로 지지되는지 이유와 함께 기록한다. 모델의 대응표 자체는 증거도 승인도 아니다.
6. 필수 내용 항목 전부, 문장별 지지 확인, 평균 4/5 이상·근거 4/5 이상·중대한 오류 0건과 새 독자 관점 검토를 충족해야 검토상 통과다. 독자 검토의 `refine`은 재작성 요구가 아니다. 그래도 이 도구는 게시 승인을 만들지 않는다.

검사 결과는 `automaticStatus`, `semanticStatus`, 전체 `status`를 각각 기록한다. 값은 `pass`(통과), `hold`(보류), `unverified`(미검증)다. 별도로 `readerReview.status`의 `usable`, `needs_revision`, `unverified`와 항목별 이유가 남는다. 자동 검사와 읽을 가치 판단을 사실·내용 통과로 승격하지 않는다.

평가 설계는 [OpenAI의 용도별 평가와 사람 판단 병행 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 참고했다. 현재 정규식은 특정 반복·효과 비교를 찾는 좁은 신호다. 비슷한 의미를 다른 말로 쓴 경우까지 잡는 의미 판별기로 주장하지 않는다.

## 로컬 실행과 기록

재평가는 `npm run report:rules`로 실행한다. 키를 읽거나 네트워크에 접속하지 않는다. 결과는 Git에서 제외된 `.local-reports/private/common-rules/<실행시각>/evaluation.json`에 새 파일로 저장한다. 이전 기록·승인·비용·본문은 수정하지 않는다.

생성 입력의 일반 원리 적용 자료는 `.local-reports/private/<이름>.json` 배열로 준비하고 기존 로컬 명령의 `--applications <이름>.json`으로 명시한다. `syntheticApplication`의 필드 구조는 참고할 수 있지만 그 테스트 승인값을 실제 자료에 복사해 승인하지 않는다. 실제 검토자가 원문·조건·반대 근거를 채워야 한다. 조건 누락·해시 불일치·버전 변경은 요청 전에 중단한다.

주요 구현:

- `rules.js`: 규칙 버전, 대응표, 적용 검사, 두 층의 평가와 해시.
- `mechanisms.js`: 여섯 원리의 출처·조건·금지 단정.
- `openrouter.js`: 무료 모델에 공통 입력/출력 필수 적용.
- `paid-comparison.js`: 신규 유료 요청에도 같은 검사. 과거 형식은 오프라인 재생 전용; 오래된 요청으로 실제 비용을 쓰기 전에 차단.
- `rule-fixtures.js`, `rules.test.ts`: 합성 고정 사례와 검사 회귀. 테스트의 human 표시는 검토자 테스트 대역이며 사람의 실제 승인이 아니다.
- `evaluate-rules-local.js`: 기존 칠레 결과 별도 재평가. 옛 원고에는 새 대응표가 없으므로 통과로 간주하지 않음.

로컬 검토 파일은 신뢰하는 개발자의 자료다. `origin: human`과 해시는 사용자 인증이나 전자서명이 아니다. 운영 승인 보안으로 재사용하려면 서버 권한 검증과 감사 기록을 별도로 연결해야 한다. 이번 작업에서는 운영 승인 경로를 변경하지 않는다.
