# LATAM FX 2.0 리포트 생성과 보류 기준안

> 2026-10-27 후속 결정: CLP·MXN·BRL·COP의 누적 2%와 한국 날짜 14일 경과 후 첫 월요일 정기 점검을 채택했다. 현재 기준은 [발행 주기 상세 설계](publication-cadence-design-20261027.md)를 따른다. 아래 원래 설계·검토 기록은 이력으로 보존하며, 운영 설정은 변경하지 않았다.


환율과 핵심 발표는 매일 확인하고, 기존 설명을 바꿀 새 정보와 설명 근거가 함께 있을 때 원고를 만든다. 큰 변동은 우선 조사할 이유이며 발행 보장은 아니다. 작은 변동 중에도 정책의 새 조건이나 소비 흐름의 전환이 확인되면 리포트 후보가 된다.

2026년 10월 11일 작성한 로컬 설계 권장안이다. [발행 정책](publication-policy.md), [필수 지표와 가격 기준](indicator-price-plan.md), [출처 접근 검토](source-feasibility.md)를 구체화한다. 아래 숫자는 초기 평가용 설정이며 시장에서 검증된 보편 기준이나 운영 승인값이 아니다. 앱 코드·운영 설정·유료 호출은 변경하지 않는다.

## 하루의 판단 순서

1. 기존 데이터 갱신이 완료된 뒤 통화별 자료 상태와 실제 확보한 발표를 확인한다. 작업 시작 예정 시각을 완료 시각으로 간주하지 않는다.
2. 환율 변화, 핵심 발표, 이전 설명의 정정 필요에서 조사 후보를 찾는다. 같은 사건은 한 묶음으로 정리한다.
3. 이전 발행본과 보류·실패·검토 대기 기록을 대조하여 새로 설명할 내용을 적는다.
4. 그 설명의 원문 근거·시점·적용 범위를 검토한다. 부족하면 조사 상태를 유지한다.
5. 별도 승인된 비용과 호출 한도가 있을 때 초안을 만든다. 내용 검사와 관리자 승인을 거쳐 공개한다.

초기에는 조사 후보의 의미적 중요성과 문장 근거를 담당 검토자가 판단한다. 코드가 금리·수치·참조 ID를 확인했다는 이유로 의미 검토를 통과시키지 않는다. 이 판단을 나중에 모델로 자동화하려면 그 호출의 평가와 비용을 따로 포함한다. 사람이 확인할 수 없는 날은 검토 대기이며 자동 게시로 전환하지 않는다.

## 조사할 환율 변화

BRL·MXN·CLP에 같은 계산 정의를 적용하되 각 통화의 과거 분포를 사용한다. 통화별 최적 숫자를 두 개의 리포트 사례에 맞춰 만들지 않는다.

| 구간 | 초기 조사 기준 | 역할 |
| --- | --- | --- |
| 전 관측일 대비 | 절대 변화가 0.75%와 해당 통화 과거 일간 변화의 80분위 중 큰 값 이상 | 일간 주목 후보 |
| 전 관측일 대비 급변 | 절대 변화가 1.5%와 과거 일간 변화의 95분위 중 큰 값 이상 | 조사 우선순위 상향. 시간·원인 검사 유지 |
| 5관측일 대비 | 절대 변화가 2%와 과거 5관측일 변화의 80분위 중 큰 값 이상 | 하루 수치만 보면 놓치는 누적 변화 |
| 20관측일 대비 | 절대 변화가 4%와 과거 20관측일 변화의 80분위 중 큰 값 이상 | 완만하게 이어진 중기 변화 |

일간 하한은 [기존 검사 코드](../../scripts/currency-report/evidence-quality.js)의 값을 초기 비교 기준으로 유지했다. 5관측일 2%와 20관측일 4%는 평가할 설계 가정이다. 아래 저장값 대조는 빈도를 보여줄 뿐 적정성을 입증하지 않는다.

계산은 `100 × (현재값 / k관측일 전 값 − 1)`이며 절대값으로 조사 후보를 고른다. 방향은 원래 부호와 `1 USD = 현지통화` 단위를 함께 보존한다. 하루 약세와 5관측일 강세가 동시에 있을 수 있다.

비교 분포는 현재 판단일을 제외한 직전 60개의 동일 구간 변화다. 현재값을 분포 계산에 미리 섞지 않는다. 분위는 오름차순 자료의 `(n−1)×p` 위치에서 선형 보간한다. 기존 일간 구현도 최대 61개 이전 관측값으로 60개 변화를 계산하므로 충분한 표본에서 같은 정의다. 다만 표본 부족 시 처리와 새 누적 구간은 별도로 평가한다.

정상 상태·양수·유한값·동일 가격 종류를 사용하며 명시된 보간값과 주말은 제외한다. 같은 날짜에 서로 다른 값이 있으면 임의로 마지막 것을 채택하지 않는다. 결측을 건너뛴 긴 구간을 5영업일로 부르지 않는다. 현지 휴장·이월값·공급자 변경 의심 구간은 자료 확인 대상으로 분리한다. 같은 값이 반복된다는 이유만으로 휴장이라고 단정하지 않는다.

60개 기준 변화가 없으면 상대적 이례성 판정은 미검증으로 둔다. 현재 구간의 유효값이 있다면 절대 하한 도달을 자료 확인 후보로 올릴 수 있으나 정상 분포 판정을 대신하지 않는다. 정책 원문 검토는 가격 표본 부족과 독립적으로 진행할 수 있다.

마지막 보고서 이후 변화도 보조로 표시하되 오래된 보고서 때문에 계속 생성 후보가 되는 별도 무기한 누적 기준은 두지 않는다. 5·20관측일 기준과 실제 새 설명을 함께 본다. 이미 설명한 구간이 다음 날에도 하한을 넘었다는 이유만으로 다시 집필하지 않는다.

## 중요한 발표의 기준

핵심 일정은 발표 원문을 확인할 계기다. 예정 시각 경과·기사 수·새 대상 월만으로 원고를 만들지 않는다. 초기 범위 밖의 선거·재정·외환 공급 등 사건도 검토한 원문이 통화와 연결되고 기존 설명을 바꾸면 후보로 추가할 수 있다.

| 발표나 사건 | 새 원고를 검토할 변화 | 생성하지 않을 경우 |
| --- | --- | --- |
| 정책금리와 성명 | 실제 결정 변경, 이전 성명과 다른 정책 조건·위험 판단·시행 내용 | 수치 동결과 기존 문구 반복만 확인 |
| 물가 | 비교 가능한 자료에서 기존 둔화·가속 설명이 바뀌거나 구성 요인이 새 설명을 제공 | 소폭 값 갱신을 기존 문구로 되풀이. 전월 비교를 예상 대비로 표현 |
| 소비·상업활동 | 추세 전환, 주요 구성 변화, 기존 설명을 바꾸는 수정 | 새 월이라는 이유만으로 정례 발행. 집계 변화를 회사 판매로 확대 |
| 미국 공통 발표 | 해당 통화와 연결되는 확인된 정책·시장 맥락이 새로 있음 | 같은 미국 발표로 세 통화 보고서를 자동 복제 |
| 계획의 실제 집행·새 반대 근거 | 이전에 조건부였던 설명의 조건이 충족되거나 무너짐 | 기존 계획을 다시 인용한 기사만 늘어남 |
| 오류·중요한 통계 수정 | 기존 공개 주장의 사실·방향·범위를 바꾸는 정정 | 오탈자나 제목 다듬기를 새 경제 사건으로 처리 |

물가나 소비에 모든 국가 공통의 작은 수치 차이 기준을 강제하지 않는다. 계절조정·기저효과·수정과 구성 항목을 포함한 기존 설명의 변화로 판단한다. 판정은 아래 기록으로 남기며 모델의 자기 중요도 점수로 대체하지 않는다.

## 집필 전에 완성할 변화 기록

각 후보에 다음 다섯 항목이 있어야 한다. 이는 사용자가 매일 답할 질문지가 아니라 수집·검토 과정의 내부 기록이다.

| 항목 | 필요한 내용 |
| --- | --- |
| 이전 설명 | 마지막 발행본 또는 이전 시도에서 이 사건을 어떻게 설명했는지. 첫 보고서는 초기 기준 사례라고 명시 |
| 새 사실 | 그 뒤 확인된 결정·집행·수정·관측 또는 반대 근거. 원문과 대상 기간 연결 |
| 독자가 새로 이해할 점 | 이전 설명에서 유지·추가·수정되는 내용을 구체적인 한 문장으로 작성 |
| 설명 근거와 한계 | 사실·출처 귀속 해석·승인된 일반 원리의 역할과 적용 조건, 중요한 반대 근거 |
| 판정 | 작성 후보·근거 대기·중복·추가 해석 없음·자료 실패 중 하나와 이유 |

“환율이 달라졌다”, “복합 요인이다”, “상황을 지켜본다”만으로는 세 번째 항목을 채운 것으로 인정하지 않는다. 가격이 거의 같아도 정책의 조건이 달라졌다면 새 정보일 수 있다. 반대로 새 기사 URL이 있어도 동일한 사실과 해석이면 중복이다.

새 기사만 신규성의 조건으로 삼지는 않는다. 기존 발표의 집행 확인이나 새 공식 수치가 설명을 바꿀 수도 있다. 다만 새 가격만으로 원인을 추정하거나 근거 없는 영업 의미를 채우지 않는다. 배경·영업 의미·관찰 변수의 최대 개수를 채우는 것은 목표가 아니다.

## 생성과 보류의 경계

| 확인 결과 | 처리 | 재검토 계기 |
| --- | --- | --- |
| 의미 있는 새 설명과 필요한 근거가 확인됨 | 승인된 호출 한도 안에서 검토 초안 후보 | 생성 후 내용 검토 |
| 큰 움직임은 있으나 설명 근거가 없음 | 배경 확인 중. 원인 원고 생성 보류 | 원문·시점·새 사실 확보 |
| 정책 원문은 있으나 이후 가격이 없음 | 정책 업데이트 범위로 검토 가능 | 실제 시장 반응 주장은 적합한 관측 확보 뒤 |
| 정상 확인했지만 새 설명이 없음 | 기존 보고서와 원래 기준일 유지 | 새 사건 또는 설명을 바꾸는 자료 |
| 수집 실패 또는 자료 충돌 | 영향을 받는 부분은 확인 실패·자료 대기 | 정상 수집 또는 충돌 해결 |
| 같은 근거의 초안이 품질 검사에서 탈락 | 원고·실패 이유 보존. 자동 재생성 없음 | 근거·규칙의 실질 보완과 별도 재시험 결정 |
| 중요한 반대 근거·오류 확인 | 기존 해석 재검토 상태를 표시할 설계. 새 집필보다 정정 우선 | 사실 확인과 정정 검토 |

환율 움직임의 원인 설명은 관측 구간·시간·출처의 해석이 맞아야 한다. 기사 장중 관측은 저장 환율 수치와 별도로 설명할 수 있다. 정책 원문이 있다는 이유로 급변 원인 검사를 통과시키지 않는다. 해당 목적만 검사하고 다른 목적의 안전장치를 면제하지 않는다.

중요한 오류가 확정된 보고서는 정상 추천 상태에서 제외하고 정정 상태와 이력을 남기는 방향을 권장한다. 새 AI 원고가 완성될 때까지 오류를 정상 정보로 유지하지 않는다. 오탈자 수정은 별도 정정 이력으로 처리하며 경제 리포트 신규 발행으로 세지 않는다. 실제 접근 처리·운영 변경은 이 계획으로 실행하지 않는다.

초기 집필은 통화별 한국시간 하루 최대 한 번을 상한으로 제안한다. 같은 날 여러 사건은 한 원고로 묶되 각각의 근거를 유지한다. 이미 생성한 뒤 중요한 새 사건이 도착하면 다음 확인 후보에 남기며 자동 추가 호출하지 않는다. 긴급 사실 정정 표시는 이 집필 상한 때문에 지연시키지 않는다. 내용 실패에 대한 자동 재시도·모델 교체는 없다.

동일 사건의 정상 확인은 매일 이어가되 같은 조사·유료 검색을 무조건 반복하지 않는다. 기존 조사 기록에 미해결 항목과 재확인 대상을 남기고 새 공개 자료가 왔을 때 갱신한다. 일정 변경·통계 수정도 새 버전으로 대조한다. 미래 자료를 과거 시점의 판단에 넣지 않으며 수집 시각을 최초 공개 시각으로 대신하지 않는다.

## 저장 환율로 본 조사 빈도

로컬 [전체 환율 파일](../../data/fx-full-history.json)의 기준일은 2026년 9월 12일이다. 10월 최신 시장 자료로 사용하지 않았다. 파일 SHA-256은 `c111e8f02d373f5867f69c73d1c0b1791dac5069a515cd3b2ad67e466822a31f`다.

앞서 정의한 정상 상태·보간·주말 필터를 적용한 BRL·MXN·CLP의 마지막 252개 관측을 계산했다. 이 파일에서는 해당 필터를 통과한 통화·날짜 중복이 없었다. 각 판단일의 직전 60개 변화만으로 기준을 계산했고, 20관측일 기준을 포함하므로 최소 80개 선행 관측이 있는 구간을 사용했다.

| MXN | 2025-09-17부터 2026-09-11 | 32 | 2 | 11 | 5 | 42 |
| CLP | 2025-09-16부터 2026-09-11 | 44 | 9 | 34 | 29 | 81 |

숫자는 해당 통화의 조사 조건을 충족한 관측일 수다. 행 안의 조건은 겹치므로 합산하지 않는다. 연속된 5·20관측일 구간도 겹치며 독립 사건 수가 아니다. 같은 사건의 중복 제거, 현지 휴장·공급자 변경 조사, 당시 확보 가능했던 기사 검토는 적용하지 않았다. 정상 표시 자료에도 실제 관측의 불확실성이 남는다.

이 결과로 알 수 있는 것은 단순 변동 감지만으로도 후보가 상당히 많다는 점이다. 적정 발행 횟수·실제 생성비·원인 설명 성공률은 계산할 수 없다. 위 하한을 발행량 목표에 맞춰 올리는 대신 의미적 중복과 새 설명의 유무를 먼저 평가한다.

## 계획의 선택과 다음 검증

권장 기본값은 하루 한 번 자료 확인, 세 구간 변동과 핵심 사건 감지, 새 설명 기록, 근거 검토, 통화별 하루 한 번 이하 집필, 초기 관리자 승인이다. 조사 조건·중복·자료 상태는 코드로 확인하고 의미적 중요성과 근거 지지는 검토자가 확인한다. 사용자가 숫자 임계값이나 모든 기술 조건을 직접 설계할 필요는 없다.

다음 로컬 구현은 **유료 호출 없이 후보와 보류 사유만 출력하는 판정기**로 제한하는 것이 적절하다. 단계 권장 개발 모델은 GPT-6.1 Sol · High다. 복잡한 구현과 비용을 함께 고려한 권장이며 실제 리포트 작성 모델 선정과 별개다. [공식 모델 안내](https://developers.openai.com/api/docs/models/gpt-6.1-sol)를 참고했다. 사례의 의미 판단은 Astra · High, 정형 회귀 검사는 Sol · Medium을 권장한다.

검증에서는 같은 사건의 연속 신호가 집필 후보로 반복되지 않는지, 작은 가격 변화의 중요한 정책 사건과 완만한 누적 변화를 놓치지 않는지, 정상적인 조건부 설명을 관측시각 부재만으로 모두 차단하지 않는지 확인한다. 가격 공급자·휴장·누락 문제는 실제 시장 사건과 구분한다. 당시 자료 버전이 없으면 과거 자동 판정 성공으로 계산하지 않는다. 조사 후보·내용 검토 후보·집필 가능 후보 수와 제외 사유를 각각 보고한다.

이 초안의 다음 검토 대상은 숫자의 사용자 선호가 아니라 누락·중복 사례와 근거 적합성이다. 실제 유료 시험 직전에는 작성 모델·검토 호출을 포함한 총비용 상한을 구체적으로 제시한다. 현재 신규 호출 허용량은 0이며 과거 승인 잔액을 재사용하지 않는다. 운영 확인 시각·검토 담당자와 출시 승인은 운영 전 결정할 항목이다.
