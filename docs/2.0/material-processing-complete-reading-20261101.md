# 자료 분량 제한 제거와 수집 본문 전체 읽기 / 2026-11-01

> 후속 [날짜·출처 범위 4건 처리](source-scope-recovery-20261101.md)를 반영해 같은24후보의 입력 준비는24건이 됐다. 아래20/4와 EBC 포괄 보류는 분량 개선 직후의 기록이다. 원문·기존 원고와 당시 검증표는 보존한다.

## 현재 규칙

사용자 지시에 따라 `material-processing/2`를 기본으로 적용했다. **6문단·5,000자·본문 60% 상한과 키워드로 일부 문단만 고르는 경로를 제거했다.** 짧은 기사에서도 본문 대부분에 해당한다는 이유로 보류하지 않는다. 이전 규칙과 결과는 [규칙1 데이터](material-processing-rules-v1.json), [당시 기록](material-processing-20261101.md)에 보존한다.

```text
등록 출처 수집 → 접근·이용 제한·원문 결합 확인
  → 수집 본문 전체를 원래 순서·문단·해시·위치 그대로 준비
  → 두 요청의 실제 구성에 대한 입력/출력 예약액 계산
  → 승인 예산·가격·ZDR·지원 기능·제공 경로 입력 가능량 확인
  → 본문 전체에서 사실·귀속 견해 추출
  → 같은 본문 전체를 별도 요청으로 대조
  → 검토된 자체 카드 → 기존 집필·원고 내용 검토 → 관리자 승인·공개
```

긴 기사 마지막의 조건·반대 근거·발언도 두 요청에 똑같이 들어간다. 문장·문단을 잘라 제한에 맞추지 않는다. **요약 분량과 근거를 읽는 분량을 분리한다.**

## 장문·비용·이용 범위의 분리

- 카드 검토기의 작은 입력 상한을 원문 읽기에 상속하지 않는다. 원문 전용 요청 목적과 비용 정책을 사용한다. 일반 카드 검토 정책은 유지한다.
- 같은 본문과 허용된 최대 후보 설명으로 비교 요청의 보수적 상한을 계산해 추출 요청과 합산한다. 고정된 작은 카드 입력량으로 비교 비용을 예약하지 않는다.
- 현재 원문 검토 시험의 두 요청 합산 상한 $0.25는 유지한다. 저장 가격 정책에 따른 준비용 상한이며 실시간 가격 확인이나 새 지출 승인이 아니다. 실제 제공 경로와 가격은 전송 직전에 확인한다.
- 입력량은 UTF-8 바이트와 요청 부가분으로 잡는 보수적 토큰 상한이다. 정확한 토큰 수나 모델이 광고한 문맥 크기로 표시하지 않는다. 원문 경로의 사전 상한은 시험 비용에서 계산하고, 실제 경로의 `context_length`와 출력 여유를 별도로 대조한다.
- 예산을 넘으면 `source_request_budget_hold`로 필요한 예약액·포함 범위·사유를 반환한다. 본문은 그대로 보존한다. 이를 기사 내용 부적합이나 사용 금지로 바꾸지 않는다.
- 승인 없는 자동 분할·추가 호출·재시도·백업은 실행하지 않는다. 여러 호출이 필요한 경우 전체 맥락을 다시 종합하는 검토와 추가 예산까지 별도 범위로 준비해야 한다. 이번에 다중 호출 장문 처리기를 완성했다고 보고하지 않는다.
- 입력 문단 수 안전 검사는 128에서 4,096으로 확장했다. 원문 객체 200KB 검사는 메모리/입력 손상 방어로 남는다. 이 검사는 근거 선별 기준이 아니다.
- 확인된 접근 제한·이용 금지·검토된 보류·출처 전달 조건은 계속 적용한다. 원문 전체 용도의 명시적 제한을 분할로 우회하지 않는다. 원문 공개와 독립 작성 카드의 사용 범위는 별개다.

## 수집 범위의 정직한 표시

`complete_capture`는 **수집된 본문 전부를 입력했다**는 뜻이다. 출판사 페이지를 빠짐없이 수집했거나 기사 내용이 진실이라고 검증했다는 뜻은 아니다. 짧거나 불완전한 본문이 주장을 지지하지 못하면 실제 내용 대조에서 구체적 공백을 반환한다.

원문 위치·해시·`omittedBlocks=0`·`completeCapturedBodyIncluded=true`를 기록한다. 새 경로의 대조 결과는 `provided_complete_capture`, `completeCapturedBodyCompared=true`, `wholeArticleReviewed=false`로 구분한다. 과거 부분 검토 결과를 전체 검토로 재표시하지 않는다.

## 장문 검사 성능

5만 자 비공백 문자열에서 이메일 탐지 정규식이 문자열을 반복 탐색해 준비 검사가 지연되는 문제를 재현했다. 테스트 제한시간을 늘리는 대신 공통 출처 안전 검사의 무제한 반복을 제거했다. 토큰/자격증명·이메일·지시문 검사는 유지한다. 잘못된 후보 한 건은 격리하고 다른 정상 후보는 계속 처리한다.

## 동일한 저장 후보 재생

원본 수집 묶음 6개·후보 24개를 그대로 재사용하고 해시 일치를 확인했다. 새 검색·실제 모델 요청은 0이다.

| 통화 | 후보 | 이전 요청 준비 | 변경 후 요청 준비 | 남은 보류 |
|---|---:|---:|---:|---|
| BRL | 2 | 0 | 0 | 외부 처리 목적·이용 범위 확인 2 |
| MXN | 8 | 2 | 6 | 게시 메타데이터 확인 2 |
| CLP | 4 | 1 | 4 | 없음 |
| COP | 3 | 0 | 3 | 없음 |
| PEN | 3 | 0 | 3 | 없음 |
| ARS | 4 | 0 | 4 | 없음 |
| 합계 | 24 | 3 | 20 | 4 |

스스로 만든 분량 규칙에 걸렸던 17건이 모두 요청 준비로 이동했다. **20건은 원인 근거 채택/리포트 품질 합격이 아니다.** 기사 관련성·실제 사건일·가격 종류·모든 하위 주장·전문가 귀속·반대 맥락과 수집 누락 여부는 별도 자동 추출/대조의 검토 대상이다. 매우 짧게 수집된 본문도 충분한 근거라고 자동 승인하지 않는다.

## 검증과 다음 순서

기존 시험을 새 계약으로 수정했다. 긴 본문·128문단 이후 반대 설명·단일 articleBody·본문 삭제/변조·실제 제공 경로 입력 부족·예산 초과 시 무전송·장문 안전 검사 성능을 확인한다. 합성 응답은 실제 AI 품질 표본에 포함하지 않는다.

전체150파일·1,110사례와 타입·lint·운영/로컬 앱/리포트 빌드·번들 경계 검사를 통과했다. 운영 산출물과 새 검증표 텍스트35파일에서 실제 비공개 키 값/비공개 경로 노출0을 확인했다. 신규 의존성 설치·실제 모델 호출·운영/DB 변경은 없다. 기존 스튜디오 동적 import 최적화 경고1건은 남았다. 프로그램 검증 수를 실제 AI 품질 표본 수로 세지 않는다.

다음은 한 사례의 자료 역할과 **원문 추출/대조·집필·내용 검토 전체 비용**을 확인하고, 별도 승인 범위에서 실제 생성→격리 승인/공개 조회를 실행하는 순서다. 그다음 이메일2.0으로 이어간다. 실제 모델 품질이나 6통화 출시 준비가 완료됐다고 표시하지 않는다.
