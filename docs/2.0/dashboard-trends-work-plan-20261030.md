# 기존 대시보드 + 통합 환율 추이 · 연결 작업 계획

2026-10-30 · 설계만 기록 / 구현·운영 변경 없음

## 목표와 확정 기준

현재 실행 중인 `http://127.0.0.1:4176/`의 기존 대시보드를 기준으로, 리포트 진입과 새 리포트 표시를 다듬고 기존 일별/월별 화면을 ‘환율 추이’로 연결한다. 앞선 독립 A/B 시안을 제품에 이식하지 않는다.

- 대시보드 본문의 당월 누적 평균, MoM, 기준일 값, 52주 위치, 주목 포인트, 30일·월간 차트의 동시 표시와 평균선을 유지한다.
- 기존 통화 순서(BRL·MXN·CLP·COP·ARS·PEN), 산식·단위·출처/자료 상태를 유지한다. 메뉴 정리는 지표 삭제 승인이 아니다.
- 새 리포트는 해당 통화 카드의 링크에 표시한다. 숫자/급변 색상과 구별하고 카드 전체를 새 의미로 덧칠하지 않는다.
- 환율 추이는 기존 `CurrencyDetail`·`MonthlySummary`를 사용한다. 월별의 전체 통화 선택과 현지통화/USD·KRW 환산표를 보존한다. 둘을 단일 표시 기준 토글로 바꾸어 하나를 숨기지 않는다.
- 코드·자료·원고는 기존 작업 브랜치에서 작은 단위로 보존한다. 새 유료 호출·자료 생성·운영 반영은 이번 구현 범위에 포함하지 않는다.

## 실제 코드에서 확인한 연결 공백

1. `App.tsx`는 dashboard/reports/monthly/currency/moving/admin 여섯 화면 상태를 사용한다. 일별/월별은 아직 독립 메뉴이며 기존 영구 주소가 있다고 가정할 수 없다.
2. 일별은 `filters.currency`+시작/종료 월, 월별은 별도 `monthlyCurrency`(ALL 가능)+시작/종료 연도를 쓴다. 화면을 합치는 것만으로 선택 유지가 해결되지 않는다.
3. 대시보드 카드에는 이미 `renderReportLink` 진입점이 있다. 새 원고 생성 기능을 카드에 추가할 필요가 없다.
4. `CurrencyReport`에는 `publishedAt`이 있지만 목록용 `CurrencyReportSummary`에는 없다. 기존 목록 조회는 화면 진입 때만 갱신된다. 보고서 기준일·기사 시각·생성 시각으로 새 배지를 판정하면 안 된다.
5. `MovingComparison`은 비교표와 편집·로그인·저장 이력이 섞여 있다. 그대로 추이 안에 붙이면 공개 조회에 편집 영역이 섞인다. 조회와 편집의 기존 권한 경계를 유지하며 분리해야 한다.
6. 로컬 새 관리 분기와 운영 기존 관리 분기는 구성 차이가 있다. 기존 편집 기능을 잃지 않는 접근 경로를 먼저 확보하고 전체 관리자 개편과 구별한다.

## 환율 추이의 선택·이동 규칙

- 대시보드 ‘CLP 추이 보기’는 CLP 일별 차트/표로 이동한다. 리포트 링크와 별도 버튼/링크로 구분해 카드 전체의 불명확한 클릭을 만들지 않는다.
- 일반 ‘환율 추이’ 메뉴는 마지막으로 본 유효 상태를 열고, 최초 진입은 기존 일별 기본 통화/기간을 따른다.
- 일별과 월별은 선택한 개별 통화를 공유한다. 월별의 ALL은 보존하되 ALL에서 일별로 갈 때 이전 개별 통화를 복원하고 화면에서 표시한다. 일별의 지원하지 않는 전체 통화 차트를 새로 꾸미지 않는다.
- 일별 월 범위와 월별 연도 범위는 각자 마지막 상태를 기억한다. 최초 전환 시 호환 범위를 연결하되 기간 확장/축소가 필요한 경우 안내한다. 연도 단위 표를 월 범위와 같은 정확도로 선택한 것처럼 표시하지 않는다.
- 조회 가능 범위와 현재 선택 범위를 구분한다. 범위 밖 자료 부족/조회 실패/보간을 정상 값처럼 표시하지 않는다.
- 차트와 수치 표는 기존 화면 구조대로 함께 확인한다. 월별은 기존 두 종류 표를 유지한다. 표의 가로 스크롤 자체를 오류로 간주하지 않으며 헤더/버튼이 가려지지 않도록 한다.
- 주소에 화면·통화·일별/월별·각 기간 선택을 재현할 정보를 넣는다. 순방향/뒤로가기/새로고침을 검사한다. 기존 `#report`, 통화/날짜/공개 run 링크와 `#mailing`을 보존한다.
- 환율 추이의 관련 리포트에는 보고서 기준일을 함께 표시한다. 선택 기간과 다른 보고서를 ‘그 기간의 설명’으로 단정하지 않는다. 리포트에서 되돌아오면 이전 추이 선택을 유지한다.

## ‘새 리포트’ 표시 계약

- 최신 유효 공개본 중 **실제 공개 시각의 한국 날짜가 오늘인 경우** 해당 통화 링크에 ‘새 리포트’를 붙인다. 보고서 기준일은 별도로 표시한다.
- 초안/반려/실패/참고본/합성 시험 자료는 대상이 아니다. 공개 시각이 없거나 잘못됐으면 추정해 배지를 붙이지 않는다.
- 목록 조회가 실패하거나 게시 상태를 확인하지 못한 경우 새 공개를 확정한 것처럼 강조하지 않는다. 기존 유효 보고서 유지/캐시 표시는 공통 상태 계약을 따른다.
- 최초 공개와 문체 편집/사본 저장을 구분한다. 기존 공개 시각을 임의로 오늘로 바꾸지 않는다. 정정은 명시적 정정 정보가 있을 때 ‘정정’으로 표시하며 단순 편집 플래그만으로 정정을 추정하지 않는다.
- 한국 자정이 지나거나 잠자던 탭으로 돌아오면 날짜를 다시 계산한다. 대시보드가 열린 동안 새 공개 여부를 갱신하는 간격과 기존 상태 확인 정책을 맞춘다. AI 호출이나 고빈도 폴링으로 구현하지 않는다.
- 다음 날 강조가 사라져도 유효 보고서 링크와 원래 기준일은 유지한다. 읽음 여부를 추적하는 기능은 이번 배지에 필요하지 않다.
- 로컬 UI 검증은 시간을 고정한 합성 목록으로 오늘/어제/자정/철회·실패를 시험한다. 실제 기존 원고의 날짜·상태를 변경해 배지를 만들지 않는다.

## 관리자·계획 대비 경계

이번에는 상위 메뉴에서 관리자를 분리하고 기존 계획 편집/변경 이력에 도달하는 최소 경로를 제공한다. 전체 API 상태/원고 검토/이용 통계/복구 화면을 새로 설계하는 것은 후속 작업이다. 계획 편집의 로그인·저장·검증/실패 안내와 사용자 권한을 보존한다. 로컬 환경에서 설정 미연결이면 그대로 안내하며 운영 DB를 연결해 우회하지 않는다.

비교표 분리 과정에서 편집 기능을 안전하게 보존할 수 없으면 기존 계획 대비를 임시 하위 진입로로 유지한다. 상위 메뉴 개수만 맞추려고 기능을 없애지 않는다. 계획값/산식의 정책 변경도 하지 않는다.
