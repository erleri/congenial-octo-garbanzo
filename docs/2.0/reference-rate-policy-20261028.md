# 대시보드·리포트 기준환율 정책

> 주기 후속 확정: 10월29일부터 PEN·ARS 포함 여섯 통화에 누적±2%·14일 후 첫 한국 월요일 점검이 적용되는 로컬 정책이다. [10월30일 저장 재생](pre-ui-policy-review-20261030.md). 아래 미결정 문구는 10월28일 이력이며 가격 가정 자체는 유지한다.

2026-10-28 · 사용자 승인 작업 가정 · 로컬 준비 경로 적용

## 이번에 확정한 작업 방향

**현재 LATAM FX API/저장 환율을 회사에서 쓰는 기준환율과 같은 것으로 보고 개발한다.** 실제 회사 기준과의 동일성은 사용자가 추후 확인한다. 확인 전 개발을 멈추거나 국가별 종가를 모두 확보하는 과제로 되돌아가지 않는다.

이는 값 사용에 대한 승인된 가정이다. 공급자가 공식 회사 환율을 제공한다고 검증한 결과로 표시하지 않는다. 종가 제공 여부에 대한 [이전 조사](provider-close-definition-review-20261028.md)는 자료 정의의 이력으로 보존하지만, 종가 미확인을 모든 리포트 준비의 차단 사유로 쓰던 방침은 이 정책으로 대체한다.

| 용도 | 공통 기준 |
| --- | --- |
| 대시보드·차트·계획 대비 | 기존 저장 환율과 기존 계산 |
| 리포트 대표 숫자·변화율 | 같은 고정 스냅샷·행 선택·계산 |
| 마지막 발행본 대비 누적 변화 | 같은 가격 정책을 사용한 기준점과 비교. 기존 기사 가격 원고와 자동 혼합하지 않음 |
| 시장 움직임 해설 | 뉴스가 설명하는 거래일·가격 종류·범위에 귀속 |
| 종가·장중 가격 | 특정 설명에 필요할 때 사용하는 선택적 보조 자료 |
| 기사에 가격이 없음 | 기준환율 경로를 그대로 사용. 기사 가격을 찾아 대표값을 채우지 않음 |

CLP·MXN·BRL·COP의 누적 ±2%와 14일 미발행 후 첫 월요일 점검 기준은 유지한다. PEN·ARS의 주기 결정 대기 상태는 이번 환율 가정으로 변경하지 않는다.

## 날짜와 설명의 공통 규칙

- 기본 날짜는 **저장 데이터 기준일**이다. 공급자 갱신시각·실제 관측시각·시장 거래일은 구분해 보존한다. 모르는 날짜를 한국 수집일의 전날로 자동 설정하지 않는다.
- 기준환율의 산정 기간이 아직 없으면 특정 시장 하루의 변화라고 바꾸어 표시하지 않는다. 시장 기사는 자체 거래일의 출처 귀속 해설로 검토한다.
- 평균 기준값의 변화 전체를 특정 마감 직전 사건 하나가 일으켰다고 단정하지 않는다. 글로벌 요인의 현지 연결과 실제 주장 지지는 내용 검토에서 확인한다.
- 월간 소매·물가 자료는 실제 발표일과 대상 월을 유지하며 소비 환경에 사용한다. 당일 환율 원인으로 바꾸지 않는다.
- 필요한 종가가 없으면 그 설명의 범위를 제한하거나 보류한다. 대표 기준환율이나 다른 통화의 자료 준비를 중단시키지 않는다.

공통 기준환율을 사용해도 원문 지지·출처 이용·자료 품질·게시 승인은 별도다. 회사 환율과 같다고 가정한 것이 과거 기사나 원고를 새 기간에 승인한 것은 아니다.

## 로컬 구현

`shared-dashboard-report/3`과 `dashboard-reference-policy/1`을 사용한다. 기존 `six-currency-preparation/2` 파일 형식은 유지하고 결과에 새 규칙 버전을 명시한다.

- `REPORT_REFERENCE_POLICY`: `companyRateEquivalence=assumed_pending_user_confirmation`, `companyRateVerified=false`, `officialReferenceVerified=false`, `localCloseRequired=false`를 여섯 통화에 동일하게 적용한다.
- 기준환율 사용 자격(`reference_rate_basis`)과 현지 종가 정보(`basis`)를 분리했다. 기본 숫자는 작업 가정으로 수용하고, 현지 종가/거래일의 미확인을 사실로 남긴다.
- 과거 출처 기록이 없거나 일부 날짜에만 있어도 그 부재를 공개 기록의 경고로 보존하며 기준환율 준비를 일괄 차단하지 않는다. 기존 캐시를 새 응답으로 인증하지 않는다. **존재하는 기록의 값 불일치·잘못된 공급자/주소·지원하지 않는 기록 버전은 차단**한다.
- 종가 필수 검사 대신 `evidence_period_and_scope`로 기간·설명 범위의 새 연결 검토를 요구한다. 이전 종가 승인·회사 가정으로 이 검토를 통과시키지 않는다.
- 공통 집필 안내 다섯 항목을 새 6통화 인계에 포함한다. 이전 유료 요청/원고를 다시 조립하거나 실제 AI로 전송하지 않았다. 실제 집필 요청은 근거 재연결 전까지 `null`이다.
- 정책이 달라지면 스냅샷 식별값도 바뀐다. 기존 원고·발행 기준점·가격 해시는 덮어쓰지 않는다.

잘못된 숫자·0·결측·중복·보간·오래된 자료·미래 시각 검사는 유지한다. 회사 환율과의 동일성 가정으로 이 품질 검사를 생략하지 않는다.

## 후속 순서와 사용자 확인 시 처리

1. **기존 6통화 근거를 같은 정책으로 재연결 — Sol High:** 카드의 실제 기간·거래일·가격 종류를 유지하고 원인 설명과 소비 환경을 분리한다. COP·PEN·ARS의 남은 근거/출처 조건을 먼저 확인하고 해결되지 않는 사유를 기록한다. 추가 유료 호출 없이 저장 자료로 진행한다.
2. **연결된 입력 최종 내용 검토 — Astra High:** 문장에 쓸 수 있는 주장 범위와 자료 공백을 판단한다. 실제 모델 생성은 별도 예산 범위에서 수행한다.
3. **집필·승인·공개 조회/UI·파일럿·출시:** 기존 순서로 복귀한다. 이번 작업으로 운영 배포/새 모델 호출을 승인하지 않는다.

사용자 확인 결과 회사 기준과 다르면 공급자/계열·기준일·산정 방식을 비교해 새 정책 버전을 만든다. 기존 원고를 조용히 재계산하지 않으며, 누적 발행 기준점과 계획 대비에 미치는 영향을 별도로 검증한다.
