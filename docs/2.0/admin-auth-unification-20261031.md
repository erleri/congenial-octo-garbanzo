# 관리자 인증 통합 — 로컬 구현 결과

2026-10-31. 계획환율에서 사용하던 **이메일 로그인 링크**를 공통 방식으로 사용한다. 데이터·리포트와 계획환율·변경 이력에 별도 로그인을 요구하지 않는다. 운영 반영은 하지 않았다.

## 바뀐 구조

1. `appClient.ts`: 계획환율·리포트가 같은 Supabase 클라이언트와 세션을 사용한다. 로컬 빌드에서는 기존 격리 DB 클라이언트를 사용하고 운영 빌드에서는 기존 운영 연결 설정을 사용한다.
2. `adminAccess.ts` / `useAdminAccess.ts`: 세션 변경, active admin 조회, 로그아웃, 화면 이탈과 복귀를 공통으로 처리한다. 환율 데이터 조회 성공 여부와 관리자 인증을 분리한다.
3. `AdminAccessPanel.tsx`: 두 관리 메뉴 위에 공통 로그인·로그아웃 영역을 하나만 표시한다. 기존 이메일 링크 방식이며 로컬 리포트 화면의 별도 비밀번호 입력을 제거했다.
4. `useExchangeData.ts`: 공통 인증 결과로 계획환율 편집과 변경 이력을 열고, 공개 계획값 조회 상태는 별도로 유지한다.
5. `CurrencyReportReview.tsx`: 독립 로그인과 세션 구독을 제거하고 공통 인증을 받는다. 검토 RPC와 초안 조회 시 서버 권한 검사는 유지한다. 제작 스튜디오의 DB 검토 화면도 같은 인증 컴포넌트를 사용한다.

로그아웃·인증 변경 시 이전 비동기 응답을 무효화한다. 초안·이력·검토 사유·열린 계획 입력창을 제거하며, 늦게 도착한 응답으로 다시 나타나지 않게 한다. 공개 환율·계획값·승인 보고서는 그대로 제공한다.

서버의 테이블 정책과 승인 RPC는 기존 active admin 검사를 그대로 사용한다. 권한 해제는 서버에서 즉시 적용된다. 화면 상태는 창 복귀·인증 이벤트·작업 시 조회와 30초 주기 재확인에 따라 갱신한다. 서버 연결을 확인하지 못하면 비공개 영역을 숨긴다. 로그아웃 실패 뒤에도 남은 세션을 자동 복구하지 않는다. 로그인 링크 발송만으로 새 로그인이 완료된 것으로 보지 않는다.

## 로컬 인증 환경

- 격리 대상: `latamfx-2x-isolated`, API `127.0.0.1:56321`, DB `56322`.
- 기존 제작 화면 4175 외에 앱 4176과 운영 코드 미리보기 4177의 로컬 로그인 반환 주소를 추가했다. 로컬 설정 생성기에도 반영했다. 운영의 반환 주소·메일·DB 설정은 변경하지 않았다.
- 테스트 로그인 이메일은 로컬 Mailpit에만 도착한다. 실제 사용자의 외부 메일로 발송하지 않았다. 링크·토큰·DB 백업은 Git 제외 경로에 보관한다.
- 재시작 도중 CLI가 서버 이미지를 갱신한 사실을 확인했다. PostgreSQL `17.6.1.165 → 17.11.0.006`, GoTrue `2.196.0 → 2.197.0`이며 **격리 로컬 환경에만 해당한다**. 데이터 볼륨과 사전 SQL 백업을 보존했다. 이후 기존 public 테이블 11개의 모든 COPY 데이터와 원고·검토·공개 기록 70건 해시가 이전과 같음을 확인하고 DB 검사 113건을 재실행했다. 이미지 버전 유지까지 확인한 것으로 보고하지 않는다.

기존 로컬 관리자 계정을 직접 비활성화하는 UI 시험은 자동 승인 검토에서 구체적 승인 부족으로 차단되어 실행하지 않았다. 대신 기존 계정은 유지한 채, 단위 검사에서 권한 해제·늦은 응답·연결 실패를 확인했고 기존 합성 계정의 DB 트랜잭션 검사로 같은 JWT의 초안·이력·승인 차단을 확인했다. 실제 계정을 비활성화한 브라우저 시험까지 완료했다고 하지 않는다.

배포·원격 push·운영 DB 변경·실제 보고서 승인/철회·계획환율 저장·외부 메일 발송·유료 모델 호출은 하지 않았다.
