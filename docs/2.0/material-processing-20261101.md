# 공통 자료 처리 — 새 출처를 추가할 때의 기준 / 2026-11-01

> 후속 사용자 지시로 분량 규칙을 개선했다. 현재는 [수집 본문 전체 읽기 규칙2](material-processing-complete-reading-20261101.md)를 적용하며, 아래의 6문단·5,000자·60% 제한과 3건 준비/21건 보류는 규칙1 당시 기록이다. 기존 원고와 당시 결과는 보존한다.

## 이번 변경의 목적과 상태

새 매체에 대한 ‘원문 전체 외부 전송’ 정책이 없다는 이유로, 제한된 문맥 분석과 자체 사실·견해 카드까지 함께 정지하던 경로를 분리했다. 국가나 특정 신문에 새 예외를 추가하는 방식 대신 `material-processing/1` 공통 규칙을 연결했다.

로컬 구현·저장/합성 검증이다. 새 실제 모델 호출·AI 원고·승인·메일·운영 반영은 없다. 기존 환율 API와 원고·원문·비용 장부를 바꾸지 않는다. 자료 처리 적합성, 모델 내용 검토, 집필 자격, 관리자 게시 승인은 계속 별개다.

이 문서와 [당시 규칙 데이터](material-processing-rules-v1.json)는 프로젝트의 처리 범위다. 출판사 허가증이나 법적 사용 가능성의 보증을 만들어내는 기록이 아니다. 접근 가능성·robots 결과·출처 표시만으로 외부 전송/공개 권한을 확정하지 않는다.

## 한 벌의 공통 흐름

```text
등록된 출처의 공개 접근 경로
  → 기존 수집기: 접근 제한·형식·게시/수정시각·본문 해시 보존
  → 자료 종류와 실제 용도 구분
      ├ 제한 문맥: 공통 규칙으로 정확한 구간과 원문 위치 고정
      ├ 원문 전체: 그 범위를 명시적으로 검토한 기존 정책 필요
      ├ 통계/PDF: 해당 자료용 수집·검토 경로, 기사 경로로 전송하지 않음
      └ 제한·불충분·메타데이터 오류: 이유 기록, 다른 후보 계속 처리
  → 별도 예산/제공 경로/데이터 보호 조건 확인
  → 사실·귀속 견해 추출 → 별도 요청으로 선택 문맥과 대조
  → 독립 작성·모든 하위 주장·귀속·조건·기간 확인
  → 공통 자체 카드 사용 프로필 + 출처 전달 조건
  → 대시보드 기준환율과 연결한 기존 집필·내용 검토
  → 관리자 승인 → 정제된 공개 리포트
```

단순 키워드와 글자 수 검사는 자료 준비 검사다. 실제 환율 원인이나 문장의 타당성을 판정하는 내용 검토를 대체하지 않는다.

## 자료별 처리표

| 자료/용도 | 공통 처리 | 허용으로 취급하지 않는 범위 |
|---|---|---|
| 공개 기사 수집 | 기존 등록·접근 검사·출처별 파서 재사용. 원본은 비공개 보존 | 차단 우회·무등록 URL 임의 수집 |
| 선택한 근거 문맥의 비공개 분석 | 원문과 정책 해시에 묶인 구간만 요청 후보로 준비 | 원문 전체 전송·학습·번역문·기사 대체물·공개 인용문 |
| 원문 전체 외부 분석 | 기존의 명시적 검토 정책과 실제 전달 조건이 맞는 경우에만 별도 경로 유지 | 제한 문맥의 판단을 전체 전송에 상속 |
| 독립 작성 사실·귀속 견해 | 별도 추출/대조 후 공통 카드 프로필 적용. 출처·기간·전문가·조건 유지 | 기사 문장 복사·단순 번역·발언자의 견해를 사실/기여도 순위로 변경 |
| 리포트 공개 | 카드의 공개 사용·내용 검토·관리자 승인을 각각 확인 | 원문/분석 문단 자체 공개·검토 통과만으로 자동 게시 |
| 재사용 카드 | 같은 원문/카드 결합을 검증하고 현재 제한을 재확인 | 과거 판단을 새 원문·새 날짜·더 넓은 범위에 재사용 |

새 매체는 공통 제한 문맥 프로필과 자체 카드 프로필을 사용한다. 별도 제한이 확인되면 국가별 코드 대신 `material-processing-rules.json`의 실제 origin·경로·대상 용도·근거 URL·확인일·사유로 기록한다. 기존에 명시적으로 금지한 외부 처리는 계속 차단한다. 원문 전체만 제한하는 경우 제한 문맥으로 좁힐 수 있지만, 외부 텍스트 처리 자체의 제한을 문단 분할로 우회하지 않는다.

## 제한 문맥 구성과 범위 표시

- 기본 상한은 6개 문맥 단위·5,000자·저장 본문의 60%다. **비용·전송 범위를 제한하는 내부 수치이며 저작권 허용 비율이 아니다.** 수치 이하라는 이유만으로 이용 허가나 내용 적합성을 입증하지 않는다.
- 도입부·발언 문단과 후속 문단·명시적 조건 문맥을 보존한다. 문장을 글자 수에 맞춰 임의로 자르지 않는다. 필요한 문맥이 범위를 넘으면 보류하며 상한을 자동으로 늘리지 않는다.
- JSON-LD의 단일 `articleBody`도 원문을 바꾸지 않고 문단/완결 문장 단위로 나눈다. 원본 블록과 문자 시작·끝 위치를 함께 보존한다. 한국어·스페인어·포르투갈어 원문 위치를 재번호만으로 덮어쓰지 않는다.
- 범용 표현 감지는 문맥 선택용이다. 악센트 때문에 실제 발언을 놓치거나 `explicación` 같은 명사를 발언 동사로 오인하던 문제를 보완했다. 모든 언어·모든 기사 구조를 완전하게 해석한다는 뜻은 아니다.
- 결과에 `supportScope=selected_original_context`, `wholeArticleReviewed=false`, 포함·생략 범위와 문맥 해시를 남긴다. ‘기사 전체 원문 검증’으로 보고하지 않는다. 생략 부분을 AI가 복원하거나 일반 원리로 메우지 않도록 요청한다.
- 자체 카드의 기계적 원문 복사 감지는 보조 장치다. 모델의 별도 독립 표현/모든 하위 주장/귀속/조건 대조를 생략하지 않는다.

## 새 사이트를 추가할 때 하는 일

1. 기존 출처 목록에 국가·공개 URL·질문/자료 역할·갱신 경로를 등록한다. 인증이 필요한 API의 자격증명은 기존 비공개 방식으로만 저장한다.
2. 접근·재사용 조건, 본문/날짜/수정본의 자동 추출 가능성을 확인한다. 파서가 없으면 해당 어댑터를 추가한다. 사이트 이름별 집필 규칙을 추가하지 않는다.
3. 알려진 제한·추가 표기 조건은 출처 데이터로 기록한다. 유사한 호스트명에 다른 사이트의 판단을 상속하지 않는다.
4. 저장 캡처로 원문 결합·문맥 범위·기간·출처 표시·제한/장애를 확인한다. 파싱 실패와 ‘새 정보 없음’을 구분한다.
5. 준비된 자료만 같은 추출→별도 대조→자체 카드→집필 경로로 보낸다. 비용 승인이 없으면 전송 전 대기한다. 자료가 막히면 다른 등록 출처를 계속 처리한다.

**정상 경로에 사용자의 기사별 수동 확인 작업을 넣지 않았다.** 자동으로 처리하지 못한 자료는 보류 상태와 이유를 반환한다. 보류 자료를 억지로 채택하거나 준비된 다른 출처를 함께 막지 않는다.

## 상태·오류·비용

| 상태 | 뜻 / 다음 처리 |
|---|---|
| `source_review_budget_required` | 입력 범위 준비. 별도 예산/전송 어댑터가 있어야 실제 추출/대조. 내용 합격이 아님 |
| `processing_restricted` | 확인된 제한 또는 범위 검토 필요. 다른 출처 계속 처리 |
| `source_metadata_hold` | 게시시각 등 필요한 정보 부족. 수집시각으로 대체하지 않음 |
| `analysis_context_hold` | 필요한 문맥이 범위를 넘거나 대부분/전체 원문이 되는 등 현재 프로필에 맞지 않음 |
| `source_review_hold` | 결합·추출·대조·카드 연결의 구체적 실패. 원인 코드를 보존 |
| `source_cost_unresolved` | 전송 후 비용 불명. 예약 유지·추가 유료 처리 중지 |

국가 요약은 처리 가능한 대체 자료가 있으면 자동 검토 대기를 우선 표시한다. 동시에 다른 자료의 제한 사유는 보존한다. 잘못 결합된 원문이나 민감/지시문이 포함된 자료는 해당 후보를 격리하며 다른 정상 후보의 처리까지 중단하지 않는다. 모델 어댑터가 등록돼 있다는 이유만으로 로컬 준비 오류를 ‘비용 미확인’으로 바꾸지 않는다. 실제 전송의 불명 비용과, 이미 비용을 확인한 뒤 카드 연결에서 난 오류를 구분한다.

원문 요청·모델 원문 응답·사적 실행 기록은 공개 화면이나 번들에 넣지 않는다. 추출/대조는 기존 ZDR·학습/수집 금지·허용 경로·120초·재시도/백업 없음·영속 비용 예약 계약을 재사용한다. 이번 구현은 실제 유료 호출을 하지 않는다.

## 저장 자료 재생 결과

직전 무료 수집에서 저장한 **동일한 24개 후보의 수집 묶음**을 다시 사용했다. 새로 검색한 수나 채택된 기사 수가 아니다.

| 통화 | 저장 후보 | 자동 검토 요청 준비 | 현재 보류 |
|---|---:|---:|---|
| BRL | 2 | 0 | EBC 처리 목적·적용 범위 확인 2 |
| MXN | 8 | 2 | 문맥 범위 4, 게시 메타데이터 2 |
| CLP | 4 | 1 | 문맥 범위 3 |
| COP | 3 | 0 | 문맥 범위 3 |
| PEN | 3 | 0 | 문맥 범위 3 |
| ARS | 4 | 0 | 문맥 범위 4 |
| 합계 | 24 | 3 | 21 |

기존에는 24건 모두 매체별 원문 정책 미등록/미확정으로 막혔다. 이번에는 같은 이유로 일괄 중지하지 않고 실제 처리 단계로 구분한다. 문맥 범위 보류 17건은 짧은 원문 대부분이 포함되거나 필요한 문맥이 현재 상한을 넘는 경우다. 이 결과를 맞추기 위해 범위를 자동 완화하거나 원문 전체 전송으로 전환하지 않았다. 3건도 해당 거래일의 원인 근거로 채택된 것이 아니며, 실제 모델 추출/대조와 기간·역할 검사가 남아 있다.

EBC는 [공식 이용 안내](https://www.ebc.com.br/termos-de-uso-e-condicoes-gerais-do-portal-da-ebc)의 목적 범위와 Agência Brasil에 적용되는 조건을 함께 확인해야 해 검토 상태로 남겼다. EBC 전체 자료의 법적 금지나 두 기사의 진실성 문제로 단정하지 않는다.

저장 캡처를 현재 수집기로 다시 탐색하는 재생도 별도로 실행했다. 이는 현재 선택/날짜 조건에 따라 후보 수가 바뀔 수 있어 위의 ‘동일 24건’ 비교에 합산하지 않았다. 두 재생 모두 새 네트워크/모델 요청은 0이다. 원본 수집 묶음의 해시 일치를 확인했다.

## 검증과 남는 한계

공통 처리와 기존 원문/노트 경로를 함께 검사했다. 신규 출처, 제한 우선순위, 허가된 기존 전체 경로 호환, 문맥 삭제/변조, 단일 본문 위치, 발언/조건 보존, 자체 카드 복사, 캐시 제한 재확인, 대체 출처 계속 처리, 로컬 오류/미확인 비용 구분을 다룬다. 합성 응답은 실제 모델 검토 합격으로 세지 않는다.

전체150파일·1,108사례와 타입·lint·운영/로컬 앱/리포트 빌드·번들 경계 검사를 통과했다. 테스트 목록의 동명/동일 본문/자명 assertion 검사는 지적이 없었으며 의미적 중복이나 실제 원고 품질을 보증하는 검사는 아니다. 운영 산출물과 새 검증표의 텍스트35파일에서 실제 비공개 키 값/비공개 경로 노출0을 확인했다. 기존 리포트 스튜디오 동적 import 최적화 경고1건은 남았다. DB 구조·권한은 바꾸지 않아 직전151항목 DB 검증은 재사용하고 이번 검사 수에 합산하지 않는다. 실제 유료 내용 검토와 6통화 집필 자격·품질 합격은 이번 완료 범위가 아니다. 자동 자료 공급에서 모든 형식·짧은 기사·누락 날짜를 해결했다고 표시하지 않는다.

구현: `material-processing.js`, 공통 규칙 JSON, 기존 `original-news-pipeline.js`, `runtime-source-review.js`, `runtime-note-material.js`, `runtime-supply.js`, 로컬 실행기. 공개 `CurrencyReport`·기존 URL·승인 구조·대시보드 대표 환율은 유지한다.

다음 고정 순서는 **준비 가능한 한 건의 실제 자료 역할·원문 대조/집필 전체 비용 상한 확인 → 별도 예산 승인 범위에서 자동 카드화·집필·내용 검토 → 격리 로컬 승인/공개 조회 → 이메일2.0**이다. 원문/형식 보류는 출처별 데이터/어댑터의 공백으로 관리하며 매번 국가별 집필 예외를 만들지 않는다.
