# 환율 리포트 누적·이력·과거 주소 · 구현 계획

2026-10-31 KST · 계획 작성 / 제품 코드·DB·원고·운영 변경 전

최종 검토 완료: [조회·표시 규칙](report-history-review-20261031.md). 아래 계획에서 미정이던 공개 상태 저장 방향·이력 주소·역사/합성 자료 선택·정정과 미존재 구분은 이 검토 결과를 따른다. 검토만 완료했으며 구현은 아직 시작하지 않았다.

후속 실행 완료: [로컬 구현·검증 결과](report-history-implementation-20261031.md). 위 문장은 검토 당시 상태다. 현재는2~5단계의 조회/저장·이력·정정/장애·묶음 검증까지 로컬 완료했으며 운영 반영은 하지 않았다.

## 목표

리포트가 늘어나도 첫 화면에서는 최신 정보를 바로 보고, 통화별 과거 자료는 날짜로 찾아 읽게 한다. 기존 A안 상세·공개 원고·대시보드의 최신 링크/새 배지·추이 복귀를 보존한다. 목록 조회 개수와 실제 자료 보존을 구분하고 이력 기능 때문에 오래된 원고를 삭제하거나 재생성하지 않는다.

## 현재 코드로 확인한 사항

1. 첫 화면은 이미6통화별 최신 공개 요약이다. 이 구조를 유지한다.
2. 공개 조회는 통화별 최근30행을 선택하며 `approvedHistory`도 최근30기준일로 제한한다. 더 오래된 이력의 기간 검색/페이지 추가는 없다.
3. 상세 선택이 위 목록에 종속돼 있다. DB에 있는30개 이전의 공개본도 직접 날짜 주소에서는 선택되지 않을 수 있다. 저장 여부와 현재 화면에서 조회 가능한 범위를 구별해야 한다.
4. 공개 테이블은 `(currency,base_date)` 기본키이며 같은 날짜의 재승인 시 공개 행과 `published_at`을 교체한다. 실행/검토 원본은 비공개 보존돼도 모든 과거 공개 판본이 별도 공개 저장되는 구조는 아니다.
5. 철회 행은 익명 RLS에서 제외된다. 현재404 응답만으로 철회/미존재/교체된 판본을 정확히 구분할 수 없다. 안전한 공개 상태 정보가 필요하다.
6. `purpose`는 환율 설명/경제 업데이트 구분이며 정기 점검 구분과 같지 않다. 제목을 읽어 보고서 유형을 추측하지 않는다.
7. 기존 provider의 목록/캐시 키는 최근 index 중심이다. 새 검색 조건과 페이지 결과가 섞이지 않도록 조회 계약과 함께 정리해야 한다.

검토 근거: `PublishedCurrencyReports.tsx`, `currencyReportAccess.ts`, `report-queries.ts`, `provider.ts`, `currencyReport.ts`, 저장 migration의 키/RLS/승인 upsert. 실제 운영 DB를 조회하거나 수정하지 않았다.

## 독자에게 보일 화면

```text
환율 리포트
  6개 통화의 최신 유효 리포트
    ├─ 최신 리포트 읽기 → 기존 A안 상세
    └─ 지난 리포트 → 해당 통화의 날짜별 목록

통화별 지난 리포트
  통화 / 연도 / 월(전체 포함)
  기준일 · 제목 · 짧은 요약 · 확인된 보고서 유형
  최신 기준일 순 / 더 보기
    └─ 상세 → 이전·다음 / 목록으로 / 최신본 보기
```

최신 카드와 목록의 통화 순서는 현재 리포트 메뉴와 같게 유지한다. 대시보드의6카드 순서를 별도로 바꾸지 않는다. 세부 색·글꼴 개편은 후속 단계다.

## 표시·이동 규칙

- 목록 정렬은 **보고서 기준일 내림차순**이다. 실제 공개일은 별도 정보다. 뒤늦게 올린 과거 검토본이 오늘의 시장 리포트처럼 최상위 최신 추천을 차지하지 않도록 한다.
- 기존 A안의 당시 본문·수치·차트·출처는 발행 자료 그대로 조회한다. 현재 대시보드 숫자로 다시 그리거나 당시 원고를 AI로 재작성하지 않는다.
- ‘이전’은 같은 통화의 더 오래된 유효 기준일, ‘다음’은 더 최근 기준일이다. 일자가 연속되지 않아도 정상이며 철회·비공개본은 건너뛴다.
- 상세의 ‘이전/다음’은 현재 검색 조건 안의 탐색으로 고정한다. 연도/월 조건이 없으면 전체 이력이다. 조건 끝이면 비활성 이유와 전체 이력 이동을 제공한다. ‘최신본 보기’는 조건 밖으로 나가는 행동임을 표시한다.
- 보고서를 보고 돌아오면 통화·연도·월·불러온 목록과 가능한 스크롤 위치를 복원한다. 최근30개만 매번 처음부터 다시 보게 하지 않는다.
- 대시보드/추이에서 들어온 경우 해당 화면 복귀를 유지하고 ‘지난 리포트 목록으로’는 별도 이동이다.
- 기존 `#report`, `#report/CLP`, `#report/CLP/2026-10-09`와 공개 run 선택 주소는 유지한다. 새 이력 주소에는 통화·기간을 재현하며 초안 ID/관리자/비용·원문을 넣지 않는다. 상세 탐색의 복귀 맥락은 검증된 내부 상태만 사용한다.
- 기록 없음, 조회 실패, 검색 결과 없음, 철회, 교체/정정, 주소 오류를 구분한다. 실패를0건으로 표시하지 않고, 잘못된 날짜/run을 다른 원고로 조용히 대체하지 않는다.

## 데이터 조회와 저장 경계

### 조회

- 첫 화면은6통화의 최신 요약만 조회한다. 이력을 보기 전부터 본문과 오래된 목록 전체를 받지 않는다.
- 통화별 이력은 **30개씩** 요약을 조회하고 다음 항목 존재 여부만 확인한다. 페이지 번호의 건너뛰기보다 마지막 기준일을 기준으로 이어 받는다. 현재 한 통화·기준일에 공개본 하나라는 키를 활용하며 날짜 정렬의 임의 동률을 만들지 않는다.
- 통화·연도·월 조건을 서버 조회에 적용한다. 최근30개를 받은 뒤 브라우저에서 필터링해 ‘과거 자료 없음’이라고 하지 않는다.
- 연도/월 선택 범위도 해당 통화의 공개 리포트 이력에서 별도 확인한다. 첫30개에 나타난 연도만 선택지로 만들거나 환율 데이터의2010년 이후 전체 기간을 보고서 발행 기간으로 대신하지 않는다.
- 오래된 직접 날짜/공개 run 주소는 최근 목록과 별도로 정확 조회한다. 반환된 통화·기준일·공개 ID·상태를 검증하고, 실제 공개본이 있으면 첫30개 밖이어도 표시한다.
- 이전/다음은 조건과 현재 기준일에 맞는 이웃 요약을 제한 조회한다. 수년치 본문을 내려받아 이웃을 찾지 않는다.
- 페이지별 결과는 통화/기간/정렬/이어받기 기준으로 분리한다. 중복 클릭·늦게 도착한 다른 통화 응답·기간 변경 후의 이전 페이지 결과가 섞이지 않게 한다.
- 페이지를 읽는 동안 새 발행·정정이 생길 수 있다. 엄격한 동일 DB 스냅샷을 보장한다고 하지 않고, 현재 기준점의 추가 조회와 최신 상태 재확인을 분리한다. 중복 제거·변경 안내·철회 우선 처리 후 필요하면 새로고침한다.

### 공개 판본·정정/철회

- 날짜 주소는 해당 기준일의 현재 유효 공개본을 가리키는 진입점이다. 정정 시에는 정정 사실을 알리고 유효 수정본을 보여준다. 보고서 ID/run 주소는 정확한 판본을 뜻하며 다른 판본으로 무단 대체하지 않는다.
- 공개 상태 응답은 안전한 ID·통화·기준일·공개/교체/철회 상태·정정본 연결·공개 가능한 짧은 안내만 반환한다. 비공개 runs/reviews를 anon에 열지 않는다.
- 잘못된 옛 본문은 철회/교체 이후 정상 이력·추천·캐시로 복구하지 않는다. 원문·상세 사유·검토자·비용은 관리자 보존 영역에 남긴다.
- 현재 키와 유효 본문 저장소는 유지하고, 공개됐던 ID의 상태·교체 관계를 작은 별도 공개 기록으로 보강한다. 옛 본문을 모두 공개하는 저장소는 만들지 않는다. 필요한 변경은 **격리 로컬 DB**에서만 추가하고, 승인·공개·정정 연결을 원자적으로 처리한다. 기존 행/감사 기록 삭제나 권한 완화를 대안으로 사용하지 않는다.
- 기존 자료는 확인 가능한 연결만 이관한다. 이전 판본의 실제 공개 시각·정정 관계를 알 수 없으면 미확인으로 남긴다. 비공개 원고 전체를 임의로 공개 이력으로 승격하지 않는다.
- 분석 목적(환율 설명/경제 환경)과 발행 계기(변동 분석/정기 점검)는 별도 메타데이터로 관리한다. 구분할 근거가 없는 옛 자료는 일반 ‘리포트’로 표시한다.

### 용량·캐시

- 목록에는 요약만, 상세에는 선택한 본문만 제공한다. 정적 배포/앱 번들에 이력 전체를 포함하지 않는다.
- 최근 방문한 목록·본문을 제한된 범위로 캐시하고 항목수/크기/유효기간을 기존 데이터 수명 정책과 맞춘다. 더 보기를 누를 때마다 모든 페이지를 영구 누적하지 않는다. 총량 상한·만료 정리도 검증한다.
- 목록 캐시는 조건별로 분리하며, 철회/정정의 최신 확인 여부가 캐시보다 우선이다. 오래된 캐시를 제공할 때 기준일·마지막 확인·현재 상태 미확인을 표시한다.
- 공개 승인본/출처/정정 관계와 임시 수집/실패 초안을 다르게 관리한다. **30개 조회 제한은 보존30개/자동 삭제 정책이 아니다.** 이번 구현에서 보존 기간을 새로 적용하거나 실제 삭제를 실행하지 않는다.

조회·표시 규칙 검토는 Astra High, 연결 구현·회귀는 Sol High를 권장한다. 실제 작업은 준비된 경로를 연결해서 진행하되 공개 판본·권한 규칙이 맞지 않으면 UI 문구만으로 덮지 않고 원인/대안을 기록한다. 운영 반영은 별도 승인이다.

## 검증 자료와 사례

- 저장된 실제 승인본은 본문/날짜/상태를 바꾸지 않고 조회 회귀에 사용한다.
- 30개 이전 탐색은 별도 격리 합성 자료를 만들어 검증한다. 최소65개 유효 기준일로 30+30+잔여/더 없음, 연도 경계·발행 없는 달·발행일 간격을 포함한다. 실제65건 발행이나 품질 평가로 보고하지 않는다.
- 첫 페이지 밖의 직접 날짜/run, 이전/다음 경계, 조건 변경·느린 응답·중복 더 보기·중간 새 발행/정정을 검증한다.
- 같은 날짜의 정정, 과거 run 링크, 철회된 본문·캐시, 조회 실패+캐시/무캐시, 일반 로그인/비로그인 접근을 확인한다. 같은 세션의 권한 해제와 동시 승인 관련 기존 검사는 재사용한다.
- 로컬 DB 변경이 필요하면 기존 자료 보존 전후 확인과 pgTAP/권한 검증을 수행한다. 운영 DB를 대체 시험장으로 사용하지 않는다.
- 기존 대시보드 지표, 새 배지, 추이 선택 복귀, 오래된 URL·공유·인쇄를 회귀 확인한다. 타입·린트·관련/전체 회귀와 운영/로컬·리포트 빌드를 변경 범위에 맞춰 실행한다.
- 새 글·AI 생성·외부 기사 수집·유료 모델 호출 없이 검증한다. 실제 리포트 원고를 합성 발행일에 복제해 정상 공개 기록처럼 섞지 않는다.

## 범위 밖과 결과물
