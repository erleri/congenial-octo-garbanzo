# 2.0 출시 전 확인과 출시 후 운영 관찰

2026-11-03 사용자 확정. 현재 출시 판단은 이 문서를 우선한다. 과거 문서의 출시 전 10영업일·초안 10건 요구는 아래 운영 관찰 기준으로 대체하며 당시 기록은 삭제하지 않는다.

## 확정 사항

- 6통화 실제 원고의 생성·별도 모델 검토·격리 로컬 승인·익명 조회는 완료했다. [완료 증거](six-report-completion-goal.md).
- 10영업일은 출시 후 첫 품질 평가 시점이고, 초안 10건은 평가 표본 목표다. 두 수치를 출시 전 대기 기간으로 사용하지 않는다.
- 영업일은 달력 날짜와 구분하고, 초안은 실제 생성한 판본으로 센다. 코드 테스트·수동 샘플·같은 원고 재평가를 초안 표본에 합산하지 않는다.
- 사건이 부족하면 발행을 강제하지 않고 관찰을 계속한다. 규칙·모델·수집 경로가 달라진 표본은 버전별로 구분한다.
- 관리자 승인 후 공개를 유지한다. 자동 생성의 활성화가 자동 게시·메일 발송 승인을 뜻하지 않는다.
- 이번 $28 승인은 완료한 로컬 목표의 한도다. 남은 승인 여유를 반복 운영의 월 예산이나 신규 시험 승인으로 옮기지 않는다.

## 출시 전 확인

운영 연결의 현재 로컬 마감 결과와 실제 적용에 남은 항목은 [운영 설정·저장·복구 연결](operating-readiness-20261103.md)을 따른다. 실제 runner·운영 백업·운영 최소 연결은 로컬 검증 완료에 합산하지 않는다.

| 구간 | 현재 확인된 범위 | 출시 전에 남은 확인 |
|---|---|---|
| 원고 | 실제 6통화 원고, 문장 근거 검토, 공개 출처 조건, 로컬 승인·익명 조회 | 해당 판본을 출시 후보로 고정. 고정 자료 한 번의 성공을 다른 날짜의 성공으로 표시하지 않음 |
| 데이터 | 대시보드 기준환율 스냅샷 재사용, 기사 거래일·가격 종류 분리 | 운영의 최신 데이터 커밋을 기준으로 릴리스 조립. 오래된 로컬 환율 파일을 운영에 덮어쓰지 않음 |
| 실행 | 기존 환율·메일 작업 뒤 별도 Actions job, 기본 무과금 plan, 서버 정책·제어·예산 검사 | 배포 후보의 실제 Actions 환경에서 의존성·새 수집·영속 저장·재개·실행 결과를 확인. 실제 실행·활성화는 별도 범위 |
| 권한·공개 | 격리 active admin 승인, 익명 공개 조회, 로그아웃 후 비공개 접근 차단 | 운영 callback·키·기능 플래그·migration 순서 확인. 서비스 키는 서버에만 두고 관리자·익명으로 최소 연결 확인 |
| 비용·실패 | 로컬 중복 방지, 요청 상한, 비용 미확정 예약, 한정 429 재시도 | 반복 운영 예산·경로·429 후 대응 확정. 미확정 비용을 0으로 계산하거나 일회 시험의 재시도를 운영 기본값으로 확대하지 않음 |
| 기존 서비스 | 로컬 환율·계획환율·메일 분리와 관련 회귀 검사 | 최신 운영 기준의 회귀·기능 끄기·복구 점검. 리포트 실패가 기존 갱신·메일을 막지 않아야 함 |
| 화면·메일 | 3메뉴, 공통 관리자 인증, 리포트 이력·상태, A안, 기본 이용 집계 구현 | 실제 6통화의 최종 화면·iPhone 열람·단위/출처 표시 정리. 이메일 2.0 제공 방식과 동작 확인 |
| 자원·복구 | 보존/경보 설계와 로컬 복구 시험 존재 | 운영 계정의 현재 용량·한도·백업 실재를 확인하고 초기 경보 값을 확정. 자동 삭제는 기존 별도 결정 유지 |

진입 경로 검사: `scripts/currency-report/operating-entry.test.ts`에서 workflow 환경의 무키 plan과 환율 갱신 미확인 execute를 검사했다. 공통 환율 로더를 대역으로 두고, 실제 조정기와 메모리 실행 장부·합성 수집을 사용한다. 새 두 사례와 기존 무인 동작 11사례, 총 13사례가 통과했다. 외부 요청·모델 전송·운영 변경은 0이다. 실제 GitHub Actions 또는 새 기사 내용의 검증으로 확대하지 않는다.

## 출시 후 첫 운영 평가

첫 10영업일에 실제 수집/판정/생성/검토/승인/공개를 관찰한다. 10건 미만이면 확보한 표본 수와 부족 이유를 보고하고 이후 축적한다. 보고서가 나오지 않는 날도 판정 기록은 확인한다.

| 관찰 항목 | 기록·판단 |
|---|---|
| 발행 판단 | 마지막 유효 발행본 대비 누적 ±2%, 14일 경과 후 첫 한국 월요일 점검, 중요 새 자료, 중복·보류 이유 |
| 실제 읽을 가치 | 환율 설명의 충분성·근거 충실도·변화 전달·가독성. 원인 불명과 시스템 실패를 구분 |
| 승인과 교정 | 검토 가능한 실제 초안 수·승인율·필수 교정 사유·검토 소요. 승인율 90%·평균 4/5는 초기 관찰 목표 |
| 누락과 과잉 | 중요한 변화 누락, 새 정보 없는 반복 생성, 정기 점검 누락. 발생 사례별 원인 분석 |
| 비용 | 수집/추출·대조/집필/검토별 실제 비용과 미확정 예약을 분리. 이번 개발 시험 비용을 일일 정상 비용으로 외삽하지 않음 |
| 신뢰성과 자원 | 공급자 429·시간 초과·조회 실패·재개·DB/Actions/전송 사용량. 제안 보존·경보 수치는 실측 후 조정 |
| 독자 이용 | 화면·리포트 열기·근거 확인 등 기존 익명 집계. 고유 독자 수나 정독으로 표현하지 않음 |

명백한 수치/방향/출처 오류, 비공개 자료 노출, 중복 과금, 무권한 공개는 평가일까지 기다리지 않는다. 해당 작업·원고의 공개를 기존 중지/철회 절차로 제한하고 기존 환율 서비스는 보존한다.
