# 현재 공급자의 현지 종가 제공 여부 — 공통 판단

2026-10-28 · 공식 정의·공개 생성 코드·저장 응답 대조 · 로컬 조사 문서

## 결론

**현재 수집 경로의 6개 통화 값을 국가별 현지 종가로 인증할 수 없다.** ExchangeRate-API/Open ER는 공개적으로 참고 중간환율을 제공한다. Currency API는 환산값과 생성 날짜를 제공하지만 국가별 원시 시장·호가 종류·마감 구간을 밝히지 않는다. Alpha Vantage의 일별 close도 국가별 현물시장 마감과 같다는 정의가 확인되지 않았다.

이것은 저장 숫자가 잘못됐다는 판정이 아니다. **참고환율로서의 정확성과 현지 종가라는 명칭의 적합성은 다른 문제**다. 새 가격으로 바꾸거나 기존 날짜를 전날로 이동하지 않았다. 대표 숫자는 대시보드와 리포트가 공유하며, 기사 가격을 대체 입력으로 쓰지 않는 사용자 결정은 유지한다.

이번 단계의 판단은 완료했다. 수집을 반복하면 종가 정의가 생길 것이라는 전제로 진행하지 않는다. 이후 작업은 아래 정의에 맞는 공통 가격 정책 설계이며, 이번 문서 자체는 공급자 교체·운영 변경·새 집필 승인에 해당하지 않는다.

## 판단에 사용한 자료와 한계

- 현재 로컬 `src/lib/api.ts`, `src/lib/merger.ts`, `.github/workflows/generate-data.yml`의 실제 선택 경로.
- 이전 작업의 저장 응답과 `price-provenance-hardening-20261028-bN6JCf/public-probe-authorized.json`, `provider-comparison.json`. 공개 API 응답은 10/28 13:48 UTC에 확보한 것으로 이번에 다시 가격을 조회하지 않았다.
- 저장된 10/28 배포 정적 JSON. 현재 운영 DB의 실시간 값으로 간주하지 않는다. 이전 실행에는 공급자 기록이 없으므로 숫자 일치만으로 당시 공급자를 확정하지 않는다.
- 10/28 재확인한 공급자 공식 문서, 공개 생성 소스, 각국 공식 가격 정의. 링크는 아래에 직접 표시한다. Currency API `main` 소스는 조회 당시 문서 증거이며, 과거 배포에 그 코드가 실행됐다는 증거가 아니다.
- 기존 PEN 정상/실패 응답, BRL PTAX·ARS 공식 기간 응답 검토를 재사용했다. 최신 시리즈 전체의 새 숫자 대조나 다일 오차 분석은 수행하지 않았다.

ECB 자료를 원천으로 쓰는 경우에도 [ECB 자체 정의](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)는 유럽 시간 기준 참고환율이다. 다만 이 설명으로 현재 Frankfurter 모든 행의 원천을 ECB로 단정하지 않는다.

## 6개 통화의 현재 경로와 공식 대조 기준

아래 최신 우선 경로는 **응답 성공·같은 날짜·유효 숫자라는 조건하의 코드 선택 순서**다. 장애·날짜 차이·캐시 때문에 실제 행은 달라질 수 있다. 실행 계보가 없는 과거 저장 행에 이 이름을 역으로 붙이지 않는다.

| --- | --- | --- | --- |

공식 근거와 필요한 구분:

- **BRL:** [BCB PTAX 데이터 정의](https://dadosabertos.bcb.gov.br/pt_BR/dataset/dolar-americano-usd-todos-os-boletins-diarios). `Fechamento`라는 이름만으로 마지막 체결가를 뜻하지 않는다. 기존 저장 PTAX 응답의 개장/중간/마감 구분과 네 조사 평균 검토는 유효하나 현물 종가 승인으로 승격하지 않는다.
- **MXN:** [Banxico FIX/마감 구분](https://www.banxico.org.mx/tipcamb/llenarTiposCambioAction.do?idioma=sp&usarCache=false), [마감 산정 방법](https://www.banxico.org.mx/apps/dao-web/4/60/DETERMINACION_DEL_TIPO_DE_CAMBIO_DE_CIERRE_DE_JORNADA.pdf). 공식적인 마감 기준 후보가 실제로 있다. 다만 마지막 한 건의 체결가가 아닌 정해진 구간의 기준값이며 결제일 T+2와 관측일을 혼동하지 않는다.
- **CLP:** [BCCh Dólar observado 방법론](https://si3.bcentral.cl/estadisticas/Principal1/Metodologias/EC/PARIDADES/Dolar_observado.pdf). 전 영업일 평균이며 공표일·적용일을 그날 종가의 거래일로 쓰지 않는다. 기존 BCCh 연결 성공만으로 현물 종가 확보가 된 것은 아니다.
- **COP:** [SFC TRM 정의](https://www.superfinanciera.gov.co/publicaciones/60819/informes-y-cifrascifrasestablecimientos-de-creditoinformacion-periodicadiariatasa-de-cambio-representativa-del-mercado-trm-60819/). 거래액 가중평균이라는 정의는 확인했다. 주말/휴일 유효 구간과 원거래일의 개별 매핑은 별도 캘린더 검증이 필요하다.
- **PEN:** [BCRP 계열 목록](https://estadisticas.bcrp.gob.pe/estadisticas/series/diarias/tipo-de-cambio), [SBS 평균 산정 방법](https://www.sbs.gob.pe/app/stats/metodologia/metodologia_07_2018.pdf). 마감 매도 계열의 존재와 13:30 표기는 확인했다. 이번 개별 시리즈 HTML은 시간 초과였고 기존 정상 JSON의 10/26 `n.d.`는 유지했다. 자료 공백·응답 오류와 방법론 부재를 구분한다. 목록의 시각만으로 IANA 시간대와 실제 관측 타임스탬프를 생성하지 않는다.
- **ARS:** [BCRA A8359 원문](https://www.bcra.gob.ar/Pdfs/comytexord/A8359.pdf). 2026-01-02 시행 문서에 적격 거래 가중평균을 명시한다. 옛 조사 방식 설명을 2026 자료에 재사용하지 않는다. 미국 휴일에는 거래 종목 선정 예외도 있으므로 통화 코드만으로 같은 가격 종류라고 보지 않는다. 도매 참조와 기사 도매 마감의 숫자가 가까워도 동일 계열의 증거가 아니다.

## 한국 오전 수집의 의미

로컬 정기 작업은 UTC 00:15, 한국 09:15로 설정돼 있다. 이는 수집을 시도하는 시각이지 원시 시장 가격의 시각이 아니다. 관찰한 Open ER 갱신 00:02:31 UTC는 한국 09:02:31이지만, 그 자료가 전일 특정 시장 종가라는 뜻은 아니다. 정적 배포본의 `fetchedAt`은 별도 생성 실행 시각이다. 이번에는 실제 운영 스케줄 이행 여부를 새로 점검하지 않았다.

따라서 다음을 분리한다: **현지 가격 산정 구간 → 공급자 공표/갱신 → 우리 수집 → 화면 표시일**. 주말·현지 휴일·미국 휴일·지연/수정 공표까지 있어 일괄 `날짜 - 1`로 고칠 수 없다. 원천에 없는 마감 구간은 더 자주 호출해도 복원되지 않는다.

## 공통 정책에 대한 판단과 다음 작업

### 유지할 확정 사항

1. 대시보드와 리포트는 같은 확정 데이터 스냅샷·값·계산을 사용한다. 기사 수치는 출처에 귀속한 참고값이다.
2. 현재 자료는 공급자가 밝힌 참고환율/미확인 가격 기준 그대로 다룬다. 종가 인증 실패를 수치 오류나 기존 서비스 장애로 확대하지 않는다.
3. 날짜·공급자·기준이 다른 값 사이의 변화를 하루 시장 움직임으로 단정하지 않는다. 새 공통 가격 기준으로 전환할 때 누적 2% 발행 기준의 기존 기준점도 호환 검증한다.
4. 자료를 못 구한 날 평균·종가·타 공급자 값을 조용히 섞지 않는다. 이전 유효 자료의 날짜와 상태를 유지한다.

### 권장 다음 설계 — 아직 구현/교체 승인 아님

**먼저 대시보드와 리포트가 함께 사용할 ‘가격 정의 계약’을 정한다.** 모든 국가에 같은 합격 조건을 적용하되 각국 시리즈 정의를 등록한다.

- 필수 정의: 시장/계열, 단위, 매수·매도·중간값, 산정 시각 또는 구간, 시간대, 실제 대상 거래일, 게시/적용일, 휴일 규칙, 수정·확정 상태, 사용 조건.
- MXN·PEN은 이미 확인한 공식 마감 기준을 대조 후보로 쓸 수 있다. 최신 연속 응답·시계/시간대·이용 조건은 별도 확인한다.
- BRL·CLP·COP·ARS는 확보한 공식 평균값을 억지로 ‘종가’로 부르지 않는다. 종가 제공 경로의 정의를 확보하거나, ‘공식 일별 기준환율’로 서비스 목적에 맞게 채택할지를 결정해야 한다. 자동 교체하지 않는다.
- 종가가 최우선 요구라면 무료로 그 정의를 충족하는 원천이 있는지 검증하고, 없다면 종가 미지원으로 명시한다. 공급자 여러 개의 평균을 자체 종가로 만들지 않는다.
- 기존 숫자를 유지하는 동안 시장 해설을 별도 거래일의 출처 귀속 설명으로 보여주는 방안은 가능하지만, 현재 대표 숫자의 직접 원인이라고 연결하는 방식은 별도 승인/설계 없이 완화하지 않는다.
- 실제 교체 제안 전에는 같은 날짜 표기만이 아니라 **같은 가격 종류·실제 거래 구간**으로 최근 관측·주말·휴일·급변 구간을 비교한다. 수치·월평균·계획 대비·메일·발행 임계값 영향까지 확인하고 한 공통 데이터 경로에서 전환한다.

현재 공급자의 나라별 현지 종가 여부 판단은 **완료**, 현지 종가 공급 체계 확보는 **미완료**다. 다음 담당 작업은 이 계약과 전환 비교 설계(Astra High), 그 후 로컬 검증/기사 기간 연결/데이터 버전이 일치하는 저장 전달(Sol High)이다. 공급자를 바꾸기 전에 운영 DB 전송만 먼저 확장하는 일을 종가 문제의 해결로 보지 않는다.
