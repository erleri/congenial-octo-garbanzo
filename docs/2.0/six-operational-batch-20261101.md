# 6통화 첫 운영 경로 실행 / 2026-11-01

## 사용자 지시와 실행 경계

칠레 한 건의 선별 시험 대신 BRL·MXN·COP·PEN·CLP·ARS 전부를 공통 운영 절차로 처리한다. 변동이 좁은 사례를 급변 리포트로 강제하지 않고 첫 정기 점검으로 시작한다. 수동 기사 선별·원고 교정·검사 우회·재시도·백업 모델·자동 게시를 하지 않는다. 기존 원고·환율·비용 이력과 운영 서비스는 보존한다.

이 문서는 실제 모델 생성 결과가 아니다. 사용자가 6통화 총 최대 $7·최대 60회 예산을 승인했다. 다만 자동 승인 검토가 수집 본문을 OpenRouter로 전송하는 실행 코드 추가를 ‘원문 payload와 구체적 외부 목적지에 대한 명시적 승인 부족’ 사유로 차단했다. 실행 파일은 생성되지 않았고 호출·지출·신규 원고·DB 활성화는 0이다. 본문·출처 URL·발표시각을 OpenRouter Chat Completions API와 Azure 경로 GPT Sol에 보내는 범위만 추가 확인 중이다. 예산을 다시 승인받는 절차가 아니다. 이전 칠레 최대 $0.83 제안은 이번 6통화 요청으로 대체됐고 실행하지 않았다.

## 하나의 실행 경로

`runOperationalReportBatch`가 동일한 기준환율 스냅샷·국가별 등록 출처 자료·검토 정책·예산을 고정한다. 원문 추출 → 다른 요청의 원문 대조 → 자체 사실·귀속 견해 카드 → 기존 공통 자료 연결 → `prepareRuntimeTask` → DB 입력 등록/재조회 → 기존 `runRuntimeWorker`의 집필 → 구조 검사 → 별도 문장 검토 → 비공개 승인 대기 또는 보류 순서다. 국가별 별도 원고·프롬프트를 주입하지 않는다.

원문은 기사 추출/대조 요청에만 전달하고 집필에는 검토된 자체 카드만 전달한다. 수집만 된 기사나 카드만 검토한 결과를 원문 검증 성공으로 세지 않는다. 저장된 소비·정책 근거를 재사용할 때도 원래 대상 기간·출처·사용 범위를 유지한다. 조사 목표 날짜는 실제 거래일을 입증하지 않는다.

한 국가의 자료·구조·내용이 부족하면 결과와 비용을 보존하고 다음 통화를 처리한다. 비용 미확인 또는 유료 응답 저장 실패는 전체 다음 호출을 중단한다. DB의 예약·중복·비활성·월 한도 검사와 별도로 묶음 전체 예산·최대 호출 수를 검사한다. 모델의 채점 통과는 관리자 게시 승인이 아니다.

## 첫 정기 점검

유효한 이전 공개 발행본이 없을 때 가짜 비교본을 만들지 않는다. 새 `initial-reference-check/1` 계약이 `previousReportId=null`과 전회 누적 비교 없음, 전 관측 기준환율 비교만 있음을 집필/검토 양쪽에 전달한다. 이것은 ‘가격 변동이 작았다’는 증거가 아니다.

첫 점검의 현재 근거가 현지 해석을 지지하면 최대 두 설명을 넣는다. 원인 근거가 없으면 drivers를 비워 두며 소비·정책 배경으로 대체 원인을 만들지 않는다. 검토된 설명 또는 소비·정책 배경이 하나도 없으면 집필을 보류한다. 기존 출처 사용·가격·기간·필수 의존 근거·귀속·본문/문장 검사는 유지한다. 일반 급변 리포트의 원인 근거 필수 조건은 낮추지 않는다.

첫 점검은 공개 후보의 `purpose=periodic_check`로 보존한다. 실제 승인 발행된 뒤에는 그때 고정한 기준환율/게시일로 기존 누적 2%·2주 후 월요일 점검 판단을 한다. 실제 발행 전 초안은 기준점을 옮기지 않는다.

격리 로컬 DB에서 확인한 유효한 운영 발행 기준점은 6통화 모두 0이다. 합성·과거 검토 표본을 실제 발행본으로 승격하지 않았고, 이것을 운영 DB의 발행 현황이라고 주장하지 않는다. 이번 로컬 묶음은 여섯 통화 모두 첫 점검으로 준비했다.

## 검증과 남은 문제

첫 점검에서 배경만 있을 때 원인 문단을 만들지 않는 경우, 빈 설명을 성공으로 처리하지 않는 경우, 기존 발행본이 있을 때 첫 점검으로 돌아가지 않는 경우를 검사했다. 공통 묶음은 한 국가의 보류 후 계속 진행하며 실제 전송 시간 초과·비용 미확인 후 다음 국가의 호출을 차단하는 합성 통합 사례를 검사했다. 이는 실제 원고 품질 표본이 아니다.

기존 A안에서 정기 점검 제목은 ‘이번 점검 배경’으로 구분하고 원인 문단이 비었으면 빈 원인 영역을 표시하지 않는다. 원고의 문장을 편집하는 처리가 아니다.

**실제 공개 전 남은 DB 문제:** 현재 격리 DB의 `app_private.review_currency_report(uuid,text,text)` 메타데이터 검사는 `economic_update`와 `fx_explanation`만 허용한다. `periodic_check` 승인은 현재 차단된다. 기존 원고의 purpose를 몰래 바꿔 승인하지 않는다. 이번 실제 생성은 비공개 후보 저장까지이며, 공개 승인 경로의 호환 변경·권한 검증은 게시 전에 별도로 완료해야 한다. 이번 단계에서 이 함수나 운영 DB를 변경하지 않았다.

격리 DB는 생성·검토 비활성, 월 한도 0으로 유지했고 미확인 작업은 0건임을 읽기 전용으로 확인했다. 신규 예산 승인이 있어야 이번 로컬 실행만 명시적으로 활성화하고 종료 후 비활성화한다. 기존 비용·실행 이력은 삭제하지 않는다.
