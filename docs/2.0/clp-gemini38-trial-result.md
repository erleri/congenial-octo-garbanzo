## 입력과 형식

- 기존 최종 입력 해시: `39c2572d538812e2ef05d4eca0cda3e0113e055c9ad67463cce4c8b17c7515f0`.
- Gemini 최초 요청 해시: `82da3ccfe1141538230e15ba51a096d51bed64455cabb3804518a3151095d0d7`.
- 수정 요청 해시: `03a46ff5801d86f7f97d1144352c0193e97c88649a011ba07748258520f60df1`.
- 환율 사실·254개 관측값·세 출처·두 메시지는 기존 고정 입력과 동일하다. 모델·제공 경로·출력 토큰 필드만 Gemini에 맞췄다. 추론 medium, 출력 최대 8,192토큰, 검색 도구 없음.
- 최초 400의 메시지는 세부 필드를 특정하지 않는다. 원인을 특정 스키마 속성으로 확정하지 않았다. Google은 스키마의 일부만 지원하며 큰 형식을 거부할 수 있다고 안내한다. 이에 전송 스키마의 문자열 길이·패턴·배열 개수 제한을 제거해 간소화했다. 수정 요청은 즉시 거부되지 않았으나, 수락·생성 성공을 입증하는 응답은 없었다. [Google 구조화 출력 안내](https://ai.google.dev/gemini-api/docs/structured-output).
- 응답 후 원래 전체 스키마·근거·편집 규칙을 적용하는 코드는 그대로다. 합성 검증에서 간소화한 전송 형식이 있어도 긴 본문과 미등록 출처는 애플리케이션에서 거부됨을 확인했다. 실제 Gemini 출력 검증은 미실행이다.
- 캠페인별 폴더 잠금은 중복 실행을 차단한다. 최초 실패 파일을 수정하거나 추가 실행으로 덮어쓰지 않았다.
