## 이번에 바로잡은 검사

- 편집 오류 연결 테스트는 이전 스키마의 초안이 먼저 거부되어도 성공했다. 현재 ledger를 포함하고 안전성 통과 후 정확한 편집 실패를 확인한다.
- 오래된 근거 검사는 평온한 변동 게이트에서 먼저 거부되어도 성공했다. 정상적으로 검토 단계에 도달하는 notable 자료에서 발표일만 바꿔 `no_recent_explanatory_evidence`를 확인한다.
- 한 테스트에 없는 제목·없는 출처·중복 경로를 함께 넣던 검사를 분리했다. 이름에만 있던 관찰 목적 검사는 실제 watch 본문을 추가한 정상 자료에서 목적만 제거한다.
- 동일 해시를 자기 자신과 비교하던 검사를 제거했다. 패킷 해시는 수치·출처 변경과 수집 시각 변경의 대비로 검사하며, 블라인드 순서는 명시적인 기대 순서와 원본 배열 보존으로 확인한다.
- 기존 다통화 계산은 단순한 `not null` 대신 알려진 날짜·수치로 확인한다. 기본 자료에는 실제 업무 관측일만 넣고, 주말 보간은 별도 사례에서 확인한다. 기존 다통화 MTD는 월초 관측값, 새 통화별 패킷은 전월 마지막 관측값이라는 기존 차이를 유지한다.
- 백업과 편집 파일의 중복 요청 계약·개인정보 검사표를 요청 계약 담당 파일로 모았다. 캐시 파일의 이력 선택 검사는 탐색 담당 파일로 옮겼다.
- 동일 합성 사례 16건을 단위 테스트와 평가 명령 양쪽에서 합산하지 않는다. 평가 명령에서만 별도로 보고한다.

## 실행과 집계

생성·검토 구조 보강의 책임은 기존 파일을 확장한다. `openrouter.test.ts`는 AI 영업 문구 차단과 승인된 고정 문구/대응표 조립을, `packet.test.ts`는 관측·수집 시각과 제공 경로를, `claim-review.test.ts`는 세부 주장 전체 범위·개별 인용·약한 판정의 전체 반영과 코드 문구 교정 차단을 담당한다. `metadata.test.ts`는 표시 시각·출처 유형의 호환 경계만 담당하며 환율 계산이나 의미적 지지 검사를 반복하지 않는다. 공통 USD 적용 합성 자료는 rule-fixtures에서 공유한다.

`claim-review.test.ts`는 `claim-review/2`의 필수 교정·편집 권고·확인 대기 분류도 담당한다. 기존 선택적 교정·원문 미확인 검사를 확장하고, 유형/지지 여부/처리 불일치와 편집 권고만 있을 때 교정 호출이 없는 경계를 검증한다. 명시적으로 제공한 검토 판단을 분류하는 합성 계약 검사이며 한국어 문장의 의미를 자동 판별했다는 증거로 계산하지 않는다. 실제 칠레 원고의 쟁점 재분류는 별도 정책 문서에 기록한다.

- `npm test`: 단위/연결 검사, 중복 감사 장치 자체 검증, 실행 결과 감사. 미대체 fetch 호출은 예외가 잡혀 숨겨져도 테스트를 실패시킨다. Node의 다른 네트워크 API 전체를 차단하는 샌드박스라고 주장하지 않는다.
- `npm run report:rules`: 합성 16건과 기존 저장 원고의 별도 재평가. 새로운 API 호출·비용 없이 원고를 보존한다.
- `npm run check`, `npm run build:report`: 정적 검사·회귀·운영 번들 경계와 별도 리포트 빌드. 테스트 실행 중 실제 API 키나 제공자 연결을 요구하지 않는다.

집계는 파일 수, 테스트 선언 수, 표 입력을 펼친 실행 사례 수로 나눈다. 중복 이름은 파일과 전체 제목의 조합으로 검사하고, 공백·주석을 제외한 동일 callback 및 자기 비교도 실패시킨다. 서로 다른 변수명으로 복사한 테스트나 의미적 중복까지 자동 판별하는 것은 아니다. 위 책임표와 코드 검토를 함께 사용한다.

원시 실행 결과와 최신 집계는 Git에서 제외된 `.local-reports/private/unit-tests.json`, `test-inventory.json`에 저장한다. 감사 장치 자체의 4개 확인은 제품 테스트 수에 포함하지 않는다.
