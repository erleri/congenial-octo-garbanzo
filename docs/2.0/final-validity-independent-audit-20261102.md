# 현재 유효성·준비 복구 수정 후 독립 점검 — 2026-11-02

후속: 아래 V1·V2는 [공통 수정·검증 결과](validity-error-and-news-scope-fixes-20261102.md)에서 보완했다. 이 문서는 당시 결함과 재현 기록으로 보존한다.

## 판정

**자동 운영 최종 합격은 보류한다.** 앞서 수정한 F1(사용한 근거 철회 차단), F2(준비 조건만 복구된 국가의 독립 진행)의 기존 재현 경로는 통과했다. 그러나 인접한 두 경계에서 공통 결함을 추가로 재현했다. 둘 다 잘못된 원고를 공개하거나 추가 과금을 일으킨 사례는 아니며, 필요한 복구 경고가 사라지거나 정상 원고의 검토 재개가 막히는 운영 문제다.

이번 작업은 점검과 재현이다. 제품 코드·SQL 정의·기존 원고·환율·운영을 변경하지 않았다. 외부 뉴스·실제 모델 호출과 신규 비용은 0이다.

## V1 — 저장 무결성 오류가 일시 조회 장애로 바뀜 (중간)

위치: `scripts/currency-report/operating-cycle.js:212`, `runtime-store.js:8`, `operating-result.js:20`.

재현 순서:

1. 원고 작성은 끝났고 원고 검토만 사전 대기 중인 국가를 준비한다. 나머지 5개국은 관리자 승인 대기다.
2. 실제 `createRuntimeStore` 복원 함수에 합성 RPC 응답을 주입한다. 저장된 JSON과 비교용 표현을 다르게 만들거나, 원래 JSON 보존 필드를 제거한다.
3. 저장 어댑터는 각각 `runtime_stored_projection_changed`, `runtime_exact_bytes_missing`을 정확히 던진다.
4. `beforeCountry`가 두 오류를 일반 RPC 장애와 동일한 `catch`에서 삼켜 `frozen_source_refresh_wait`로 바꾼다.
5. 두 번 연속 실행해도 `resume_saved_stages`가 유지되며, 전체 결과는 다른 국가의 승인 대기 때문에 `review_wait`, 종료 코드 0이다. 추가 호출 0, 초안 추가 0.

6통화 각각에서 두 무결성 오류와 정상적인 RPC 장애 대조군을 확인했다. 실제 DB 자료가 손상됐다는 뜻은 아니다. 합성 손상 입력을 **실제 저장 어댑터**로 복원했을 때의 공통 처리 결함이다.

원인: 코드 작성 시 `assertStagedRuntimeInput`이 조회 뒤에 있다는 점만 봤다. 실제 어댑터는 조회 Promise가 반환되기 전에 이미 원본 JSON/표현의 일치 여부를 검사한다. 따라서 무결성 오류도 조회 실패를 처리하는 `catch`에 들어간다. 앞선 “저장 자료의 결합/무결성 오류는 일시적 조회 실패로 숨기지 않는다”는 설명은 이 경로에서는 맞지 않았다.

수정 요구:

- 확인된 일시적 저장소/전송 오류만 재개 대기로 분류한다.
- 원본 보존 필드 누락·JSON 복원 실패·표현 불일치·결합 오류는 원래 이유를 유지한 복구 필요 상태로 전달한다. 알 수 없는 오류를 임의로 일시 장애로 낮추지 않는다.
- 다른 국가의 승인 대기가 기술적 복구 필요 경고를 가리지 않게 한다.
- 실제 어댑터에서 오류가 발생하는 위치를 포함해 검사한다. 단순히 가짜 저장소가 네트워크 오류를 던지는 시험으로 대신하지 않는다.

## V2 — 미사용 기사의 철회가 정상 원고의 작업까지 종료 (중간)

위치: `scripts/currency-report/operating-cycle.js:157`, `operating-cycle.js:229`, `operating-refresh.js:33`.

재현 순서:

1. 같은 국가의 기사 A는 채택하고 기사 B는 이미 반려해 집필 입력에서 제외한다.
2. A만 사용한 원고 작성은 완료하고 원고 검토만 대기시킨다. 실제 등록 입력의 `materialEditions`에 B가 없음을 확인한다.
3. B의 판정만 명시적으로 철회한다. A·환율·원고·요청은 그대로다.
4. `frozenSourceReviewHolds`는 사용한 기사만 검사하여 정상 통과한다.
5. 그러나 별도의 `classifyCountryRefresh`는 수집 전체의 검토 판정 변경을 감지한다. `countryChanges`의 `frozen_country_material_superseded`가 적용되어 원래 작업을 종료한다.

반복 운영 합성 시험에서는 6통화 모두 같은 현상이 발생했다. 다음 실행에서 새 배치를 만들어 남은 검토 1회로 복구했으나, 불필요한 배치 종료와 한 실행 주기 지연이 생긴다.

**격리 DB의 실제 저장 어댑터·설치 SQL에서도 일회 시험으로 확인했다.** 원래 작업 종료 뒤 후속 실행 두 번 모두 `one_time_scope_or_expiry_hold`가 되었고 남은 검토는 실행되지 않았다. 시험 유효기간은 남아 있었으며, 새 배치가 일회 승인 범위에 포함되지 않아 차단된 것이다. 예산 제한은 올바르게 작동했다. 고쳐야 할 부분은 그 제한이 아니라, 무관한 기사 변경 때문에 원래 정상 작업을 종료한 판단이다.

원인: “사용한 출처만 검사”는 새 유효성 검사 함수 한 곳에만 반영됐고, 기존 전체 자료 변경 판정에는 연결되지 않았다. 기존 단위 시험도 함수만 직접 호출하므로 뒤의 종료 처리를 지나지 않았다.

수정 요구:

- 집필 입력이 확정된 작업은 해당 입력에 실제 연결된 근거의 유효성 변화와, 탐색 후보 전체의 변화를 구분한다.
- 미사용 기사 판정만 바뀐 경우 새 탐색 기록은 보존하되, 정상 원고의 남은 검토는 원래 작업·요청·승인 범위에서 재개한다.
- 사용한 근거 철회, 실제 가격 변경, 원고에 영향을 주는 근거 수정의 기존 차단은 유지한다. 모든 자료 변경을 무시하는 완화로 해결하지 않는다.
- 전체 실행 경로와 실제 SQL 일회 승인 경계를 함께 검증한다.
