# LATAM FX 리포트 자료 탐색 설계

리포트의 목적에 따라 답해야 할 질문을 정하고, 저장 자료로 답할 수 없는 부분만 공식 통계와 원문에서 보충한다. 기사 수나 평가 점수를 높이기 위한 자료 추가는 하지 않는다. 이번 범위는 기존 코드 조사와 설계이며 수집 자동화나 새 원고 생성의 완료를 뜻하지 않는다.

2026년 10월 13일 로컬 `codex/2.0-local-experience`의 `b08305e` 기준으로 조사했다. 기존 A안, 공개 보고서 계약, 승인 기록, 원문과 비용 기록을 유지한다. 유료 검색·AI 호출, 운영 설정·배포·DB 변경은 포함하지 않는다.

## 현재 기능과 보강할 부분

| 영역 | 확인한 현재 동작 | 취사선택 |
| --- | --- | --- |
| 질문별 탐색 | [research-harness.js](../../scripts/currency-report/research-harness.js)의 여섯 고정 질문과 최대 회차·쿼리·후보 제한 | 탐색 루프·상한·질문 연결은 재사용. 목적별 질문 선택을 추가 |
| 조사 자격 | 같은 파일은 market·local·global·counter를 필수로 요구하고 consumer는 선택으로 처리 | 환율 해설의 기존 계약은 유지. 경제 업데이트에 동일한 필수 질문을 강제하지 않음 |

| 공식 일정 | [official-events.js](../../scripts/currency-report/official-events.js)는 일부 API·RSS·ICS와 CLP·MXN 수동 경로를 구분 | 일정 탐지와 수동 반입 유지. 예정일을 발표 완료로 승격하지 않음 |
| 근거 검토 | [evidence-scope.js](../../scripts/currency-report/evidence-scope.js)의 원문 바인딩, 대상·기간·비교·범위 검사와 복수 출처 연결 | 그대로 재사용. 탐색 성공과 의미 검토 성공은 별도 |
| 생성 판정 | [generation-decision.js](../../scripts/currency-report/generation-decision.js)는 사건 신규성·중복 및 economic_update 등의 목적을 구분 | 새 근거를 해당 판정에 연결. 다운로드 성공만으로 새 집필을 허용하지 않음 |
| 집필 연결 | [report-harness.js](../../scripts/currency-report/report-harness.js)의 근거 검사 후 요청 준비와 문장별 검토 | 보강 근거를 새 패킷에 연결. 과거 패킷·검토를 덮어쓰지 않음 |

별도 검색 엔진이나 검토 시스템을 하나 더 만드는 대신 기존 탐색기의 앞에 질문 계획을, 원문 채택 전에 통계 비교 검사를 넣는다. 현재 CLI는 수집 모드에서도 모델 비교 요청 준비를 먼저 수행하므로, 새 무비용 탐색 명령은 이 의존성을 분리해야 한다. 검색에는 작성 모델·API 키·비용 산정용 요청 본문이 필요하지 않다.

## 질문을 고르는 기준

보고서 목적과 이미 확인된 사건을 입력으로 받는다. 최초 구현은 코드에 등록된 질문 템플릿과 검토자가 선택한 목적을 사용하며, 계획을 세우기 위해 AI를 호출하지 않는다.

| 목적 | 필수 확인 | 선택적 보충 질문 |
| --- | --- | --- |
| 환율 해설 | 저장 환율의 관측 기준, 사건과 시장 반응, 주요 반대 근거 | 해당 사건과 관련이 있을 때 소비·구매 여건 한 가지 |
| 정책 업데이트 | 실제 결정과 이전 결정의 차이, 적용 조건 | 시장 반응 또는 관련 금융 여건 |
| 경제 소비 업데이트 | 발표 내용·대상 기간·이전 비교, 지표 범위 | 실제 소비·관련 품목·구매 여건 중 부족한 질문 최대 두 가지 |

현재 칠레처럼 실질보수 자료가 있으면 `실제 소비도 같은 방향인가`를 우선 후보로 삼는다. 관련 소매 지표가 확인되면 `전자제품·가정용품 분류도 전체와 같은가`를 두 번째 질문으로 선택할 수 있다. 이미 충분한 답이 있거나 원고 목적과 관련이 없으면 선택하지 않는다. 금융 여건까지 자동으로 덧붙이지 않는다.

각 질문에는 다음을 사전에 기록한다.

- 왜 필요한가: 원고에서 아직 답하지 못하는 독자의 질문.
- 무엇이 답이 되는가: 국가·지표·모집단·상품/채널·대상 기간·비교 기준.
- 어떤 답도 허용하는가: 증가·감소·정체·불일치 모두 동일한 채택 조건. 기대 결론을 검색 조건으로 쓰지 않음.
- 어디까지 말할 수 있는가: 기술적 비교인지 시장 귀속인지. 인과는 별도 근거가 필요함.
- 없어도 작성 가능한가: 핵심 질문이면 보류, 선택 질문이면 생략하고 확보된 근거 범위로 작성.

`자료 미확보`만으로 질문이 답변됐다고 처리하지 않는다. `비교 불가`를 확인한 경우도 답이 있는 것과 별도로 기록하고, 유용성이 없으면 본문에 경고를 추가하지 않는다.

## 자료 탐색과 재사용 순서

1. 동결된 환율·기존 근거·보고서 목적·기준시점으로 질문 계획을 만든다.
2. 원문 해시와 지표 식별자로 저장 자료를 찾는다. 대상 기간·버전·재사용 조건·기존 검토가 유효하면 재사용한다.
3. 국가별 등록 출처의 발표 목록·통계 표·API를 먼저 확인한다. 등록된 경로로 찾지 못한 부분만 허용 도메인 검색으로 보충한다.
4. 필요한 원문·표·주석을 확보한다. PDF/표 추출 실패는 수동 반입으로 전환할 수 있으나 자동 성공으로 기록하지 않는다.
5. 시점·수치·범위와 질문에 대한 실제 지지를 검토한다. 같은 원문의 번역·재배포는 독립 근거로 세지 않는다.
6. 채택 근거와 미해결 질문으로 새 패킷·근거 범위 카드를 만든다. 검토 완료 후에만 기존 집필 준비 경로로 넘긴다.
7. 기존 생성 판정에서 새 사실/설명인지 확인한다. 새 자료가 있어도 기존 설명과 같으면 생성하지 않는다.

질문에 충분한 답이 있으면 전체 회차를 채우지 않고 종료한다. 반대 근거 검토는 원문의 조건·범위·반대 방향 자료를 확인하는 과정이지 반대 기사를 한 개씩 강제로 찾는 절차가 아니다.

## 출처와 통계의 내부 계약

공개 `CurrencyReport`와 URL은 바꾸지 않고 다음 계약을 로컬 비공개 자료에 추가하는 안이다. 기존 원문·scope 검토 필드를 재사용하고 같은 의미의 승인 플래그를 중복 만들지 않는다.

### 출처 등록

`sourceId`, 국가, 제공 지표, 공식 랜딩 URL, 검토된 조회 URL/호스트, 접근 방식, 인증 필요 여부, 발표 주기, 지원 기간, 시계열·분류 코드, 재사용 조건과 확인일, 어댑터 버전, 변경 탐지 방법을 기록한다. 공개 접근 가능성과 AI 입력·공개 재사용 허용은 별개다. URL에 포함된 토큰은 저장·로그·AI 입력에서 제거한다.

CLP의 INE 소매 전체·관련 상품군을 첫 연결 대상으로 하고, BRL·MXN은 같은 계약의 지원 상태만 먼저 등록한다. 각국에 정확히 같은 상품 분류가 있다고 가정하지 않는다. 기존 이용 조건 조사 문서인 [source-feasibility.md](source-feasibility.md)를 재사용하되 실제 채택할 표의 조건과 접근 상태를 다시 확인한다. 새로운 인증이나 구독을 자동 진행하지 않는다.

### 통계 관측

`seriesId`, `sourceId`, 대상 기간 시작/끝, 값, 단위, 명목/실질/판매대수, 계절·달력 조정, 비교 기준, 기준연도, 국가·지역, 품목 분류, 채널, 모집단, 발표 시점과 정확도, 수집 시점, 자료 버전, 원문 해시, 표·셀·주석 위치를 보존한다.

명목 판매금액과 물가 조정 지수는 구분한다. 실질 지수도 특정 제품의 판매대수가 아니다. 전체와 세부 품목은 분류 정의가 확인돼야 비교한다. 온라인 통계만으로 전체 시장의 증가를 말하지 않는다. 월간 실질보수와 소매판매를 같은 달로 맞춰도 두 지표 간 인과가 입증되는 것은 아니다.

### 탐색 기록

`researchPlanVersion`, `planId`, 입력 패킷 해시, 목적, 기준시점, 질문과 필요성, 예상 근거 범위, 질문별 예산, 수집 결과, 채택/배제 이유, 미해결 사유, 기존 사건과의 관계를 저장한다. 자료 상태·작성 자격·내용 품질·게시 승인을 합치지 않는다.

질문별로 `available`, `not_yet_released`, `no_matching_series`, `access_failed`, `extraction_failed`, `terms_unverified`, `stale`, `scope_mismatch`, `conflict`, `historical_version_unverified`, `review_pending`를 구분한다. 미발표는 공식 일정·기관 안내로 확인해야 하며 빈 검색 결과는 `no_matching_series`의 확정 근거도 아니다. 검색했으나 확인 못한 경우에는 `review_pending`과 `not_found_in_attempt` 사유를 남긴다.

## 기준시점과 수정본

월간 지표는 보고서 당일 발표가 아니어도 최근 맥락으로 사용할 수 있다. 단순히 30일 전이라는 이유로 유효한 분기 지표나 과거 비교 자료를 삭제하지 않는다. 시리즈 주기와 예정 발표를 기준으로 최신성을 판단하고 지연·미확인을 표시한다.

기존 10월 9일 사례에는 그 기준시점에 이용 가능했던 자료만 당시 근거로 채택한다. 나중에 수정된 현재 시계열을 당시 값으로 위장하지 않는다. 최초 발표본이나 보존한 당시 응답을 확보하지 못하면 역사 버전 미검증으로 두거나 별도 사후 분석으로 분리한다. 발표 날짜만 있으면 장중 이용 가능 여부까지 보장하지 않는다.

새 수정본은 새 버전으로 추가한다. 기존 보고서의 수치·차트·본문은 고정하고, 중요한 수정은 별도 검토 사건으로 넘긴다. 캐시 키는 URL만이 아니라 출처·시리즈·범위·기간·버전으로 구성한다. ETag 등은 지원하는 출처에서만 활용하며 원문 해시 비교와 발표 일정 확인을 대체하지 않는다.

## 초기 실행 상한

아래 값은 최초 로컬 구현·측정용 제안이지 이미 동작하는 설정이 아니다.

| 항목 | 초기 상한 |
| --- | --- |
| 선택 보충 질문 | 최대 2개 |
| 외부 검색 | 전체 최대 4회, 질문별 최초 1회 우선 배정 후 남은 한도만 재탐색 |
| 원문 또는 표 확보 | 전체 최대 6개, 선택된 각 질문에 최소 1개 시도 슬롯 예약 |
| 총 HTTP 요청 | 검색·목록·표·원문·재확인을 합해 최대 12회 |
| 실행 시간 | 전체 120초, 개별 요청 15초 이하와 남은 전체 시간 중 짧은 값 |
| 응답 크기 | 전체 12MB, 개별 2MB. 초과 파일은 자동 분할/무제한 재시도하지 않고 별도 수동 검토 |
| 유료 호출 | 0회. 인증·과금 경로는 자동 대체하지 않음 |

원문과 표를 하나 더 가져오기 위해 요청 상한을 우회하지 않는다. `maxOriginals`와 검색 제한 외에 공통 요청 장부를 사용한다. 요청은 전송 전에 예약하고 실패도 시도에 포함한다. 로컬 재실행에는 같은 계획과 자료 버전을 확인해 기존 결과를 재사용하며, 장애 재시도는 다음 허용 확인시점에 명시적으로 기록한다. 한도 소진은 자료 부재가 아니라 미완료다.

이미 저장된 원문은 매번 먼저 다운로드하지 않는다. 변경 확인과 신규 질문 수집의 슬롯을 구분한다. 기본 한도에서 자료가 부족하면 조용히 상한을 늘리지 않고 미해결 이유를 반환한다.

| 8월 실질보수 증가와 같은 기간의 소매 흐름은 어떠한가 | 8월 실질보수 원문 | 8월 소매 전체와 비교 기준·주석 | 같은 방향 여부만 비교. 보수가 판매를 유발했다는 단정 금지 |
| 관련 상품군은 전체와 같은 흐름인가 | 품목별 소매 수치 미포함 | 동일 기준 전자제품·가정용품 분류와 정의 | TV 단독·브랜드별 실적·전체 가전 판매량으로 확대 금지 |

첫 배치는 같은 달과 비교에 필요한 전년 자료를 우선 확보한다. 최근 12~24개월 계열은 추세 질문이 필요하고 정의·기준연도가 일치할 때 확보한다. 숫자 두 개로 회복 추세나 가속을 주장하지 않는다. 온라인 명목금액만 있으면 범위가 다른 맥락으로 별도 검토하며, 전체 실질 소매 자료를 확보한 것으로 표시하지 않는다.

## 구현 순서와 합격 조건

1. **질문 계획과 비교 계약:** 새 `research-needs.js` 순수 함수로 목적별 필수/선택 질문, 기존 자료 적합성, 질문별 상한을 출력한다. 범위 정의가 없는 수치나 불명확한 의미 판단은 검토 대기로 둔다. 기존 `report-harness/1`을 소급 변경하지 않고 새 계약 버전으로 연결한다.
2. **출처 등록과 저장 재사용:** 새 출처 레지스트리의 메타데이터를 기존 `sources.js` 및 공식 수집 경로가 공유한다. 호출기는 하나의 요청 장부를 사용한다. 통계별 버전·기간·주석 저장과 변경 확인을 구현한다.
3. **CLP 공식 통계 연결:** 검토된 INE 표/발표 목록으로 실제 소비 질문을 연결한다. 원문과 표의 일치·분류·발표 버전·이용 조건을 검토한다. 추출 미지원은 같은 계약의 수동 입력으로 남긴다. BRL·MXN 미지원 경로를 성공으로 표시하지 않는다.
4. **기존 탐색과 집필 연결:** `runResearch`와 `collectHarnessResearch`에 계획을 전달하고 기존 질문 전용 호출은 호환 유지한다. 경제 업데이트의 질문 범위는 축소할 수 있어도 출처/시간/의미 검토는 완화하지 않는다. 생성 실행은 여전히 별도 승인이다.
5. **무비용 리플레이와 근거 검토:** 다음 고정 시나리오를 검사하고 실제 CLP 원문 한 건으로 질문에 답하는지 검토한다. 새 AI 호출 없이 저장 원고에 어떤 설명이 가능해졌는지 제시한다. 그 뒤에만 실제 생성 품질 시험 여부를 결정한다.

| 고정 시나리오 | 합격 동작 |
| --- | --- |
| 앞의 시장 질문 네 개가 미충족인 경제 업데이트 | 목적에 맞는 소비 질문이 선택되고 할당 슬롯을 받음 |
| 동일 월간 자료로 반복 실행 | 버전 유효성 확인 후 재사용, 새 집필 자격 자동 생성 없음 |
| 온라인 명목만 확보 | 전체 시장 실질/물량 주장 차단, 범위 제한 결과 |
| 같은 달 실질보수와 소매판매 방향이 반대 | 불리한 자료도 보존하고 차이를 설명, 인과 단정 없음 |
| 같은 수치를 가진 정의/기준연도 다른 시리즈 | 직접 비교 보류 |
| 이후 수정본과 과거 사례 | 당시 값 덮어쓰기 차단, 역사 버전 상태 유지 |
| 공식 일정상 미발표와 HTTP 실패 | 서로 다른 상태로 기록 |
| 원문 해시 변경 | 기존 의미 검토 승인 재사용 차단 |
| 검색 결과 많지만 질문에 답하는 원문 없음 | 근거 미확보, 기사 수로 통과시키지 않음 |
| 요청·시간·바이트 한도 소진 | 추가 요청 중지, 원문/실패 기록 보존 |
| 새 자료의 독자 가치가 없음 | 이전 보고서 날짜 유지, 불필요한 집필 없음 |
| 외부 문서의 명령·인증 필요 URL | 지시 실행 및 비밀값 노출 없이 차단/검토 대기 |

각 조건은 기존 중복·권한·집필 비용 테스트를 복제하지 않고 해당 계약의 소유 테스트에서 검사한다. 통계 원문이 주장을 뒷받침하는지와 독자에게 새 이해를 주는지는 별도 내용 검토이며 자동 테스트 수로 품질 표본을 대신하지 않는다.

## 이번 확인 결과

기존 연구 하네스·공개 어댑터·공식 사건·자료 정규화·근거 범위의 5개 파일에서 38개 테스트가 통과했다. 외부 통신은 모의 응답을 사용했다. 최초 테스트 실행은 Windows 임시 폴더 rename 권한 오류로 시작하지 못했고, 임시 경로를 워크스페이스 내부로 지정한 뒤 통과했다.

빈 합성 dossier와 검색 한도 4로 오프라인 재현한 결과 질문은 market, local, global, counter였고 consumer는 검색되지 않았다. 실제 원고 품질 시험이나 실제 출처의 지속 수집 성공을 뜻하지 않는다.

이번 변경은 이 설계 문서뿐이다. 애플리케이션·생성 코드·보고서·승인·운영은 변경하지 않았다. 전체 빌드와 운영 회귀는 이번 문서 작업에서 재실행하지 않았으며, 구현 단계에서 변경 범위에 맞게 수행한다. 신규 유료 API·검색 비용은 0이다.
