## 2. 자동 연결에서 고친 부분

### 수집 실패와 중복 요청

같은 실패 URL을 여러 질문이 다시 요청하던 경로를 수정했다. 실패·수정 충돌·요청 한도 결과도 한 실행 안에서 재사용한다. 칠레 기존 수집기는 출처와 대상 기간 단위로 결과를 공유한다. 실패는 여전히 실패로 기록하며 자료 없음으로 바꾸지 않는다.

### 수집 결과 → 검토 기록 연결

`report:research:review-batch`를 추가했다. 기존 기사·통계 검토 함수를 재사용하며 원본과 연결된 저장 검토 기록만 수용한다.

- 유효한 기록: `review_receipt_verified`. 기존 검토 기록 재사용이지 새 독립 검토나 게시 승인이라는 뜻은 아니다.
- 기록 없음: `automatic_review_unavailable`. 사용자 수동 업무를 생성하지 않는다.
- 원본 불일치·중복·알 수 없는 카드의 기록: 거부한다.
- 외부 모델 호출, 키 읽기, 유료 검색, 원문 외부 전송 없음.

**남은 자동화:** 원문에 담긴 주장이 카드의 설명을 실제로 지지하는지 판단하여 이 검토 기록을 만드는 자동 실행 경로. 배치 연결만으로 이 판단이 구현됐다고 보고하지 않는다. 새 모델 검토 실행은 이용 범위·비용·실패 상태를 갖춘 별도 시험이 필요하다.

- 적용 대상은 로컬 `supabase_db_latamfx-2x-isolated`뿐이다. 운영 적용 없음.
- 호환되지 않는 로컬 CLI 설정 때문에 SQL을 해당 컨테이너에서 직접 적용해 검증했다. migration 이력은 변경하지 않았다. 새 빈 DB의 전체 migration 재구축은 이번 결과에 포함하지 않는다.
- 새 합성 원고만 사용하여 6개 통화 승인·공개·동시 승인·철회와 비관리자 차단·관리자 권한 해제·로그아웃을 36개 확인 항목으로 검증했다.
- 시험 공개본은 모두 철회하고 시험 감사 기록은 보존했다. 기존 공개본과 관리자 활성 상태는 복원/보존 확인했다.
- 목록·직접 주소·통화 전환·대시보드 숫자 카드 링크를 6개로 확장했다. 승인본이 없으면 준비 중 안내를 보여주며 초안으로 대체하지 않는다.
