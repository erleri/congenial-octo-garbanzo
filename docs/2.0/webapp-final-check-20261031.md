# 웹앱 2.0 최종 동선 점검 — 2026-10-31

## 판단

후속 사용자 확인: A4 인쇄창이 정상적으로 열렸다고 확인받았다. 앞선 도구 시간 초과/범위 차단은 당시 검증 기록으로 남긴다. 페이지 수·잘림·실제 종이 출력까지 확인된 것으로 확대하지 않는다.

대시보드·환율 추이·환율 리포트·공통 관리자 로그인으로 구성된 현재 웹앱을 다음 운영 연결 작업의 기준으로 사용한다. 이번 확인에서 발견한 모바일 표시 오류는 수정했다. 실제 iPhone/Safari·VoiceOver·A4 미리보기는 미검증이며, 전체 2.0 출시 승인으로 간주하지 않는다.

현재 결과를 확인하는 [한 장 요약](../../artifacts/webapp-final-check-20261031/index.html)과 [실제 앱](http://127.0.0.1:4176/#dashboard)을 제공한다. 기존 A안, 환율 산식, 원고와 공개/검토 기록을 유지했다.

390px에서는 대시보드·일별·월별·리포트 목록·상세·출처를 확인했다. 320px에서는 대시보드·국가 이력·상세 출처·공통 로그인·계획환율 화면을 확인했다. 큰 표의 내부 가로 스크롤은 유지한다. 모든 화면과 모든 보조기술에 대한 접근성 인증을 의미하지 않는다.

이번 공개 목록에는 실제 승인된 칠레 보관본 1건과 나머지 국가의 미발행 상태가 보였다. 제작 스튜디오의 최신 초안과 공개 승인본은 별개다. 6개 통화의 실제 내용 품질·운영 발행 준비가 완료됐다는 뜻이 아니다.

## 발견하고 수정한 표시 오류

1. 모바일 관리자 버튼이 데이터 갱신 버튼 위에 겹쳤다. 상위 행의 backdrop-filter가 절대 위치 버튼의 기준 영역을 만들고 있었다. 모바일에서 불필요한 필터를 제거하고 헤더를 위치 기준으로 고정했다.
2. 320px 로그인 폼에서 ‘이메일’이 두 줄로 갈라졌다. 레이블은 한 줄로 유지하고 입력창이 가용 폭에 맞춰 줄어들게 했다.
3. 자료 정보 팝업이 헤더 필터의 영향을 받아 viewport 대신 헤더 안쪽 좌표에서 시작했다. 헤더의 모바일 필터도 제거해 팝업이 화면 안에 들어오도록 했다.

제품 수정은 `src/ui2.css`의 모바일 규칙에 한정한다. 별도 로직이나 같은 CSS 선언을 되풀이하는 단위 테스트를 추가하지 않고 실제 화면 좌표와 스크린샷으로 확인했다. 수정 전 CSS는 `.local-reports/private/webapp-final-check-20261031/baseline/`에 보존했다.

## 검사와 한계

- 이번 재실행: 타입 검사·전체 lint·관련 6파일 21사례 통과. 운영 빌드와 로컬 앱 빌드, 번들 경계 통과. 초기 HTML JS 466,450bytes.
- 최초 관련 테스트는 Windows 샌드박스 임시 경로 rename 권한 오류로 6개 파일의 import 전에 중단됐다. 작업 폴더의 임시 경로를 지정해 같은 21개 사례를 다시 실행했고 통과했다. 오류를 테스트 성공으로 계산하지 않는다.
- 직전 전체 1,066사례·DB 113검사·기존 70기록 보존은 [인증 통합 검증](admin-auth-unification-20261031.md)의 결과를 재사용한다. 이번 CSS 수정 후 전체 DB 검사를 재실행했다고 보고하지 않는다.
- 인쇄 버튼은 IAB와 Chrome에서 시도했으나 브라우저 입력 호출이 시간 초과됐다. 이것만으로 앱 인쇄 결함 또는 성공을 판단하지 않는다. 네이티브 확인 대상이 개인 YouTube 창으로 식별되어 자동 승인 검토가 창 접근을 차단했다. 다른 앱/개인 탭을 조작하지 않았고 실제 출력·파일 저장도 하지 않았다. 인쇄 CSS 확인과 실제 A4 출력 검증은 구분한다.
- 실제 iPhone/Safari·VoiceOver, A4 페이지 수/잘림, 전체 키보드 접근성은 미검증이다. 이번 테스트에서 이를 자동 합격시키지 않는다.
- 로컬 환율은 저장된 2026-09-12 스냅샷이고 ‘갱신 확인 필요’로 표시된다. 운영 최신 환율 파일과 섞어 배포하지 않는다.
- 새 AI 호출·비용·원고 편집·DB/권한 변경·운영 변경·메일 발송·push·배포는 0이다.
