# 현재 근거 유효성·국가별 준비 복구 보완 — 2026-11-02

후속 독립 점검에서 **무결성 오류 분류와 미사용 출처의 전체 흐름 처리**에 남은 결함을 확인했다. 아래는 당시 수정·검증 기록이며 전체 자동 운영 합격을 뜻하지 않는다. 최신 판정과 기존 설명의 제한은 [V1·V2 독립 점검](final-validity-independent-audit-20261102.md)을 따른다.

## 반영 결과

[최종 독립 점검 F1·F2](final-independent-audit-20261102.md)의 두 결함을 공통 경로에서 수정했다. 특정 국가·기사에 대한 허용 예외를 추가하지 않았다.

| 문제 | 반영한 동작 | 확인 |
|---|---|---|
| F1: 철회된 근거를 고정 입력이 재사용 | 재개 전에 현재 서비스 소유 검토 기록을 읽어 철회·충돌·재검토 필요를 확인. 문제가 있으면 모델 호출 전에 해당 고정 작업 종료/보류 | 6통화 모두 철회 후 새 호출0, 초안 추가0. COP에서 기사 조회 장애가 겹쳐도 명시적 철회 적용 |
| F2: 준비 조건만 복구된 국가는 다른 국가의 대기에 묶임 | 옛 준비 보류/미대상에서 현재 작성 가능으로 바뀐 국가도 후속 입력 후보로 선택. 미완료 작업의 원래 배치 소유권 유지 | 6통화 모두 다른 국가 조회 장애 중 복구된 국가만 먼저 진행. 반복3회 추가 호출0, 장애 복구 후 원래 검토만1회 |

현재 결과에 후속 완료가 반영되면 옛 준비 보류가 실행 요약의 기술 오류로 남지 않도록 했다. 배치 전체의 비용 미확인·lease·저장 오류는 계속 공통 중단 사유로 취급한다.

## 현재 유효성과 불변 입력

- 고정된 기사·환율·원고·모델 응답·비용은 변경하지 않는다. 현재 유효성 검사는 별도의 실행 제약이다.
- 저장소 조회 자체가 실패하면 `frozen_source_refresh_wait`로 원래 작업을 보존한다. 저장 자료의 결합/무결성 오류는 일시적 조회 실패로 숨기지 않는다.
- `frozen_source_review_withdrawn`, `frozen_source_review_conflict`, `frozen_source_review_revalidation_required`와 원래 근거 보류 사유를 남긴다. 오래된 성공 응답이 이를 승인으로 바꾸지 않는다.
- 이미 등록된 집필 입력이 있으면 그 입력의 결합과 통화·스냅샷·사건을 확인한 후, 원고에 연결된 출처만 유효성 검사 대상으로 삼는다. 원고에 사용하지 않은 다른 기사 때문에 정상 원고를 막지 않는다.
- 철회·명시적 대체 검토를 자료 판본에 연결한다. 첫 성공 검토를 단순 캐시한 것만으로 새 자료로 보지 않는다.
- 대체 근거가 확보되면 그 근거로 새 입력을 평가한다. 철회 자체를 없애지 않는다.
- 서비스 소유의 명시적 재승인이 과거 판정을 대체하면 새 유효성 판본을 인식한다. 검증된 기존 작성 응답을 재사용해 남은 검토만 진행할 수 있고, 철회 기록도 보존한다.

## 준비 복구·소유권·승인 범위

현재 준비 판정이 `planned`로 바뀐 국가는 새 기사/새 환율이 없어도 반복 운영 정책의 다음 입력으로 평가한다. 다른 미완료 국가는 원래 입력·장부·작업에서 재개한다. 기존 사건 잠금과 완료 기록을 확인하므로 복구를 이유로 매번 다시 작성하지 않는다.

일회 시험 승인을 반복 운영 승인으로 바꾸지 않는다. 일회 정책의 두 번째 배치 차단은 유지한다. 호출 수·확정 비용의 실행별 누계, DB 배치/월 예산, 미확인 비용 차단, 동시 lease, 승인·공개 분리도 유지한다. 자동 재시도·백업·게시 기능은 추가하지 않았다.

## 검증

### 회귀와 정적 검사

최종 **168파일·1,236검사 통과**. 타입, 전체 린트, 최종 변경 파일 린트, 운영 빌드·번들 경계 검사, 앱 리포트 빌드·리포트 전용 빌드가 통과했다. 마지막 변경은 시험 사례 추가이며 제품 코드는 같은 빌드 검증본이다.

새 `operating-eligibility-recovery.test.ts`의 7개 논리 사례는 다음 실패 경계를 담당한다.

1. 6통화별 철회 차단 → 실제로 다른 대체 근거 → 정상 진행 → 중복 실행 차단.
2. 충돌/옛 검토 버전에서 기존 성공 응답 재사용 차단.
3. 원고에 사용하지 않은 기사로 정상 원고를 과도하게 막지 않음.
4. 명시적 재승인 후 기존 작성 응답 재사용과 철회 기록 보존.
5. 유효성 조회 장애 후 원래 검토만 재개.
6. 6통화별 준비 조건 복구 + 다른 국가 지속 장애 + 반복3회 + 최종 원래 검토 재개.
7. 준비 복구가 일회 승인을 두 번째 배치로 확장하지 않음.

앞서 고친 반환형 조회 실패·빈 색인·가격 결측·다중 배치·비용 미확인·일회 승인 경계 검사도 전체 회귀에 포함된다. 메타데이터 검사에서 중복 이름·동일 본문·자명한 자기 비교는 없었다. 의미적 중복 부재나 실제 원고 품질 표본1,236건을 뜻하지 않는다.

### 실제 격리 저장 경로

실제 `createRuntimeStore`의 직렬화/복원과 설치된 SQL 함수를 연결했다. 기사와 모델 응답만 합성이다.

| 조합 | 이번 모의 호출 | 결과 |
|---|---:|---|
| COP 원고 검토 대기 → 근거 철회 → 재개 | 0 | 원고 검토 호출·초안 추가 전에 차단 |
| COP 준비 오류 복구 + PEN 지속 장애 | 4 | COP의 추출·대조·집필·검토만1회 진행, 뒤의 반복2회 추가 호출0 |
| COP 근거 철회 → 명시적 재승인 | 1 | 기존 작성 응답 유지, 남은 원고 검토만 진행 |

`supabase_db_latamfx-2x-isolated`, 포트56322만 사용했다. 시험 정책·제어·행 변경은 전부 롤백했고 대상 테이블/제어의 전후 해시가 같았다. 시퀀스 불변까지 주장하지 않는다. 새 SQL 정의·권한·migration 변경은 없다. 종료 후 `enabled=false`, `review_enabled=false`, `monthly_limit_nano=0`을 별도로 조회해 확인했다.

이번 시험은 SQL 클라이언트를 주입한 실제 저장 계약 검사다. Supabase HTTP 연결·UI 클릭·실제 제공자·실제 원고 품질을 시험한 결과가 아니다.

### 기존 실제 자료 보존

과거 실제 원문 처리 요청21건을 동일 해시로 재현했고 원본 입력4파일 해시가 유지됐다. 알려진 MXN의 과거 잘못된 성공 판정은 기록을 보존하되 현재 자동 재사용 보류를 유지했다. 추가 외부 뉴스/모델 요청·비용·운영 변경은 모두0이다.
